## 架构概述

Immich 移动端采用**多级渐进式媒体加载架构**，通过智能的资源选择、分级加载、多级缓存和占位符机制，实现流畅的用户体验和高效的资源管理。

### 核心特点

- **智能资源选择**：根据资源可用性和用户偏好自动选择本地或远程资源
- **分级渐进加载**：缩略图 → 预览图 → 原图的渐进式加载策略
- **多级缓存体系**：内存缓存 + 磁盘缓存，大图小图分离管理
- **占位符优化**：ThumbHash 和渐变占位符提供即时视觉反馈
- **可取消加载**：支持加载任务取消，避免资源浪费
- **平台原生集成**：充分利用平台原生 API 获取本地资源

## 核心设计理念

### 1. 渐进式加载（Progressive Loading）

**设计目标：**
- 快速显示内容，减少用户等待时间
- 逐步提升图片质量，提供流畅的视觉体验
- 根据网络条件和用户设置动态调整加载策略

**实现策略：**
- **三级加载流程**：占位符 → 缩略图 → 预览图 → 原图
- **智能降级**：网络不佳时停止在预览图，不加载原图
- **用户控制**：提供设置选项，允许用户选择是否加载原图

**优势：**
- 用户感知的加载时间大幅缩短
- 节省带宽和存储空间
- 适应不同网络环境

### 2. 智能资源选择（Smart Resource Selection）

**选择逻辑：**
```
资源选择决策树：
├─ 资源是否有本地文件？
│  ├─ 是 → 检查用户偏好
│  │  ├─ preferRemoteImage = false → 使用本地资源
│  │  └─ preferRemoteImage = true → 使用远程资源
│  └─ 否 → 使用远程资源
```

**考虑因素：**
- **本地资源可用性**：检查资源是否已下载到本地
- **用户偏好设置**：尊重用户的选择（本地优先或远程优先）
- **资源完整性**：确保本地资源完整可用
- **网络状态**：在网络不佳时优先使用本地资源

**优势：**
- 减少不必要的网络请求
- 提供离线浏览能力
- 提升加载速度（本地资源通常更快）

### 3. 多级缓存分离（Separated Multi-Level Cache）

**缓存层次：**
- **L1 缓存（内存）**：最快，但容量有限
- **L2 缓存（磁盘）**：较慢，但容量大
- **缓存分离**：大图和小图使用不同的缓存池

**设计原因：**
- **防止大图驱逐小图**：如果大图小图混用同一缓存，一张大图可能驱逐大量小图
- **优化内存使用**：小图缓存可以存储更多缩略图，大图缓存限制数量
- **提升命中率**：分离后各自独立管理，提升缓存命中率

**实现方式：**
- 使用 `CustomImageCache` 实现三级内存缓存
- 使用不同的 `CacheManager` 管理磁盘缓存
- 根据 ImageProvider 类型自动路由到对应缓存

### 4. 可取消加载（Cancellable Loading）

**设计目标：**
- 避免加载已不需要的资源
- 及时释放网络和计算资源
- 提升应用响应性

**实现机制：**
- **CancellableImageProvider**：提供取消接口
- **ImageRequest 取消**：支持取消网络请求和文件读取
- **自动清理**：组件销毁时自动取消相关加载任务

**应用场景：**
- 用户快速滚动列表，离开视口的图片不再需要
- 用户关闭图片查看器，停止加载原图
- 应用进入后台，取消所有加载任务

## 架构组件详解

### 1. ImageProvider 层

#### 1.1 本地资源提供者

**LocalThumbProvider / ImmichLocalThumbnailProvider**
- **用途**：加载本地资源的缩略图
- **实现方式**：使用 `photo_manager` 的 `thumbnailDataWithSize` API
- **缓存策略**：先检查磁盘缓存，未命中则生成并缓存
- **缓存键**：`{userId}{localId}{checksum}{width}{height}`

**LocalFullImageProvider / ImmichLocalImageProvider**
- **用途**：加载本地资源的原图
- **实现方式**：
  - 图片：直接读取原文件
  - 视频：生成指定尺寸的缩略图
- **加载流程**：
  1. 先显示缩略图（从缓存或生成）
  2. 加载适配设备分辨率的图片
  3. 根据设置决定是否加载原图

#### 1.2 远程资源提供者

**RemoteThumbProvider / ImmichRemoteThumbnailProvider**
- **用途**：加载远程资源的缩略图
- **URL 格式**：`/assets/{id}/thumbnail?size={size}`
- **缓存策略**：使用 `ThumbnailImageCacheManager`（5000 个对象，30 天过期）

**RemoteFullImageProvider / ImmichRemoteImageProvider**
- **用途**：加载远程资源的原图
- **加载流程**：
  1. 先加载预览图（Preview）
  2. 根据用户设置决定是否加载原图
- **URL 格式**：
  - 预览图：`/assets/{id}/thumbnail?size=preview`
  - 原图：`/assets/{id}/original`

#### 1.3 资源选择逻辑

**getThumbnailImageProvider / getFullImageProvider**
- **输入**：`BaseAsset`（本地或远程资源）
- **输出**：对应的 `ImageProvider`
- **选择逻辑**：
  ```dart
  bool _shouldUseLocalAsset(BaseAsset asset) =>
      asset.hasLocal && 
      (!asset.hasRemote || !AppSetting.get(Setting.preferRemoteImage));
  ```

### 2. 加载层

#### 2.1 LocalImageRequest

**功能**：
- 从本地文件系统读取图片
- 使用 `photo_manager` 生成缩略图
- 支持指定尺寸和质量

**实现细节**：
- **图片资源**：直接读取原文件路径
- **视频资源**：调用 `thumbnailDataWithSize` 生成缩略图
- **错误处理**：文件不存在或读取失败时抛出异常

#### 2.2 RemoteImageRequest

**功能**：
- 从网络下载图片
- 支持流式下载和进度报告
- 自动处理缓存

**实现细节**：
- **HTTP 客户端**：使用 `HttpClient`，最大 16 个并发连接
- **缓存检查**：
  1. 先检查内存缓存（快速路径）
  2. 再检查磁盘缓存
  3. 最后从网络下载
- **流式处理**：支持边下载边解码，提升感知速度
- **错误恢复**：网络失败时回退到磁盘缓存

#### 2.3 ImageLoader

**功能**：
- 统一的图片加载接口
- 集成缓存管理器
- 支持进度事件

**工作流程**：
1. 调用 `CacheManager.getFileStream()` 获取文件流
2. 监听下载进度，发送 `ImageChunkEvent`
3. 文件就绪后解码为 `Codec`
4. 返回解码后的图片

### 3. 缓存层

#### 3.1 CustomImageCache（内存缓存）

**三级缓存结构**：

```
CustomImageCache
├─ _thumbhash (ThumbHash 缓存)
│  └─ maximumSize = 0 (无限制)
├─ _small (小图缓存)
│  └─ 用于缩略图
└─ _large (大图缓存)
   └─ maximumSize = 5 (最多 5 张)
```

**路由规则**：
- **大图缓存**：`ImmichLocalImageProvider`、`ImmichRemoteImageProvider`、`LocalFullImageProvider`、`RemoteFullImageProvider`
- **小图缓存**：`ImmichLocalThumbnailProvider`、`ImmichRemoteThumbnailProvider`、`LocalThumbProvider`、`RemoteThumbProvider`
- **ThumbHash 缓存**：`ThumbHashProvider`

**优势**：
- 防止大图驱逐小图
- 优化内存使用
- 提升缓存命中率

#### 3.2 CacheManager（磁盘缓存）

**ThumbnailImageCacheManager**
- **用途**：存储缩略图
- **配置**：最多 5000 个对象，30 天过期
- **存储位置**：应用缓存目录

**RemoteImageCacheManager**
- **用途**：存储远程原图
- **配置**：最多 500 个对象，30 天过期
- **存储位置**：应用缓存目录

**缓存策略**：
- **LRU 淘汰**：超出数量限制时淘汰最久未使用的
- **过期清理**：超过过期时间的自动清理
- **流式存储**：支持边下载边存储，不占用额外内存

## 资源选择策略

### 选择决策树

```
开始
  │
  ├─ 资源是否有本地文件？
  │  │
  │  ├─ 是
  │  │  │
  │  │  ├─ 资源是否有远程版本？
  │  │  │  │
  │  │  │  ├─ 是 → 检查用户偏好
  │  │  │  │  │
  │  │  │  │  ├─ preferRemoteImage = false → 使用本地资源 ✅
  │  │  │  │  └─ preferRemoteImage = true → 使用远程资源 ✅
  │  │  │  │
  │  │  │  └─ 否 → 使用本地资源 ✅
  │  │  │
  │  │  └─ 使用本地资源 ✅
  │  │
  │  └─ 否 → 使用远程资源 ✅
```

### 实现细节

**检查本地资源可用性**：
- `asset.hasLocal`：资源是否有本地文件
- `asset.local != null`：本地资源对象是否存在
- `asset.localId != null`：本地资源 ID 是否存在

**检查用户偏好**：
- `AppSetting.get(Setting.preferRemoteImage)`：用户是否偏好远程图片
- `Store.get(StoreKey.preferRemoteImage, false)`：从存储中读取设置

**资源提供者映射**：
- **本地资源** → `LocalThumbProvider` / `LocalFullImageProvider`
- **远程资源** → `RemoteThumbProvider` / `RemoteFullImageProvider`

### 特殊场景

**混合资源（既有本地又有远程）**：
- 默认使用本地资源（更快、节省带宽）
- 用户可设置偏好远程资源（可能质量更高或已更新）

**仅本地资源**：
- 直接使用本地资源，无需网络请求

**仅远程资源**：
- 使用远程资源，需要网络连接

## 分级加载策略

### 缩略图加载流程

**阶段 1：占位符显示**
- **ThumbHash**（如果可用）：
  - 适用于远程资源且无本地文件
  - 体积小（通常 < 100 字节）
  - 解码速度快（毫秒级）
  - 提供模糊但色彩准确的占位符
- **渐变占位符**（无 ThumbHash 时）：
  - 基于主题色的线性渐变
  - 提供视觉反馈，避免空白

**阶段 2：缩略图加载**
- **本地资源**：
  1. 检查磁盘缓存
  2. 缓存命中：直接使用
  3. 缓存未命中：使用 `photo_manager` 生成并缓存
- **远程资源**：
  1. 检查内存缓存
  2. 检查磁盘缓存
  3. 从网络下载
  4. 存储到缓存

**阶段 3：淡入动画**
- 100ms 淡入动画
- 平滑过渡，提升视觉体验

### 原图加载流程（远程）

**阶段 1：预览图加载**
- **目的**：快速显示较高质量的图片
- **URL**：`/assets/{id}/thumbnail?size=preview`
- **特点**：
  - 比缩略图大，但比原图小
  - 通常足够满足查看需求
  - 加载速度快

**阶段 2：原图加载（可选）**
- **触发条件**：`AppSetting.get(Setting.loadOriginal) == true`
- **URL**：`/assets/{id}/original`
- **特点**：
  - 完整分辨率
  - 文件较大，加载时间长
  - 需要良好网络条件

**渐进式显示**：
- 预览图先显示
- 原图加载完成后替换
- 平滑过渡，用户感知流畅

### 原图加载流程（本地）

**阶段 1：缩略图显示**
- 从缓存或生成缩略图
- 快速显示，提供即时反馈

**阶段 2：适配分辨率加载**
- **计算目标尺寸**：`size * devicePixelRatio`
- **目的**：适配设备屏幕，避免加载过大图片
- **优势**：减少内存占用，提升加载速度

**阶段 3：原图加载（可选）**
- **触发条件**：`Store.get(StoreKey.loadOriginal, false) == true`
- **实现方式**：`LocalImageRequest` 使用 `Size.zero` 加载原图
- **特点**：直接读取本地文件，速度快

### 加载优先级

**优先级顺序**：
1. **内存缓存**：最快，优先检查
2. **磁盘缓存**：较快，次优选择
3. **本地资源**：中等速度，无需网络
4. **远程资源**：最慢，需要网络

**智能降级**：
- 网络不佳时：停止在预览图，不加载原图
- 内存不足时：优先清理大图缓存
- 磁盘空间不足时：清理过期缓存

## 缓存机制

### 内存缓存（CustomImageCache）

#### 缓存结构

**三级缓存池**：
- **ThumbHash 缓存**：无大小限制，仅存储占位符
- **小图缓存**：存储缩略图，容量较大
- **大图缓存**：存储原图，限制为 5 张

#### 路由机制

**自动路由**：
- 根据 `ImageProvider` 类型自动选择缓存池
- 大图提供者 → `_large` 缓存
- 小图提供者 → `_small` 缓存
- ThumbHash 提供者 → `_thumbhash` 缓存

**优势**：
- 防止大图驱逐小图
- 优化内存使用
- 提升缓存命中率

#### 缓存策略

**LRU 淘汰**：
- 超出容量限制时淘汰最久未使用的图片
- 大图缓存限制严格（5 张），小图缓存更宽松

**生命周期管理**：
- 图片不再被引用时自动清理
- 支持手动清理：`ImageCache.evict()`

### 磁盘缓存（CacheManager）

#### ThumbnailImageCacheManager

**配置**：
- **最大对象数**：5000
- **过期时间**：30 天
- **存储位置**：应用缓存目录

**用途**：
- 存储远程缩略图
- 存储本地生成的缩略图

**优势**：
- 大量存储，适合缩略图
- 长期有效，减少重复下载

#### RemoteImageCacheManager

**配置**：
- **最大对象数**：500
- **过期时间**：30 天
- **存储位置**：应用缓存目录

**用途**：
- 存储远程预览图
- 存储远程原图

**特点**：
- 对象较大，限制数量
- 支持流式存储，边下载边存储

#### 缓存操作

**获取缓存**：
1. `getFileFromMemory(url)`：检查内存缓存（快速）
2. `getFileFromCache(url)`：检查磁盘缓存
3. `getFileStream(url)`：获取文件流，支持下载进度

**存储缓存**：
1. `putFile(key, bytes)`：存储字节数组
2. `putStreamedFile(url, stream)`：流式存储
3. 自动生成缓存键和文件路径

**清理缓存**：
1. **自动清理**：超出数量或过期时自动清理
2. **手动清理**：`removeFile(url)` 删除指定文件
3. **全部清理**：`emptyCache()` 清空所有缓存

### 缓存键生成

#### 缩略图缓存键

**远程资源**：
- 格式：`thumbnail-image-{id}` 或 `{id}_previewStage`
- 基于资源 ID，确保唯一性

**本地资源**：
- 格式：`{userId}{localId}{checksum}{width}{height}`
- 包含用户 ID、本地 ID、校验和、尺寸
- 确保不同用户、不同尺寸的缓存不冲突

#### 原图缓存键

**远程资源**：
- 格式：`{id}_fullStage` 或 `{remoteId}_fullStage`
- 基于资源 ID

**本地资源**：
- 格式：基于本地 ID 和尺寸
- 不同尺寸使用不同缓存键

### 缓存优化策略

#### 预加载策略

**可见性检测**：
- 仅加载可见区域的图片
- 离开视口时取消加载

**预加载相邻图片**：
- 可以预加载前后几张图片
- 提升滚动体验

**启动时预热**：

**后台预热**：
- 在后台预加载可能需要的图片
- 需要平衡性能和资源消耗

## 占位符机制

### ThumbHash 占位符

#### 什么是 ThumbHash

**定义**：
- 一种紧凑的图片占位符格式
- 将图片压缩为极小的字节数组（通常 < 100 字节）
- 保留图片的主要色彩和结构信息

**优势**：
- **体积小**：比传统缩略图小几个数量级
- **解码快**：毫秒级解码速度
- **视觉效果好**：提供模糊但色彩准确的占位符

#### 使用场景

**适用条件**：
- 远程资源（`RemoteAsset`）
- 资源有 `thumbHash` 字段
- 资源无本地文件（`localId == null`）

**实现方式**：
- `ThumbHashProvider` 解码 ThumbHash
- 生成低分辨率占位图
- 在缩略图加载前显示

#### 解码流程

1. **读取 ThumbHash 字节**：从资源对象获取
2. **解析头部信息**：
   - 亮度、色度信息
   - 尺寸信息
   - Alpha 通道信息
3. **生成像素数据**：使用 DCT 变换重建图片
4. **创建 Image 对象**：转换为 Flutter Image

### 渐变占位符

#### 设计原则

**视觉一致性**：
- 基于应用主题色
- 与整体设计风格一致

**简洁性**：
- 简单的线性渐变
- 不分散用户注意力

#### 实现方式

**颜色选择**：
- 从主题色方案获取：`colorScheme.surfaceContainer`
- 生成渐变：从浅色到深色

**缓存优化**：
- 按颜色方案缓存渐变对象
- 避免重复创建

**显示时机**：
- 无 ThumbHash 时使用
- 图片加载失败时作为后备

### 占位符切换

#### 切换流程

1. **初始状态**：显示占位符（ThumbHash 或渐变）
2. **加载中**：占位符保持显示
3. **加载完成**：淡入显示实际图片
4. **加载失败**：保持占位符或显示错误图标

#### 动画效果

**淡入动画**：
- 持续时间：100ms
- 曲线：`Curves.easeOut`
- 平滑过渡，提升视觉体验

**错误处理**：
- 显示错误图标
- 提供重试机制
- 清理失败的缓存

### 视频预览图

### 视频播放

#### 本地视频播放

**实现方式**：
- 直接使用本地文件路径
- 使用 `VideoSource.init(path: file.path, type: VideoSourceType.file)`
- 无需网络连接

**优势**：
- 播放速度快
- 不消耗带宽
- 支持离线播放

#### 远程视频播放

**播放选项**：
- **转码版本**（默认）：
  - URL：`/assets/{id}/video/playback`
  - 服务器转码后的优化版本
  - 文件较小，加载快
- **原视频**（可选）：
  - URL：`/assets/{id}/original`
  - 完整原始视频
  - 文件较大，需要良好网络

**用户控制**：
- 设置选项：`loadOriginalVideo`
- 用户可选择播放质量

#### Live Photo 处理

**特殊处理**：
- Live Photo 包含静态图片和视频两部分
- 视频部分使用 `livePhotoVideoId` 加载
- 图片和视频分别处理

**加载流程**：
1. 加载静态图片（使用图片加载流程）
2. 需要时加载视频部分（使用视频加载流程）
3. 分别缓存，独立管理

## 总结

Immich 移动端的媒体资源加载架构通过以下核心机制实现了高效、流畅的媒体加载体验：

1. **智能资源选择**：根据资源可用性和用户偏好自动选择最优资源
2. **分级渐进加载**：占位符 → 缩略图 → 预览图 → 原图的渐进式加载
3. **多级缓存体系**：内存缓存 + 磁盘缓存，大图小图分离管理
4. **占位符优化**：ThumbHash 和渐变占位符提供即时视觉反馈
5. **可取消加载**：支持加载任务取消，避免资源浪费
6. **错误恢复**：网络失败时自动回退到缓存，提供无缝体验

该架构设计充分考虑了性能、用户体验和资源消耗的平衡，可以作为其他相册应用的重要参考。
