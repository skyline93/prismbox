## **统一认证系统设计文档 (UAS-DD)**

### **1. 概述**

#### 1.1. 项目目标
本文档旨在设计一个灵活、健壮且以用户为中心的统一认证系统。该系统将支持 Flutter 应用（iOS 和 Android）的用户通过 Apple ID 和传统的邮箱/密码方式进行注册和登录。核心目标是确保无论用户选择何种认证方式，其身份都将归属到系统内唯一的账户，实现无缝的跨平台、跨认证方法的用户体验。

#### 1.2. 核心原则
*   **身份与认证解耦**: 用户的核心身份（Profile）与登录方式（Method）分离。
*   **单一事实来源**: 系统内有且仅有一个主用户记录，所有认证方式都链接到该记录。
*   **以邮箱为锚点**: 用户的唯一邮箱地址是关联不同认证方式的关键标识。
*   **用户体验至上**: 简化注册流程，提供账户关联的清晰指引，确保数据一致性。
*   **可扩展性**: 架构设计应能方便地在未来集成其他第三方登录（如 Google, 微信等）。

### **2. 系统架构**

系统由以下几个关键部分组成：

1.  **Flutter 客户端**: 负责渲染 UI，调用原生登录 SDK (Sign in with Apple)，并与后端 API 安全通信。
2.  **Go 后端服务**: 系统的核心，负责处理所有业务逻辑，包括：
    *   验证第三方身份提供商（Apple）的凭证。
    *   管理用户数据库。
    *   处理邮箱/密码认证。
    *   生成和验证用于会话管理的 JWT (JSON Web Tokens)。
3.  **PostgreSQL 数据库** (或其他关系型数据库): 持久化存储用户信息和认证凭证。
4.  **Apple 认证服务**: 外部依赖，用于验证用户 Apple ID 的真实性。

### **3. 数据库 Schema 设计**

数据库是本设计的基石。我们将设计两个核心表。

#### 3.1. `users` 表
存储核心、统一的用户身份信息。

```sql
-- public.users definition

CREATE TABLE public.users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(), -- 系统内部唯一用户ID，作为所有关联的中心
    email VARCHAR(255) UNIQUE NOT NULL,             -- 统一的、经过验证的邮箱，作为账户关联的“锚点”
    password_hash VARCHAR(255) NULL,                -- 用于邮箱密码登录，对于仅使用Apple注册的用户可为空
    full_name VARCHAR(255) NULL,                    -- 用户全名
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),  -- 创建时间
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()   -- 最后更新时间
);

-- 添加索引以优化查询性能
CREATE INDEX idx_users_email ON public.users(email);
```

#### 3.2. `auth_providers` 表
存储用户关联的外部登录凭证。

```sql
-- public.auth_providers definition

CREATE TABLE public.auth_providers (
    id BIGSERIAL PRIMARY KEY,
    user_id UUID NOT NULL,                          -- 外键，关联到核心用户ID
    provider_name VARCHAR(50) NOT NULL,             -- 'apple', 'google', etc.
    provider_user_id TEXT NOT NULL,                 -- 来自第三方提供商的用户唯一ID (例如Apple的 'sub' 字段)
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),

    -- 外键约束，确保user_id存在于users表中，并在用户删除时级联删除此记录
    CONSTRAINT fk_users
        FOREIGN KEY(user_id)
        REFERENCES public.users(id)
        ON DELETE CASCADE,

    -- 复合唯一约束，确保一个用户只能绑定一种第三方账户一次
    UNIQUE (user_id, provider_name),
    -- 复合唯一约束，确保一个第三方账户ID全局唯一
    UNIQUE (provider_name, provider_user_id)
);
```

### **4. API 端点设计 (Go Backend)**

所有 API 都应使用 `Authorization: Bearer <JWT>` Header 进行认证（登录/注册端点除外）。

---

#### `POST /v1/auth/apple/login`
**功能**: 处理来自客户端的 Apple 登录请求。可用于注册或登录。

*   **Request Body**:
    ```json
    {
      "identityToken": "string (required)",
      "fullName": {
        "givenName": "string (optional)",
        "familyName": "string (optional)"
      }
    }
    ```
*   **Success Response (200 OK)**:
    ```json
    {
      "token": "YOUR_SYSTEM_JWT",
      "user": {
        "id": "uuid",
        "email": "user@example.com",
        "fullName": "John Doe"
      }
    }
    ```*   **Error Responses**:
    *   `400 Bad Request`: `identityToken` 缺失或无效。
    *   `401 Unauthorized`: Apple `identityToken` 验证失败。
    *   `500 Internal Server Error`: 数据库或其他内部错误。

---

#### `POST /v1/auth/register`
**功能**: 使用邮箱和密码进行新用户注册。

*   **Request Body**:
    ```json
    {
      "email": "user@example.com (required, valid email format)",
      "password": "string (required, min 8 chars)",
      "fullName": "John Doe (optional)"
    }
    ```
*   **Success Response (201 Created)**: (与上面相同)
*   **Error Responses**:
    *   `400 Bad Request`: 请求参数不符合要求。
    *   `409 Conflict`: 邮箱地址已被注册。

---

#### `POST /v1/auth/login`
**功能**: 使用邮箱和密码进行登录。

*   **Request Body**:
    ```json
    {
      "email": "user@example.com (required)",
      "password": "string (required)"
    }
    ```
*   **Success Response (200 OK)**: (与上面相同)
*   **Error Responses**:
    *   `401 Unauthorized`: 邮箱或密码不正确。

---

#### `POST /v1/auth/password/set`
**功能**: 为已登录（例如通过 Apple 登录）但未设置密码的用户创建密码。

*   **Authorization**: `Bearer <JWT>`
*   **Request Body**:
    ```json
    {
      "password": "string (required, min 8 chars)"
    }
    ```
*   **Success Response (204 No Content)**
*   **Error Responses**:
    *   `401 Unauthorized`: 无效的 JWT。
    *   `409 Conflict`: 该用户已经设置过密码。

### **5. 核心用户旅程与后端逻辑**

#### 5.1. **场景 A: 新用户通过 Apple 注册**
1.  **Flutter**: 调用 `SignInWithApple.getAppleIDCredential` 获取 `identityToken`, `email`, `fullName`。
2.  **Flutter**: 将凭证 `POST` 到 `/v1/auth/apple/login`。
3.  **Go Backend**:
    a. 验证 `identityToken` 并解析出 `apple_user_id` (`sub`) 和 `email`。
    b. **查询数据库**: `SELECT * FROM users WHERE email = ?`
    c. **结果**: 未找到用户。
    d. **执行事务**:
        i.  `INSERT INTO users (email, full_name) VALUES (?, ?)` 创建新用户。
        ii. `INSERT INTO auth_providers (user_id, provider_name, provider_user_id) VALUES (?, 'apple', ?)` 链接 Apple 凭证。
    e. 生成包含新 `user_id` 的 JWT 并返回给客户端。

#### 5.2. **场景 B: 已有邮箱账户的用户，首次使用 Apple 登录 (账户链接)**
1.  **Flutter**: 同上。
2.  **Flutter**: 同上。
3.  **Go Backend**:
    a. 验证 `identityToken` 并解析出 `apple_user_id` 和 `email`。
    b. **查询数据库**: `SELECT * FROM users WHERE email = ?`
    c. **结果**: 找到现有用户。
    d. **执行**: `INSERT INTO auth_providers (user_id, provider_name, provider_user_id) VALUES (?, 'apple', ?)`，将 Apple ID 链接到现有账户。
    e. 生成包含该现有 `user_id` 的 JWT 并返回。

#### 5.3. **场景 C: 用户通过 Apple 注册后，希望在安卓上用密码登录**
1.  **Flutter (iOS/Android)**: 用户在个人设置页面找到“创建密码”或“账户安全”入口。
2.  **Flutter**: 弹出一个表单让用户输入新密码，然后 `POST` 到 `/v1/auth/password/set` (需要携带JWT)。
3.  **Go Backend**:
    a. 验证 JWT，从中获取 `user_id`。
    b. 查询 `users` 表，确认 `password_hash` 字段为 `NULL`。
    c. 使用 `bcrypt` 对新密码进行哈希。
    d. `UPDATE users SET password_hash = ? WHERE id = ?`。
    e. 返回成功响应。
4.  此后，用户即可在任何设备的登录页使用邮箱和刚设置的密码登录。

### **6. 安全考量**

*   **JWT 安全**:
    *   JWT 应包含 `user_id` 作为核心 claim。
    *   设置合理的、较短的过期时间 (如 15 分钟)，并使用 Refresh Token 机制来获取新的 Access Token。
    *   必须使用强密钥（`secret key`）进行签名 (HS256 或更强的 RS256)。
    *   所有通信必须在 HTTPS/TLS 下进行。
*   **密码安全**:
    *   **绝不**以明文形式存储密码。
    *   必须使用业界标准、带盐的慢哈希算法，如 `Bcrypt` 或 `Argon2`。
*   **Apple `identityToken` 验证**:
    *   必须严格按照 Apple 文档验证 Token 的签名、`iss` (issuer)、`aud` (audience)、`exp` (expiry time) 等字段。
*   **输入验证**: 对所有来自客户端的输入进行严格的格式和内容验证，防止 SQL 注入、XSS 等攻击。
*   **速率限制**: 对登录、注册、密码重置等敏感 API 端点实施速率限制，防止暴力破解攻击。

### **7. 前端 (Flutter) 实施要点**

*   **依赖包**:
    *   `sign_in_with_apple`: 用于调用原生 Apple 登录。
    *   `http` 或 `dio`: 用于进行网络请求。
    *   `flutter_secure_storage`: **必须**使用此包将获取到的 JWT 安全地存储在设备的 Keychain (iOS) / Keystore (Android) 中。**严禁**使用 `SharedPreferences` 存储敏感令牌。
*   **状态管理**:
    *   使用 Provider, BLoC, Riverpod 或其他状态管理方案来管理用户的认证状态（已登录/未登录）。
    *   App 启动时，应检查 `flutter_secure_storage` 中是否存在有效的 JWT，以实现自动登录。
*   **UI/UX**:
    *   提供清晰的登录选项：“通过 Apple 继续” 和 “通过邮箱继续”。
    *   在处理账户链接（场景 B）时，可以向用户提供一个确认对话框，例如：“我们发现 `user@example.com` 已经注册。是否要将您的 Apple ID 关联到此账户？”
