### **重构实施方案：统一认证系统**

*   **版本**: 1.0
*   **目标**: 在现有认证系统基础上，集成“通过 Apple 登录”功能，并实现与邮箱/密码账户的统一管理。
*   **核心策略**: 将现有 `User` 模型作为统一的用户身份中心，通过新增 `AuthProvider` 模型来关联不同的登录方式。用户的 `Email` 将作为跨认证方式识别同一用户的关键“锚点”。


---

### **1. 后端 (Go) 重构方案**

#### **1.1. 数据库 Schema 变更 (models/models.go)**

这是最关键的一步，我们需要调整数据模型以支持新架构。

**1.1.1. `User` 模型修改**

*   **目标**: 使 `Password` 和 `Username` 字段变为可选，因为通过 Apple 注册的用户初始状态下没有密码，也可能没有用户名。
*   **建议**: 将主键 `ID (uint)` 升级为 `UUID` 类型，这是现代分布式系统的最佳实践，可以避免 ID 冲突且不暴露用户总量。如果此项改动过大，可以暂时保留 `uint`。

**`models/models.go` - 修改**
```go
package models

import (
	"time"
	"github.com/google/uuid" // 建议引入
	"gorm.io/gorm"
)

type User struct {
	// --- 建议的修改 (ID) ---
	ID        uuid.UUID      `gorm:"type:uuid;primary_key;default:gen_random_uuid()" json:"id"`

	// --- 如果保持 uint (备选方案) ---
	// ID        uint           `gorm:"primarykey" json:"id"`

	CreatedAt time.Time      `json:"created_at"` // 建议暴露 created_at
	UpdatedAt time.Time      `json:"-"`
	DeletedAt gorm.DeletedAt `gorm:"index" json:"-"`

	// --- 关键修改 ---
	Username  string         `gorm:"type:varchar(100);uniqueIndex" json:"username,omitempty"` // 保持 unique, 但在业务逻辑中允许为空
	Email     string         `gorm:"type:varchar(255);uniqueIndex;not null" json:"email"` // 确保 Email 始终存在且唯一
	Password  string         `gorm:"type:varchar(255);null" json:"-"` // 修改: 允许密码为空 (NULL)
	Avatar    string         `gorm:"type:varchar(255)" json:"avatar"`
}

// ... RefreshToken 模型保持不变 (如果 User ID 变为 UUID，UserID 字段类型也要相应修改)
```

#### **1.2. 认证逻辑重构 (auth/handler.go)**

**1.2.1. 新增 Apple 登录处理器**

*   **目标**: 创建一个全新的 API 端点 `POST /auth/apple/login` 来处理 Apple 登录和账户关联。

**`auth/handler.go` - 新增 DTO**
```go
type AppleLoginInput struct {
	IdentityToken string `json:"identityToken" binding:"required"`
	FullName      struct {
		GivenName  string `json:"givenName"`
		FamilyName string `json:"familyName"`
	} `json:"fullName"` // 客户端在首次授权时传递
}
```

**`auth/handler.go` - 新增 Handler 方法 (伪代码逻辑)**
```go
// AppleLogin godoc
// @Summary      通过 Apple ID 登录或注册
// @Description  使用从 Apple 获取的 identityToken 进行登录。如果用户不存在，则创建新用户；如果邮箱已存在，则关联账户。
// @Tags         Authentication
// @Accept       json
// @Produce      json
// @Param        credentials body AppleLoginInput true "Apple 登录凭证"
// @Success      200 {object} core.ApiResponse{data=UserLoginSuccessData} "登录成功"
// @Failure      400 {object} core.ApiResponse "请求参数错误"
// @Failure      401 {object} core.ApiResponse "Apple Token 验证失败"
// @Router       /auth/apple/login [post]
func (h *AuthHandler) AppleLogin(c *gin.Context) {
	// 1. 绑定输入
	var input AppleLoginInput
	// ...

	// 2. 验证 Apple Identity Token
	//    需要一个新函数或服务来处理此逻辑，它会与 https://appleid.apple.com/auth/keys 通信
	//    并验证签名、iss, aud, exp 等字段。
	claims, err := ValidateAppleToken(input.IdentityToken, "your_app_bundle_id", "your_service_id")
	if err != nil {
		core.ErrorAuth(c, "Invalid Apple token")
		return
	}

	appleUserID := claims.Subject // Apple 用户的唯一 ID ('sub')
	email := claims.Email

	// 3. 核心逻辑：通过邮箱查找用户
	var user models.User
	err = h.DB.Where("email = ?", email).First(&user).Error

	// 场景 A: 邮箱不存在 -> 全新注册
	if errors.Is(err, gorm.ErrRecordNotFound) {
		// 在事务中创建 User 和 AuthProvider
		tx := h.DB.Begin()

		// 创建 User，注意 Password 为空
		newUser := models.User{
			Email:    email,
			FullName: input.FullName.GivenName + " " + input.FullName.FamilyName,
			// Username 可以留空或基于 email 生成一个临时的
		}
		if err := tx.Create(&newUser).Error; err != nil {
			tx.Rollback()
			// ... handle error
			return
		}

		// 创建 AuthProvider 链接
		provider := models.AuthProvider{
			UserID:         newUser.ID,
			ProviderName:   "apple",
			ProviderUserID: appleUserID,
		}
		if err := tx.Create(&provider).Error; err != nil {
			tx.Rollback()
			// ... handle error
			return
		}

		tx.Commit()
		user = newUser // 后续JWT生成使用此新用户
	} else if err != nil {
		// 其他数据库错误
		core.Error(c, "Database error")
		return
	} else {
		// 场景 B: 邮箱已存在 -> 账户链接
		// 检查此 Apple ID 是否已链接到其他账户 (防止恶意操作)
		var existingProvider models.AuthProvider
		if h.DB.Where("provider_name = ? AND provider_user_id = ?", "apple", appleUserID).First(&existingProvider).Error == nil {
			if existingProvider.UserID != user.ID {
				core.Error(c, "This Apple ID is already linked to another account.")
				return
			}
			// 如果已链接到当前账户，则直接走登录流程
		} else {
			// 创建新的链接
			provider := models.AuthProvider{
				UserID:         user.ID,
				ProviderName:   "apple",
				ProviderUserID: appleUserID,
			}
			if err := h.DB.Create(&provider).Error; err != nil {
				// ... handle error
				return
			}
		}
	}

	// 4. 为找到的或新创建的用户生成 JWT
	accessToken, refreshToken := generateTokensForUser(user.ID) // 封装 Token 生成逻辑
	// ... 保存 refresh token 到数据库 ...
	// ... 返回 tokens ...
}
```

**1.2.3. 新增设置密码处理器**

*   **目标**: 允许通过 Apple 登录的用户在登录后设置自己的密码。
*   **端点**: `POST /auth/password/set` (需要 JWT 认证)

**`auth/handler.go` - 新增 DTO 和 Handler**
```go
type SetPasswordInput struct {
	Password string `json:"password" binding:"required,min=8"`
}

// SetPassword godoc
// @Summary      为账户设置密码
// @Description  允许通过第三方登录且未设置密码的用户创建一个密码
// @Tags         Authentication
// @Accept       json
// @Produce      json
// @Param        password body SetPasswordInput true "新密码"
// @Success      204 "密码设置成功"
// @Failure      400 {object} core.ApiResponse "请求参数错误或用户已设置密码"
// @Failure      401 {object} core.ApiResponse "未授权"
// @Security     BearerAuth
// @Router       /auth/password/set [post]
func (h *AuthHandler) SetPassword(c *gin.Context) {
    userID := c.MustGet("userID").(uint) // 或 uuid.UUID
    // ... 绑定 input ...

    var user models.User
    h.DB.First(&user, userID)

    if user.Password != "" {
        core.Error(c, "Password has already been set for this account.")
        return
    }

    hashedPassword, _ := HashPassword(input.Password)
    h.DB.Model(&user).Update("password", string(hashedPassword))

    core.NoContent(c)
}
```
**实施动作**:
1.  在 `main.go` 或路由文件中，为 `AuthHandler` 添加新路由: `/auth/apple/login`, `/auth/password/set`。
2.  实现 `ValidateAppleToken` 的辅助函数（推荐使用 `github.com/MicahParks/keyfunc` 来获取和缓存 Apple 公钥）。
3.  修改 `Login` 函数的 DTO 和查询逻辑。

### **2. 移动端 (Flutter) 调整方案**

#### **2.1. 项目配置和依赖**

1.  **添加依赖**: 在 `pubspec.yaml` 中添加 `sign_in_with_apple` 包。
    ```yaml
    dependencies:
      sign_in_with_apple: ^...
    ```2.  **iOS 配置 (Xcode)**:
    *   在 `Signing & Capabilities` 标签页下，点击 `+ Capability`。
    *   选择并添加 `Sign in with Apple`。
3.  **Android/Web 配置 (Apple Developer Portal)**:
    *   **创建 Service ID**:
        *   前往 `Identifiers` -> `+` -> 选择 `Services IDs`。
        *   Description: `Your App Name Android Sign In`
        *   Identifier: `com.yourdomain.app.signin` (或其他，需记下)。
        *   勾选 `Sign in with Apple` 并点击 `Configure`。
        *   在 `Domains and Subdomains` 中填入你的 API 域名 (e.g., `api.yourdomain.com`)。
        *   在 `Return URLs` 中填入由 Apple 重定向的后端回调 URL (注意：对于 Flutter 库，这个 URL 主要是为了在 Apple Portal 完成配置，库本身可能会拦截 Web 视图的重定向来获取凭证，因此后端不需要实现这个回调端点)。
    *   **创建 Key**: 确保你已创建并下载了 `.p8` 私钥，并记下了 `Key ID` 和 `Team ID`。这些信息需要提供给后端。

### **3. 总结：破坏性变更与迁移**

*   **主要破坏性变更**:
    1.  **登录方式**: 传统登录从 `username` 变为 `email`。所有移动端版本必须同步更新，否则老版本用户将无法登录。
    2.  **数据库主键**: 如果决定将 `User.ID` 从 `uint` 改为 `UUID`，这将是重大的数据库和代码库变更，所有外键关联都需要更新。
*   **对现有用户的影响**:
    *   现有通过邮箱/密码注册的用户不受影响，他们只需在更新 App 后使用邮箱而非用户名进行登录。
    *   他们也可以在登录后，从个人设置中选择“关联 Apple 账户”，触发与场景 B 相同的账户链接流程。
