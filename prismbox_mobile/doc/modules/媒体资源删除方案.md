# 媒体资源删除方案（最终完整版）

## 一、方案概述

### 1.1 设计原则
- 服务端职责单一：只管理服务端资源，使用 `Deleted` 字段标记删除状态
- 移动端职责明确：管理本地资产删除，同步服务端删除状态
- 状态流转清晰：支持部分删除，UI 准确反映资产状态
- 本地文件安全删除：移动到临时目录，30天后清理
- 解耦设计：通过 checksum 动态关联，不在表中存储关联ID
- 用户体验优先：提供回收站、恢复、自动清理

### 1.2 术语定义
- 本地（Local）：移动设备上的媒体文件，存储在手机/平板文件系统
- 云端（Remote/Server）：服务端上的媒体文件，存储在服务端存储系统
- 仅本地（LocalOnly）：只在移动设备上存在
- 仅云端（RemoteOnly）：只在服务端存在
- 已备份（Merged）：在移动设备和服务端都存在

## 二、数据模型设计

### 2.1 后端数据模型（服务端）

#### Media 模型扩展
```
字段：
- Deleted (bool, default: false)          // 服务端删除标志
- DeletedAt (*time.Time, index)          // 删除时间（用于30天自动清理）
- DeletedBy (*uint, index)                // 删除操作者（用于审计）
- DeletionReason (string, optional)       // 删除原因（可选）

说明：
- 服务端只管理服务端资源，不需要区分本地和云端删除状态
- Deleted=true 表示服务端资源已删除（软删除，进入回收站）
- PurgeMedia 会硬删除服务端存储文件（LocalPath, CloudPath, 缩略图, 预览图）
```

### 2.2 前端数据模型（移动端）

#### LocalAssetEntity 扩展
```
字段：
- id (主键)
- checksum (索引，用于关联，不存储 remoteId)
- path (文件路径)
- deletedAt (DateTime?, nullable)         // 删除时间（软删除）
- localFileDeleted (bool, default: false) // 文件是否已移动到临时目录
- deletionTempPath (string?, nullable)    // 临时文件路径（用于恢复和清理）
- 其他业务字段...

不需要：
- linkedRemoteId ❌（通过 checksum 动态查询）
```

#### RemoteAssetEntity 扩展
```
字段：
- id (主键)
- checksum (索引，用于关联，不存储 localId)
- deletedAt (DateTime?, nullable)         // 删除时间（同步自服务端）
- 其他业务字段...

不需要：
- linkedLocalId ❌（通过 checksum 动态查询）
```

#### AssetDeletionRecord 新增表（回收站）
```
字段：
- id (int, autoIncrement)                 // 主键
- assetType (string)                      // 'local' | 'remote' | 'merged'
- localId (string?, nullable)            // 本地资产ID（如果存在）
- remoteId (string?, nullable)            // 远程资产ID（如果存在）
- checksum (string?, nullable)            // checksum（用于关联查找）
- deletionType (string)                  // 'local_only' | 'cloud_only' | 'both'
- deletedAt (DateTime)                    // 删除时间
- originalState (string)                  // 'local' | 'remote' | 'merged'（原始状态）

说明：
- 用于回收站显示和恢复操作
- 记录删除的资产类型和删除方式
- 支持部分删除的记录（已备份资产删除本地或云端）
- 可以存储关联信息，因为这是业务逻辑表，不是核心数据表
```

## 三、删除操作类型

### 3.1 删除类型枚举
```
DeletionType:
- localOnly: 仅删除本地（移动设备）
- cloudOnly: 仅删除云端（服务端）
- both: 同时删除本地和云端
```

### 3.2 删除场景映射

| 媒体状态 | 支持的删除类型 | 操作说明 |
|---------|--------------|---------|
| 仅本地（LocalOnly） | localOnly | 移动本地文件到临时目录，软删除本地数据库记录 |
| 仅云端（RemoteOnly） | cloudOnly | 调用后端API删除服务端资源 |
| 已备份（Merged） | localOnly、cloudOnly、both | 根据用户选择删除 |

## 四、本地文件处理策略

### 4.1 临时目录设计

#### 目录结构
```
App私有空间：
/data/user/0/com.example.prismbox/
├── files/
│   ├── upload_temp/         # 上传临时文件（已有）
│   └── deletion_temp/       # 删除临时文件（新增）
│       ├── {year}/
│       │   ├── {month}/
│       │   │   ├── {day}/
│       │   │   │   ├── {assetId}_{timestamp}.{ext}
│       │   │   │   └── ...
│       │   │   └── ...
│       │   └── ...
│       └── ...
```

#### 文件命名规则
- 目录：`deletion_temp/YYYY/MM/DD/`
- 文件名：`{assetId}_{timestamp}.{ext}`
- 便于按日期清理

### 4.2 文件移动策略

#### 删除本地文件时
1. 不直接删除文件
2. 移动到临时目录（按日期组织）
3. 保留原路径信息（用于恢复）
4. 更新数据库记录（设置 `deletionTempPath`）

#### 恢复文件时
1. 检查临时文件是否存在
2. 如果存在，移回原位置（或新位置，如果原位置被占用）
3. 如果不存在，提示文件已永久删除

#### 清理文件时
1. 30天后自动清理临时文件
2. 清理空的临时目录
3. 更新数据库记录（清除 `deletionTempPath`）

## 五、删除逻辑设计

### 5.1 删除"仅本地"媒体

#### 流程
1. 获取本地资产文件路径
2. 创建临时目录（如果不存在）
3. 生成临时文件路径：`deletion_temp/YYYY/MM/DD/{assetId}_{timestamp}.{ext}`
4. 移动文件到临时目录（不是复制）
5. 更新 LocalAssetEntity：
   - `deletedAt = now()`
   - `localFileDeleted = true`
   - `deletionTempPath = 临时文件路径`
   - `path = 原路径`（保留，用于恢复）
6. 创建删除记录（AssetDeletionRecord）：
   - `assetType = 'local'`
   - `localId = asset.localId`
   - `checksum = asset.checksum`
   - `deletionType = 'local_only'`
   - `originalState = 'local'`

#### 结果
- 照片页面：不显示（本地资产已删除）
- 回收站：显示仅本地版本

### 5.2 删除"仅云端"媒体

#### 流程
1. 获取远程资产ID列表
2. 调用后端API删除服务端资源（设置 `Media.Deleted=true`）
3. 创建删除记录（AssetDeletionRecord）：
   - `assetType = 'remote'`
   - `remoteId = asset.remoteId`
   - `checksum = asset.checksum`
   - `deletionType = 'cloud_only'`
   - `originalState = 'remote'`
4. 软删除 RemoteAssetEntity（设置 `deletedAt`）

#### 结果
- 照片页面：不显示（远程资产已删除）
- 回收站：显示仅云端版本

### 5.3 删除"已备份"媒体

#### 5.3.1 仅删除本地（localOnly）

**流程**：
1. 获取本地资产文件路径
2. 移动文件到临时目录（同上述流程）
3. 更新 LocalAssetEntity（设置 `deletedAt`, `localFileDeleted`, `deletionTempPath`）
4. 通过 checksum 查找关联的远程资产（如果存在）
   - 不需要更新 RemoteAssetEntity（保持独立）
5. 创建删除记录（AssetDeletionRecord）：
   - `assetType = 'local'`
   - `localId = asset.localId`
   - `remoteId = asset.remoteId`（如果通过 checksum 找到）
   - `checksum = asset.checksum`
   - `deletionType = 'local_only'`
   - `originalState = 'merged'`
6. 不调用后端API（服务端资源保留）

**结果**：
- 照片页面：显示为仅云端状态（通过 checksum 匹配，只找到远程资产，显示云图标）
- 回收站：显示仅本地版本（已删除的本地部分）

#### 5.3.2 仅删除云端（cloudOnly）

**流程**：
1. 获取远程资产ID列表
2. 通过 checksum 查找关联的本地资产（如果存在）
   - 不需要更新 LocalAssetEntity（保持独立）
3. 创建删除记录（AssetDeletionRecord）：
   - `assetType = 'remote'`
   - `localId = asset.localId`（如果通过 checksum 找到）
   - `remoteId = asset.remoteId`
   - `checksum = asset.checksum`
   - `deletionType = 'cloud_only'`
   - `originalState = 'merged'`
4. 调用后端API删除服务端资源
5. 软删除 RemoteAssetEntity（设置 `deletedAt`）
6. 保留移动设备上的文件（不删除）

**结果**：
- 照片页面：显示为仅本地状态（通过 checksum 匹配，只找到本地资产，无云图标）
- 回收站：显示仅云端版本（已删除的云端部分）

#### 5.3.3 同时删除（both）

**流程**：
1. 移动本地文件到临时目录（同上述流程）
2. 更新 LocalAssetEntity（设置 `deletedAt`, `localFileDeleted`, `deletionTempPath`）
3. 创建删除记录（AssetDeletionRecord）：
   - `assetType = 'merged'`
   - `localId = asset.localId`
   - `remoteId = asset.remoteId`
   - `checksum = asset.checksum`
   - `deletionType = 'both'`
   - `originalState = 'merged'`
4. 调用后端API删除服务端资源
5. 软删除 RemoteAssetEntity（设置 `deletedAt`）

**结果**：
- 照片页面：不显示（本地和远程都已删除）
- 回收站：显示已备份版本（完整版本）

## 六、状态流转规则

### 6.1 状态流转表

| 原始状态 | 删除操作 | 照片页面显示 | 回收站显示 | 云图标状态 |
|---------|---------|------------|----------|----------|
| 仅本地 | 删除本地 | ❌ 不显示 | ✅ 仅本地版本 | - |
| 仅云端 | 删除云端 | ❌ 不显示 | ✅ 仅云端版本 | - |
| 已备份 | 仅删除本地 | ✅ 仅云端状态 | ✅ 仅本地版本 | ✅ 显示 |
| 已备份 | 仅删除云端 | ✅ 仅本地状态 | ✅ 仅云端版本 | ❌ 不显示 |
| 已备份 | 同时删除 | ❌ 不显示 | ✅ 已备份版本 | - |

### 6.2 状态判断逻辑

#### 照片页面查询逻辑
1. 查询未删除的本地资产（`LocalAssetEntity.deletedAt IS NULL`）
2. 查询未删除的远程资产（`RemoteAssetEntity.deletedAt IS NULL`）
3. 通过 checksum 动态关联：
   - 如果本地资产和远程资产的 checksum 匹配 → 已备份（显示云图标）
   - 如果只有本地资产 → 仅本地（不显示云图标）
   - 如果只有远程资产 → 仅云端（显示云图标）

#### 删除状态判断
- 删除"已备份"媒体 - 仅删除本地后：
  - 本地资产：`deletedAt IS NOT NULL`
  - 远程资产：`deletedAt IS NULL`
  - 照片页面：通过 checksum 匹配，只找到远程资产 → 显示为仅云端（显示云图标）
- 删除"已备份"媒体 - 仅删除云端后：
  - 本地资产：`deletedAt IS NULL`
  - 远程资产：`deletedAt IS NOT NULL`
  - 照片页面：通过 checksum 匹配，只找到本地资产 → 显示为仅本地（不显示云图标）

## 七、后端API设计

### 7.1 删除接口

#### 单个删除
```
DELETE /api/v1/media/{uuid}
功能：软删除服务端媒体，进入回收站
响应：成功/失败
```

#### 批量删除
```
DELETE /api/v1/media/batch
Body: {
    "uuids": ["uuid1", "uuid2", ...]
}
功能：批量软删除服务端媒体
响应：成功/失败列表
```

#### 永久删除
```
DELETE /api/v1/media/{uuid}/purge
功能：硬删除服务端媒体（从回收站永久删除）
响应：成功/失败
```

#### 批量永久删除
```
DELETE /api/v1/media/purge/batch
Body: {
    "uuids": ["uuid1", "uuid2", ...]
}
功能：批量硬删除服务端媒体
响应：成功/失败列表
```

### 7.2 回收站接口

#### 获取回收站列表
```
GET /api/v1/media/trash?page=1&page_size=20
功能：分页获取回收站中的媒体列表
响应：媒体列表（包含删除时间等信息）
```

#### 恢复单个媒体
```
POST /api/v1/media/{uuid}/restore
功能：从回收站恢复媒体
响应：成功/失败
```

#### 批量恢复
```
POST /api/v1/media/restore/batch
Body: {
    "uuids": ["uuid1", "uuid2", ...]
}
功能：批量恢复媒体
响应：成功/失败列表
```

#### 清空回收站
```
DELETE /api/v1/media/trash/empty
功能：清空回收站（永久删除所有回收站中的媒体）
响应：删除数量
```

### 7.3 后端删除逻辑

#### 软删除（进入回收站）
1. 验证媒体存在性和用户权限
2. 设置 `Media.Deleted=true`, `DeletedAt=now()`, `DeletedBy=userID`
3. 不删除存储文件（保留在回收站）
4. 处理相册关联（从相册中移除）
5. 处理分享关联（标记分享为已撤销）

#### 硬删除（永久删除）
1. 验证媒体在回收站中
2. 删除服务端存储文件（LocalPath, CloudPath, 缩略图, 预览图）
3. 永久删除数据库记录
4. 记录操作日志

## 八、前端服务设计

### 8.1 删除服务接口

#### 统一删除接口
```
deleteAssets(
    assets: List<BaseAsset>,
    deletionType: DeletionType,
    options?: {
        deleteFiles?: boolean,  // 是否立即删除文件（默认false，仅标记删除）
        showProgress?: bool,    // 是否显示进度
    }
)
```

**功能**：
- 根据资产状态自动选择删除策略
- 仅本地资产：移动文件到临时目录，软删除本地记录
- 仅云端资产：调用后端API删除服务端资源
- 已备份资产：根据 deletionType 执行对应删除操作

### 8.2 回收站服务接口

#### 获取回收站列表
```
getTrashAssets(): Future<List<TrashAsset>>
```

**功能**：
- 查询 AssetDeletionRecord 表
- 根据记录类型加载对应的资产信息
- 返回 TrashAsset 列表（包含显示信息）

#### 恢复资产
```
restoreTrashAsset(trashAsset: TrashAsset): Future<void>
```

**功能**：
- 根据删除记录类型执行恢复操作
- 仅本地删除：从临时目录移回文件，恢复 LocalAssetEntity
- 仅云端删除：调用后端API恢复 + 同步 RemoteAssetEntity
- 同时删除：恢复本地和云端资产

#### 永久删除
```
purgeTrashAsset(trashAsset: TrashAsset): Future<void>
```

**功能**：
- 删除删除记录
- 如果是服务端资源，调用后端API永久删除
- 如果是本地资源，删除临时文件，硬删除 LocalAssetEntity

### 8.3 查询服务接口

#### 时间线查询（照片页面）
```
getTimelineAssets(): Future<List<BaseAsset>>
```

**逻辑**：
1. 查询未删除的本地资产（`LocalAssetEntity.deletedAt IS NULL`）
2. 查询未删除的远程资产（`RemoteAssetEntity.deletedAt IS NULL`）
3. 通过 checksum 关联，构建 BaseAsset 列表
4. 根据关联情况判断资产状态（local/remote/merged）

#### 云图标显示逻辑
```
BaseAsset.shouldShowCloudIcon: bool
- LocalOnly: false（不显示）
- RemoteOnly: true（显示）
- Merged: true（显示）
```

## 九、回收站功能设计

### 9.1 回收站数据结构

#### TrashAsset 类型
```
enum TrashAssetType {
    localOnly,   // 仅本地版本（已备份媒体删除本地后）
    remoteOnly,  // 仅云端版本（已备份媒体删除云端后）

#### TrashAsset 属性
```
- type: TrashAssetType

- remoteAsset?: RemoteAssetEntityData

### 9.2 回收站显示逻辑

#### 显示规则
- 仅本地删除：显示本地资产信息，标题"仅本地（已删除本地部分）"
- 仅云端删除：显示远程资产信息，标题"仅云端（已删除云端部分）"，显示云图标

#### 排序规则
- 按删除时间倒序（最近删除的在前）
- 支持按类型筛选

### 9.3 回收站操作

#### 恢复操作
- 单个恢复：恢复选中的资产
- 批量恢复：批量恢复多个资产
- 恢复后：从回收站移除，在照片页面显示

#### 永久删除操作
- 单个永久删除：从回收站永久删除
- 批量永久删除：批量永久删除
- 清空回收站：永久删除所有回收站中的资产

## 十、恢复逻辑设计

### 10.1 恢复本地资产

#### 流程
1. 检查 `deletionTempPath` 是否存在
2. 如果临时文件存在：
   - 检查原路径是否可用（如果被占用，生成新路径）
   - 将文件从临时目录移回原位置（或新位置）
   - 更新 LocalAssetEntity：
     - `deletedAt = NULL`
     - `localFileDeleted = false`
     - `deletionTempPath = NULL`
3. 如果临时文件不存在：
   - 提示用户文件已永久删除，无法恢复
   - 仅恢复数据库记录（标记为文件丢失）
4. 删除删除记录（AssetDeletionRecord）

### 10.2 恢复远程资产

#### 流程
1. 调用后端API恢复服务端资源
2. 同步更新 RemoteAssetEntity（清除 `deletedAt`）
3. 删除删除记录（AssetDeletionRecord）

### 10.3 恢复已备份资产

#### 恢复仅本地删除
1. 恢复本地资产（从临时目录移回文件）
2. 通过 checksum 查找关联的远程资产（如果存在）
3. 删除删除记录

#### 恢复仅云端删除
1. 调用后端API恢复服务端资源
2. 同步更新 RemoteAssetEntity
3. 通过 checksum 查找关联的本地资产（如果存在）
4. 删除删除记录

#### 恢复同时删除
1. 恢复本地资产（从临时目录移回文件）
2. 调用后端API恢复服务端资源
3. 同步更新 RemoteAssetEntity
4. 删除删除记录

## 十一、自动清理机制

### 11.1 后端自动清理

#### 定时任务
- 执行频率：每天执行一次
- 执行时间：凌晨低峰期（如 2:00 AM）

#### 清理逻辑
1. 查询条件：`Deleted=true AND DeletedAt < NOW() - INTERVAL 30 DAY`
2. 对每条记录执行 PurgeMedia（永久删除）
3. 记录清理日志（清理数量、清理时间）
4. 发送清理通知（可选）

### 11.2 前端自动清理

#### 本地文件清理
1. 查询条件：
   - `deletedAt < NOW() - INTERVAL 30 DAY`
   - `localFileDeleted = true`
   - `deletionTempPath IS NOT NULL`
2. 对每条记录：
   - 检查临时文件是否存在
   - 如果存在，删除临时文件
   - 更新 LocalAssetEntity（清除 `deletionTempPath`）
3. 清理空的临时目录（按日期）
4. 记录清理日志

#### 删除记录清理
1. 查询条件：`deletedAt < NOW() - INTERVAL 30 DAY`
2. 删除过期的删除记录（AssetDeletionRecord）
3. 如果本地文件已删除，清理 LocalAssetEntity 记录
4. 如果服务端资源已删除，清理 RemoteAssetEntity 记录

#### 触发时机
- 应用启动时检查
- 进入回收站时检查
- 定时任务（可选）

### 11.3 临时目录清理

#### 清理逻辑
1. 遍历临时目录下的所有日期目录
2. 检查日期目录是否超过30天
3. 如果超过30天：
   - 删除整个日期目录及其内容
   - 删除父目录（如果为空）
4. 保留最近30天的目录

## 十二、相册和分享关联处理

### 12.1 相册关联处理

#### 删除媒体时
- 从相册中移除媒体（删除 album_items 关联记录）
- 如果相册封面是该媒体，清空封面字段（CoverMediaUUID = NULL）
- 不删除相册本身

#### 恢复媒体时
- 不自动重新加入相册（用户需要手动添加）
- 如果相册封面被清空，可以选择恢复封面（如果媒体仍在相册中）

### 12.2 分享关联处理

#### 删除媒体时
- 标记相关分享为已撤销（Share.IsRevoked = true）
- 不删除分享记录（保留审计信息）
- 分享链接失效（返回404或提示已删除）

#### 恢复媒体时
- 不自动恢复分享（需要用户重新分享）
- 分享记录保持已撤销状态

## 十三、安全性设计

### 13.1 权限验证
- 所有删除操作必须验证用户权限
- 只能删除自己拥有的媒体
- 批量操作需要验证所有媒体都属于当前用户
- 服务端API需要验证JWT token

### 13.2 操作审计
- 记录所有删除操作（用户ID、时间、删除类型、媒体UUID）
- 记录恢复操作
- 记录永久删除操作
- 记录自动清理操作

### 13.3 数据一致性
- 使用数据库事务确保删除操作的原子性
- 文件删除失败时，数据库记录仍保留（可重试）
- 定期检查并清理孤立文件
- 同步机制确保移动端和服务端状态一致

## 十五、存储空间管理

### 15.1 临时目录大小限制
- 设置临时目录最大大小（如 1GB）
- 如果超过限制，优先清理最旧的文件
- 定期监控临时目录大小

### 15.2 清理优先级
- 超过30天的文件（按删除时间）
- 超过临时目录大小限制的文件（按删除时间）
- 应用卸载时清理所有临时文件

## 十六、错误处理

### 16.1 文件移动失败
- 如果移动失败，尝试复制后删除原文件
- 如果复制也失败，记录错误，保留原文件
- 标记为删除失败，用户可重试

### 16.2 临时文件丢失
- 恢复时检查临时文件是否存在
- 如果不存在，提示用户文件已永久删除
- 仅恢复数据库记录，标记为文件丢失

### 16.3 存储空间不足
- 移动文件前检查可用空间
- 如果空间不足，提前清理旧文件
- 如果仍不足，提示用户清理空间
