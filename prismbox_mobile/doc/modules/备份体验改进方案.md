## 背景与问题分析

### 当前问题

用户反馈当前备份功能存在以下体验问题：

1. **缺少已备份照片的统计和展示**
   - 当前只显示队列状态（总任务数、待上传、上传中、已完成、失败）
   - 无法知道哪些照片已经备份了（只显示数量，不显示具体照片）
   - 无法知道当前正在备份哪张照片

2. **缺少实时备份进度展示**
   - 没有显示当前正在上传的照片信息
   - 没有显示上传进度条和速度
   - 用户无法感知备份是否正在进行

3. **缺少备份状态的可视化反馈**
   - 在 AppBar 或其他位置没有备份状态指示器
   - 用户需要进入备份页面才能知道备份状态

### 当前实现分析

#### 现有组件

1. **BackupStatusWidget** (`lib/presentation/widgets/backup/backup_status_widget.dart`)
   - 显示备份配置状态（是否启用、最后备份时间）
   - 显示队列状态（总任务数、待上传、上传中、已完成、失败）
   - **缺失**：已备份照片统计、当前上传照片信息、进度展示

2. **BackupService** (`lib/services/backup/backup_service.dart`)
   - 提供 `getBackupStatus()` 方法，但只返回配置信息
   - **缺失**：备份统计信息（总数、已备份数、剩余数）

3. **UploadService** (`lib/services/backup/upload_service.dart`)
   - 提供 `getQueueStatus()` 方法，返回队列状态
   - **缺失**：已备份资产统计、当前上传资产信息

/// 备份统计信息
class BackupCounts {
  /// 总数量（所有需要备份的照片）
  final int total;
  
  /// 已备份数量（已上传到服务器）
  final int backupCount;
  
  /// 剩余数量（还需要备份）
  final int remainder;
  
  /// 处理中数量（正在准备/哈希计算中）
  final int processing;
  
  BackupCounts({
    required this.total,
    required this.backupCount,
    required this.remainder,
    required this.processing,
  });
  
  /// 进度百分比（0.0 - 1.0）
  double get progress {
    if (total == 0) return 0.0;
    return backupCount / total;
  }
  
  /// 是否已完成备份
  bool get isCompleted => remainder == 0 && processing == 0;
}

## 技术实现细节

### 1. 备份统计信息查询实现

#### 1.1 SQL 查询方案

**参考 Immich 的实现**，使用 SQL 查询统计信息：

```dart
Future<BackupCounts> getBackupCounts(String userId) async {
  // 1. 获取备份配置
  final backupStatus = await BackupQueryBuilder(_database)
      .withUserId(userId)
      .getBackupStatus();
  
  if (backupStatus == null || !backupStatus.enabled) {
    return BackupCounts(
      total: 0,
      backupCount: 0,
      remainder: 0,
      processing: 0,
    );
  }
  
  // 2. 根据备份模式构建查询
  // 需要根据 AutoBackupMode 过滤资产
  // - allUnbacked: 所有未备份的资产
  // - selectedAlbums: 选中相册的资产
  // - timeRange: 时间范围内的资产
  
  // 3. SQL 查询（参考 Immich 的 getAllCounts）
  const sql = '''
    SELECT
      COUNT(*) AS total_count,
      COUNT(*) FILTER (WHERE lae.checksum IS NULL) AS processing_count,
      COUNT(*) FILTER (WHERE rae.id IS NULL) AS remainder_count
    FROM local_asset_entity lae
    LEFT JOIN remote_asset_entity rae
      ON lae.checksum = rae.checksum AND rae.owner_id = ?1
    WHERE EXISTS (
      SELECT 1
      FROM local_album_asset_entity laa
      INNER JOIN local_album_entity la ON laa.album_id = la.id
      WHERE laa.asset_id = lae.id
        AND la.backup_selection = ?2
    )
    AND NOT EXISTS (
      SELECT 1
      FROM local_album_asset_entity laa
      INNER JOIN local_album_entity la ON laa.album_id = la.id
      WHERE laa.asset_id = lae.id
        AND la.backup_selection = ?3
    );
  ''';
  
  // 4. 执行查询并返回结果
  // ...
}
```

#### 1.2 查询优化

1. **索引优化**:
   - 确保 `local_asset_entity.checksum` 有索引
   - 确保 `remote_asset_entity.checksum` 和 `owner_id` 有联合索引
   - 确保 `local_album_asset_entity` 的 `asset_id` 和 `album_id` 有索引

2. **缓存策略**:
   - 统计信息可以缓存一段时间（如 30 秒）
   - 当有上传任务完成时，清除缓存

3. **分批查询**:
   - 如果资产数量很大，考虑分批查询
   - 使用 `LIMIT` 和 `OFFSET` 分页查询

Future<List<UploadTaskDetail>> getActiveUploadTasks(String userId) async {
  final dao = _database.uploadTaskDao;
  
  // 1. 查询状态为 uploading 的任务
  final tasks = await dao.getTasksByStatusAndUserId(
    userId: userId,
    status: UploadTaskStatus.uploading,
  );
  
  // 2. 转换为 UploadTaskDetail
  final details = <UploadTaskDetail>[];
  for (final task in tasks) {
    // 获取资产信息
    final asset = await _database.localAssetDao.getAssetById(task.assetId);
    if (asset == null) continue;
    
    // 获取文件名
    final filename = asset.path.split('/').last;
    
    // 计算进度
    final progress = task.progress / 100.0;
    
    // 获取上传速度（需要从 background_downloader 获取）
    final networkSpeed = await _getNetworkSpeed(task.id);
    
    details.add(UploadTaskDetail(
      taskId: task.id,
      assetId: task.assetId,
      filename: filename,
      progress: progress,
      fileSize: task.fileSize,
      networkSpeed: networkSpeed,
      status: task.status,
      errorMessage: task.errorMessage,
    ));
  }
  
  return details;
}

/// 备份状态 Notifier
class BackupStateNotifier extends StateNotifier<BackupState> {
  final BackupService _backupService;
  final UploadService _uploadService;
  StreamSubscription? _uploadStatusSubscription;
  Timer? _refreshTimer;
  
  BackupStateNotifier(this._backupService, this._uploadService)
      : super(BackupState());
  
  /// 刷新备份状态
  Future<void> refresh(String userId) async {
    state = state.copyWith(isLoading: true);
    
    try {
      // 1. 获取备份统计信息
      final counts = await _backupService.getBackupCounts(userId);
      
      // 2. 获取当前上传任务
      final activeTasks = await _uploadService.getActiveUploadTasks(userId);
      
      // 3. 更新状态
      state = state.copyWith(
        counts: counts,
        activeTasks: activeTasks,
        currentTask: activeTasks.isNotEmpty ? activeTasks.first : null,
        isBackingUp: activeTasks.isNotEmpty,
        isLoading: false,
        hasError: false,
      );
    } catch (e) {
      state = state.copyWith(
        isLoading: false,
        hasError: true,
        errorMessage: e.toString(),
      );
    }
  }
  
  /// 开始监听上传任务状态变化
  void startListening(String userId) {
    // 定期刷新状态（每 3 秒）
    _refreshTimer?.cancel();
    _refreshTimer = Timer.periodic(
      const Duration(seconds: 3),
      (_) => refresh(userId),
    );
    
    // 监听上传任务状态变化
    listenToUploadStatus();
  }
  
  /// 停止监听
  void stopListening() {

## 技术难点与解决方案

### 1. 统计信息查询性能优化

**难点**: 当资产数量很大时，统计查询可能很慢。

**解决方案**:
1. 使用 SQL 聚合查询，避免在应用层计算
2. 添加适当的数据库索引
3. 实现缓存机制（30 秒缓存）
4. 考虑使用后台任务定期更新统计信息

### 2. 实时进度更新

**难点**: 如何实时获取上传任务的进度和速度。

**解决方案**:
1. 如果 `background_downloader` 提供 Stream API，使用 Stream
2. 否则使用定期轮询（每 500ms 或 1s）
3. 使用 `StateNotifier` 管理状态，避免不必要的 UI 更新

### 3. 状态同步

**难点**: 后台任务和前台 UI 的状态同步。

**解决方案**:
1. 使用数据库作为状态源
2. 前台 UI 定期查询数据库
3. 当有状态变化时，通过 EventBus 或 Stream 通知 UI

### 4. 内存优化

**难点**: 大量任务列表可能导致内存问题。

**解决方案**:
1. 使用分页加载
2. 使用 `ListView.builder` 实现虚拟滚动
3. 及时释放不需要的资源

SELECT
  COUNT(*) AS total_count,
  COUNT(*) FILTER (WHERE lae.checksum IS NULL) AS processing_count,
  COUNT(*) FILTER (WHERE rae.id IS NULL) AS remainder_count
FROM local_asset_entity lae
LEFT JOIN remote_asset_entity rae
  ON lae.checksum = rae.checksum AND rae.owner_id = ?1
WHERE EXISTS (
  SELECT 1
  FROM local_album_asset_entity laa
  INNER JOIN local_album_entity la ON laa.album_id = la.id
  WHERE laa.asset_id = lae.id
    AND la.backup_selection = ?2
)
AND NOT EXISTS (
  SELECT 1
  FROM local_album_asset_entity laa
  INNER JOIN local_album_entity la ON laa.album_id = la.id
  WHERE laa.asset_id = lae.id
    AND la.backup_selection = ?3
