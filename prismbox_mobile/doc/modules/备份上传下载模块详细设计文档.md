## 模块概述

### 职责范围

备份上传下载模块是 PrismBox 移动端的核心功能模块，负责：

1. **后台自动备份**：在后台自动将设备媒体库中的照片和视频上传到服务器
2. **上传队列管理**：智能管理上传任务队列，支持并发控制、优先级排序、断点续传
3. **数据同步**：同步本地媒体库和远程服务器数据，确保数据一致性
4. **网络优化**：优化网络资源利用，支持连接复用、智能重试、WiFi 优先
5. **错误处理与恢复**：完善的错误处理机制，支持自动重试和任务恢复

### 核心目标

1. **高性能**：高效的网络资源利用，支持并发上传，最大化上传速度
2. **高可靠性**：完善的错误处理和重试机制，确保任务最终完成
3. **用户体验**：后台运行不影响用户正常使用，提供进度反馈
4. **资源优化**：智能的资源管理，防止内存泄漏，优化电池使用

### 设计原则

1. **隔离性**：后台任务运行在独立 Flutter Engine 中，与主应用完全隔离
2. **类型安全**：使用 Pigeon 进行跨平台通信，编译时类型检查
3. **平台原生集成**：充分利用 Android WorkManager 和 iOS BGTaskScheduler
4. **资源管理**：任务完成后必须清理资源，防止内存泄漏
5. **渐进式优化**：支持增量同步，只上传新资产，减少网络传输

### 与其他模块的关系

```
备份上传下载模块
    │
    ├─→ API 对接模块：使用 ApiService 进行网络请求
    ├─→ 数据库模块：使用 Drift 存储任务状态和资产信息
    ├─→ 本地媒体同步模块：共享同步逻辑（BackgroundSyncManager 和 LocalSyncService）
    ├─→ 媒体资源展示模块：共享媒体加载和缓存机制
    └─→ 页面导航模块：提供备份状态和进度信息给 UI
```

## 架构设计

### 整体架构

备份上传下载模块采用**独立 Flutter Engine 架构**，实现完全隔离的后台任务执行环境。

```
┌─────────────────────────────────────────────────────────────┐
│                     主应用 (Main App)                         │
│  ┌──────────────────────────────────────────────────────┐   │
│  │          UI Flutter Engine (主引擎)                   │   │
│  │  - 用户界面                                           │   │
│  │  - 前台交互                                           │   │
│  │  - 备份设置和状态显示                                 │   │
│  └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
                            │
                            │ Pigeon API (类型安全通信)
                            │
┌─────────────────────────────────────────────────────────────┐
│              原生平台层 (Native Platform Layer)              │
│                                                               │
│  Android: WorkManager          iOS: BGTaskScheduler          │
│  ├─ MediaObserver              ├─ BGAppRefreshTask           │
│  │  (监听媒体库变化)            │  (快速同步，~20秒)          │
│  └─ BackgroundWorker            └─ BGProcessingTask         │
│     (执行备份任务)                (长时间上传)                │
└─────────────────────────────────────────────────────────────┘
                            │
                            │ 启动独立 Engine
                            │
┌─────────────────────────────────────────────────────────────┐
│         后台任务 Engine (Background Worker Engine)            │
│  ┌──────────────────────────────────────────────────────┐   │
│  │  BackgroundWorkerBgService                           │   │
│  │  ├─ 数据库初始化 (Drift)                            │   │
│  │  ├─ 同步服务 (BackgroundSyncManager)                 │   │
│  │  ├─ 上传服务 (UploadService)                         │   │
│  │  ├─ 上传编排器 (UploadOrchestrator)                  │   │
│  │  └─ 资源清理 (Cleanup)                               │   │
│  └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 核心组件

1. **BackgroundWorkerBgService**：后台任务服务，管理独立 Engine 生命周期
2. **BackgroundSyncManager**：同步管理器，处理本地和远程数据同步
3. **UploadService**：上传服务，管理上传任务队列和执行
4. **UploadOrchestrator**：上传编排器，协调上传流程和进度管理
5. **上传队列管理组件**：管理上传任务队列，支持优先级和并发控制
6. **任务状态管理组件**：管理任务状态持久化和恢复

### 技术选型

#### Flutter 侧

- **Pigeon**：类型安全的跨平台通信，编译时类型检查
- **Riverpod**：状态管理和依赖注入
- **Drift**：本地数据库（SQL），存储任务状态和资产信息
- **background_downloader**：后台文件上传/下载管理，支持断点续传
- **cancellation_token_http**：支持取消的 HTTP 请求

#### Android 侧

- **WorkManager**：后台任务调度，支持约束条件
- **FlutterEngine**：独立的 Flutter 引擎
- **FlutterEngineCache**：Engine 缓存管理

#### iOS 侧

- **BGTaskScheduler**：后台任务调度
- **FlutterEngine**：独立的 Flutter 引擎
- **DispatchSemaphore**：信号量同步，防止并发任务冲突

## 核心组件详解

### 1. BackgroundWorkerBgService

**职责**：
- 管理独立 Flutter Engine 的生命周期
- 处理任务初始化和清理
- 协调同步和上传流程
- 与原生平台通信

**接口定义**：

```dart
/// 后台任务服务
class BackgroundWorkerBgService {
  /// 初始化后台服务
  Future<void> init({
    required String databasePath,
    required String apiEndpoint,
    required String apiKey,
  });
  
  /// 执行上传任务
  Future<void> onAndroidUpload();
  Future<void> onIosUpload();
  
  /// 取消任务
  Future<void> cancel();
  
  /// 通知原生层初始化完成
  void onInitialized();
  
  /// 通知原生层任务完成
  void onCompleted();
}
```

**实现要点**：

1. **Engine 生命周期管理**：
   - 任务开始时创建独立 Engine
   - 任务结束时销毁 Engine
   - 使用 Engine Cache 管理 Engine 实例

2. **初始化流程**：
   - 初始化数据库连接
   - 创建独立的 ProviderContainer
   - 配置 API 客户端
   - 初始化同步和上传服务

3. **清理流程**：
   - 取消所有进行中的任务
   - 关闭数据库连接
   - 释放资源
   - 销毁 Engine

**使用示例**：

```dart
// 在后台任务入口点
void backgroundTaskEntryPoint() {
  final service = BackgroundWorkerBgService();
  
  // 初始化
  await service.init(
    databasePath: databasePath,
    apiEndpoint: apiEndpoint,
    apiKey: apiKey,
  );
  
  // 执行上传
  await service.onAndroidUpload();
  
  // 清理
  await service.cancel();
}
```

- 同步本地媒体库到数据库

**实现要点**：

1. **本地同步**：
   - 使用 `photo_manager` 扫描设备媒体库
   - 识别新增、修改、删除的资产
   - 更新本地数据库

2. **远程同步**：
   - 调用服务器 API 获取已上传资产列表
   - 更新本地数据库中的远程资产信息
   - 用于后续去重判断

3. **哈希计算**：
   - 计算待上传资产的哈希值（checksum）

### 3. UploadService

**职责**：
- 管理上传任务队列
- 处理上传任务执行
- 管理上传进度和状态
- 处理上传错误和重试

**接口定义**：

```dart
/// 上传服务
class UploadService {
  /// 添加上传任务
  Future<void> addUploadTask(UploadTask task);
  
  /// 开始上传
  Future<void> startUpload({
    required CancellationToken cancellationToken,
    required ProgressCallback onProgress,
  });
  
  /// 暂停上传
  Future<void> pauseUpload();
  
  /// 恢复上传
  Future<void> resumeUpload();
  
  /// 取消上传
  Future<void> cancelUpload();
  
  /// 获取上传队列状态
  UploadQueueStatus getQueueStatus();
}

class UploadTask {
  final String id; // 任务 ID（主键）
  final String userId; // 用户 ID（外键，用于多用户隔离）
  final String assetId; // 资产 ID
  final String localPath; // 本地文件路径
  final String remotePath; // 远程路径
  final AssetType type; // 资产类型（image/video）
  final int fileSize; // 文件大小（字节）
  final DateTime createdAt; // 创建时间
  final int priority; // 优先级（数字越小优先级越高）
  final UploadTaskType taskType; // 任务类型（manual/auto）
  final UploadTaskStatus status; // 任务状态
  final int retryCount; // 重试次数
  final int maxRetries; // 最大重试次数（默认 3）
  final String? errorMessage; // 错误信息
  final DateTime? uploadedAt; // 上传完成时间
}

class UploadQueueStatus {
  final int totalCount;
  final int pendingCount;
  final int uploadingCount;
  final int completedCount;
  final int failedCount;
}
```

**实现要点**：

1. **队列管理**：
   - 使用优先级队列管理任务
   - 支持任务添加、删除、更新
   - 支持任务状态查询

2. **并发控制**：
   - 最大并发数：6 个任务
   - 每个服务器最大并发：6
   - 每个组最大并发：3

3. **优先级管理**：
   - **任务类型优先**：手动备份（manual）优先于自动备份（auto）
   - **优先级字段**：数字越小优先级越高（manual: 1, auto: 5）
   - **文件类型**：图片优先于视频
   - **文件大小**：小文件优先（可选配置）
   - **创建时间**：早创建的任务优先

**职责**：
- 协调上传流程

```dart
/// 上传编排器
class UploadOrchestrator {
  /// 执行上传编排（需要 userId 确保多用户隔离）
  Future<UploadResult> orchestrate({
    required String userId,
    required List<UploadTask> tasks,
    required CancellationToken cancellationToken,
    required ProgressCallback onProgress,
  });

    required List<UploadTask> candidates,

  });
}

class UploadResult {
  final int successCount;
  final int failedCount;
  final List<UploadError> errors;
}

class UploadError {
  final String assetId;
  final String errorMessage;
  final ErrorType type;
}

enum ErrorType {
  network,        // 网络错误（可重试）
  authentication, // 认证错误（不可重试）
  server,         // 服务器错误（5xx 可重试，4xx 不可重试）
  local,          // 本地错误（文件不存在、权限不足等，不可重试）

```

**实现要点**：

1. **候选列表构建**：
   - 根据选中的相册获取资产
   - 根据排除的相册过滤资产
   - 应用时间过滤器（只获取上次备份后的新资产）

2. **去重处理**：
   - 检查本地重复资产数据库
   - 调用服务器 API 批量检查已存在资产
   - 过滤掉已上传的资产

3. **上传执行**：
   - 按优先级排序任务（考虑任务类型、优先级字段、文件类型等）
   - 并发执行上传任务（最大 6 个并发）
   - 更新进度和状态
   - 处理错误和重试（指数退避策略）
   - 根据成功比例更新 lastBackupTime（仅自动备份）

**与本地媒体同步模块的集成**：

- 数据新鲜度：依赖同步模块的数据，必要时触发同步

**依赖注入**：

```dart
/// 备份服务 Provider
@riverpod
BackupService backupService(BackupServiceRef ref) async {

  final localSyncService = ref.watch(localSyncServiceProvider.future);

  final candidateSelector = ref.watch(backupCandidateSelectorProvider.future);
  
  return BackupService(
    uploadService: await uploadService,
    syncService: await localSyncService,
    database: database,
    candidateSelector: await candidateSelector,
  );
}

**接口优化**（需要 userId 确保多用户隔离）：

```dart
/// 上传服务：队列管理层
class UploadService {
  final Database _database;
  final UploadOrchestrator _orchestrator;
  final TaskConflictResolver _conflictResolver;
  final UploadConcurrencyController _concurrencyController;
  
  /// 添加上传任务（自动进行冲突检测）
  Future<void> addTask(UploadTask task) async {
    // 1. 冲突检测
    final resolution = await _conflictResolver.checkConflict(
      userId: task.userId,
      newTask: task,
    );
    
    // 2. 解决冲突
    await _conflictResolver.resolveConflict(
      resolution: resolution,
      newTask: task,
      existingTask: await _getExistingTask(task),
    );
  }
  
  /// 开始上传
  Future<UploadResult> startUpload({
    required String userId,
    required CancellationToken cancellationToken,
  });
  
  /// 暂停上传
  Future<void> pauseUpload(String userId);
  
  /// 获取队列状态
  UploadQueueStatus getQueueStatus(String userId);
}
```

class BackupQueryBuilder {
  final Database _database;
  String? _userId;
  
  BackupQueryBuilder(this._database);
  
  /// 设置用户 ID（必须调用）
  BackupQueryBuilder withUserId(String userId) {

    return this;

  /// 构建任务查询：强制包含 userId 过滤
  Selectable<UploadTask> buildTaskQuery({
    UploadTaskStatus? status,
    UploadTaskType? taskType,
  }) {
    if (_userId == null) {
      throw StateError('userId must be provided before building query');
    }
    
    var query = _database.select(_database.uploadTasks)
      ..where((t) => t.userId.equals(_userId!));
    
    if (status != null) {
      query = query..where((t) => t.status.equals(status));
    }
    
    if (taskType != null) {
      query = query..where((t) => t.taskType.equals(taskType));
    }
    
    return query;
  }
  
  /// 构建备份状态查询
  Future<BackupStatus?> getBackupStatus() async {
    if (_userId == null) {
      throw StateError('userId must be provided');
    }
    
    return await (_database.select(_database.backupStatus)
      ..where((t) => t.userId.equals(_userId!)))
      .getSingleOrNull();
  }
}
```

### 冲突检测与解决

#### TaskConflictResolver（任务冲突解决器）

**设计目的**：检测和解决手动备份与自动备份的冲突。

**接口定义**：

```dart
/// 冲突解决策略
enum ConflictResolution {
  skip,      // 跳过新任务
  replace,   // 替换旧任务
}

/// 任务冲突解决器
class TaskConflictResolver {
  final Database _database;
  
  /// 检查冲突
  Future<ConflictResolution> checkConflict({
    required String userId,
    required UploadTask newTask,
  }) async {
    // 查询已存在的任务（按 userId 和 assetId 过滤）
    final existingTasks = await BackupQueryBuilder(_database)
        .withUserId(userId)
        .buildTaskQuery()
        .where((t) => 
          t.assetId.equals(newTask.assetId) &
          t.status.isIn([
            UploadTaskStatus.pending,
            UploadTaskStatus.uploading,
          ])
        )
        .get();
    
    if (existingTasks.isEmpty) {
      return ConflictResolution.skip; // 无冲突
    }
    
    // 根据优先级决定解决策略
    final existingTask = existingTasks.first;
    if (newTask.taskType == UploadTaskType.manual && 
        existingTask.taskType == UploadTaskType.auto) {
      return ConflictResolution.replace; // 手动任务替换自动任务
    }
    
    if (newTask.priority < existingTask.priority) {
      return ConflictResolution.replace; // 高优先级替换低优先级
    }
    
    return ConflictResolution.skip; // 跳过新任务
  }
  
  /// 解决冲突
  Future<void> resolveConflict({
    required ConflictResolution resolution,
    required UploadTask newTask,
    required UploadTask? existingTask,
  }) async {
    switch (resolution) {
      case ConflictResolution.skip:
        // 不创建新任务
        return;
        
      case ConflictResolution.replace:
        if (existingTask != null) {
          // 取消旧任务
          await _database.update(_database.uploadTasks)
            ..where((t) => t.id.equals(existingTask.id))
            ..write(UploadTasksCompanion(
              status: Value(UploadTaskStatus.cancelled),
            ));
        }
        // 创建新任务
        await _database.into(_database.uploadTasks).insert(newTask);
        break;
    }
  }
}
```

### 状态转换验证

#### TaskStatusValidator（任务状态转换验证器）

**设计目的**：确保任务状态转换的合法性。

**状态转换图**：

```
pending
  ├─→ uploading（开始上传）
  └─→ cancelled（用户取消）

uploading
  ├─→ completed（上传成功）
  ├─→ failed（上传失败，可重试）
  ├─→ permanentlyFailed（达到最大重试次数）
  └─→ cancelled（用户取消）

failed
  ├─→ uploading（重试）
  ├─→ permanentlyFailed（达到最大重试次数）
  └─→ cancelled（用户取消）

permanentlyFailed
  └─→ uploading（用户手动重试）

cancelled（终态）
completed（终态）
```

**接口定义**：

```dart
/// 状态转换验证器
class TaskStatusValidator {
  /// 验证状态转换是否合法
  bool canTransition(UploadTaskStatus from, UploadTaskStatus to) {
    const allowedTransitions = {
      UploadTaskStatus.pending: [
        UploadTaskStatus.uploading,
        UploadTaskStatus.cancelled,
      ],
      UploadTaskStatus.uploading: [
        UploadTaskStatus.completed,
        UploadTaskStatus.failed,
        UploadTaskStatus.permanentlyFailed,
        UploadTaskStatus.cancelled,
      ],
      UploadTaskStatus.failed: [
        UploadTaskStatus.uploading,
        UploadTaskStatus.permanentlyFailed,
        UploadTaskStatus.cancelled,
      ],
      UploadTaskStatus.permanentlyFailed: [
        UploadTaskStatus.uploading, // 用户手动重试
      ],
    };
    
    return allowedTransitions[from]?.contains(to) ?? false;
  }
  
  /// 验证并更新状态（如果转换不合法会抛出异常）
  Future<void> validateAndUpdate({
    required Database database,
    required String taskId,
    required UploadTaskStatus from,
    required UploadTaskStatus to,
  }) async {
    if (!canTransition(from, to)) {
      throw StateError(
        'Invalid state transition: $from -> $to',
      );
    }
    
    await database.update(database.uploadTasks)
      ..where((t) => t.id.equals(taskId))
      ..write(UploadTasksCompanion(
        status: Value(to),
      ));
  }
}
```

## 实现细节

### 1. 并发控制实现（优化）

**设计原则**：
- **优先使用 background_downloader 的内置并发控制**：底层网络请求的并发控制由 background_downloader 管理
- **自定义并发控制器仅用于业务层面的优先级调度**：控制哪些任务可以进入执行队列
- **避免重复实现底层并发控制**：不在业务层重复实现网络层的并发控制

**实现方案**：

```dart
class UploadConcurrencyController {
  final Semaphore _semaphore;
  final int maxConcurrency;
  
  UploadConcurrencyController({
    this.maxConcurrency = 6,
  }) : _semaphore = Semaphore(maxConcurrency);
  
  /// 获取并发许可
  Future<void> acquire() async {
    await _semaphore.acquire();
  }
  
  /// 释放并发许可
  void release() {
    _semaphore.release();
  }
  
  /// 执行任务（业务层并发控制）
  /// 注意：此控制器仅控制任务进入执行队列，实际网络请求的并发由 background_downloader 管理
  Future<T> execute<T>(Future<T> Function() task) async {
    await acquire();
    try {
      // 任务进入执行队列后，由 background_downloader 管理实际的网络并发
      return await task();
    } finally {
      release();
    }
  }
}
```

**与 background_downloader 的集成**：

```dart
class UploadService {
  final UploadConcurrencyController _concurrencyController;
  final FileDownloader _downloader; // background_downloader 实例
  
  Future<void> uploadTask(UploadTask task) async {
    // 1. 业务层并发控制：控制任务进入执行队列
    await _concurrencyController.execute(() async {
      // 2. 使用 background_downloader 执行实际上传（其内部管理网络并发）
      final request = UploadRequest(
        url: task.remotePath,
        filePath: task.localPath,
        headers: await getAuthHeaders(),
      );
      
      await _downloader.enqueue(request);
    });
  }
}
```

```dart

### 2. 优先级管理实现

**目标**：按照优先级排序任务，优先上传图片和小文件。

**实现方案**：

```dart
class UploadTaskPriorityComparator implements Comparator<UploadTask> {
  @override
  int compare(UploadTask a, UploadTask b) {
    // 1. 任务类型优先：手动备份优先于自动备份
    if (a.taskType != b.taskType) {
      return a.taskType == UploadTaskType.manual ? -1 : 1;
    }
    
    // 2. 优先级字段（已设置好的优先级）
    final priorityDiff = a.priority.compareTo(b.priority);
    if (priorityDiff != 0) {
      return priorityDiff;
    }
    
    // 3. 图片优先于视频
    if (a.type != b.type) {
      return a.type == AssetType.image ? -1 : 1;
    }
    
    // 4. 小文件优先（可选配置）
    if (shouldPrioritizeSmallFiles) {
      final sizeDiff = a.fileSize.compareTo(b.fileSize);
      if (sizeDiff != 0) {
        return sizeDiff;
      }
    }
    
    // 5. 按创建时间排序（早创建的优先）
    return a.createdAt.compareTo(b.createdAt);
  }
}

// 使用优先级队列
final queue = PriorityQueue<UploadTask>(
  UploadTaskPriorityComparator(),

### 5. 智能重试机制实现

**目标**：实现指数退避重试策略，提高上传成功率。

**实现方案**：

```dart
class RetryStrategy {
  final int maxRetries;
  final Duration initialDelay;
  final double backoffMultiplier;
  
  RetryStrategy({
    this.maxRetries = 3,
    this.initialDelay = Duration(seconds: 1),
    this.backoffMultiplier = 2.0,
  });
  
  /// 计算重试延迟
  Duration calculateDelay(int retryCount) {
    final delay = initialDelay * math.pow(backoffMultiplier, retryCount);
    return Duration(milliseconds: delay.inMilliseconds);
  }
  
  /// 执行带重试的任务
  Future<T> executeWithRetry<T>(Future<T> Function() task) async {
    int retryCount = 0;
    
    while (retryCount <= maxRetries) {
      try {
        return await task();
      } catch (e) {
        if (retryCount == maxRetries || !isRetryableError(e)) {
          rethrow;
        }
        
        retryCount++;
        final delay = calculateDelay(retryCount - 1);
        await Future.delayed(delay);
      }
    }
    
    throw Exception('Max retries exceeded');
  }
  
  /// 判断错误是否可重试
  bool isRetryableError(dynamic error) {
    if (error is DioException) {
      return error.type == DioExceptionType.connectionTimeout ||
          error.type == DioExceptionType.receiveTimeout ||
          error.type == DioExceptionType.sendTimeout ||
          (error.response?.statusCode ?? 0) >= 500;
    }
    return false;
  }
}
```

  ///

  /// - 全部成功：立即更新
  /// - 部分成功且成功比例 ≥ 80%：更新（避免少量失败阻塞增量同步）
  /// - 部分成功且成功比例 < 80%：不更新（避免跳过大量失败任务）
  /// - 全部失败：不更新
  /// 
  /// **注意**：此方法仅由自动备份调用，手动备份不更新 lastBackupTime
  Future<void> updateBackupTime({
    required String userId,
    required int successCount,
    required int totalCount,
  }) async {
    if (totalCount == 0) {
      return; // 没有任务，不更新
    }
    
    // 计算成功比例
    final successRatio = successCount / totalCount;
    
    // 更新策略
    if (successCount == totalCount || successRatio >= 0.8) {
      await database.into(database.backupStatus).insertOnConflictUpdate(
        BackupStatus(
          userId: userId,
          lastBackupTime: DateTime.now(),
        ),
      );
    }
  }

### 8. Checksum 去重实现

**目标**：使用文件哈希值进行去重，避免重复上传。

**实现方案**：

```dart
class ChecksumDeduplicator {
  final Database database;
  final ApiService apiService;
  static const int batchSize = 100; // 每批最多检查 100 个
  static const Duration timeout = Duration(seconds: 30); // 超时时间
  static const Duration cacheValidity = Duration(hours: 24); // 缓存有效期
  
  /// 批量检查已存在资产（支持分批和降级策略）
  Future<Set<String>> checkExistingAssets({
    required String userId,
    required List<String> checksums,
  }) async {
    final Set<String> existingChecksums = {};
    
    // 1. 优先检查本地数据库（按 userId 过滤）
    final localChecksums = await database.select(
      database.remoteAssets,
      where: (t) => t.checksum.isIn(checksums) & t.ownerId.equals(userId),
    ).get();
    
    final localSet = localChecksums.map((a) => a.checksum).toSet();
    existingChecksums.addAll(localSet);
    
    // 2. 检查服务器（分批检查，避免单次请求过大）
    final remainingChecksums = checksums.where((c) => !existingChecksums.contains(c)).toList();
    
    if (remainingChecksums.isNotEmpty) {
      try {
        // 分批检查
        for (int i = 0; i < remainingChecksums.length; i += batchSize) {
          final batch = remainingChecksums.skip(i).take(batchSize).toList();
          
          // 带超时的批量检查
          final remoteChecksums = await apiService
              .checkAssetsExist(batch)
              .timeout(timeout);
          
          existingChecksums.addAll(remoteChecksums);
        }
      } catch (e) {
        // 降级策略：批量检查失败时，记录错误但不阻塞流程
        // 可以选择跳过去重或逐个检查（根据配置决定）
        logger.warn('批量检查失败，跳过服务器去重检查: $e');
        // 如果配置了严格模式，可以抛出异常
      }
    }
    
    // 3. 返回已存在的 checksum 集合
    return existingChecksums;
  }
  
  /// 过滤已上传资产（支持跳过去重选项）
  Future<List<UploadTask>> filterUploadedAssets({
    required String userId,
    required List<UploadTask> tasks,
    bool skipDeduplication = false,
  }) async {
    if (skipDeduplication) {
      return tasks; // 手动备份可选跳过
    }
    
    // 计算所有任务的 checksum
    final checksums = await Future.wait(
      tasks.map((task) => calculateChecksum(task.localPath)),
    );
    
    // 批量检查已存在资产
    final existingChecksums = await checkExistingAssets(
      userId: userId,
      checksums: checksums,
    );
    
    // 过滤掉已存在的资产
    return tasks
        .where((task) {
          final index = tasks.indexOf(task);
          return !existingChecksums.contains(checksums[index]);
        })
        .toList();
  }
  
  /// 计算文件 checksum
  Future<String> calculateChecksum(String filePath) async {
    final file = File(filePath);
    final bytes = await file.readAsBytes();
    final hash = sha256.convert(bytes);
    return hash.toString();
  }
}
```

enum UploadErrorType {
  network, // 网络错误
  authentication, // 认证错误

  local, // 本地错误（文件不存在、权限不足等）

/// 上传错误
class UploadError {
  final UploadErrorType type;
  final String message;
  final dynamic originalError;
  final String? assetId;
  final DateTime timestamp;
  
  UploadError({
    required this.type,
    required this.message,
    this.originalError,
    this.assetId,
    DateTime? timestamp,
  }) : timestamp = timestamp ?? DateTime.now();
  
  /// 判断是否可重试
  bool get isRetryable {
    switch (type) {
      case UploadErrorType.network:
      case UploadErrorType.timeout:
        return true; // 网络和超时错误可重试
      case UploadErrorType.server:
        return _isServerRetryable(); // 5xx 可重试，4xx 不可重试
      case UploadErrorType.authentication:
      case UploadErrorType.local:
      case UploadErrorType.cancelled:
        return false; // 认证、本地、取消错误不可重试
    }
  }
  
  bool _isServerRetryable() {
    // 5xx 错误可重试，4xx 错误不可重试
    if (originalError is DioException) {
      final statusCode = (originalError as DioException).response?.statusCode;
      if (statusCode != null) {
        return statusCode >= 500 && statusCode < 600; // 5xx 可重试
      }
    }
    return false;
  }
}

### 自动恢复机制

```dart
class AutoRecoveryManager {
  final Database database;
  final UploadService uploadService;
  
  /// 恢复未完成任务（需要 userId 确保多用户隔离）
  Future<void> recoverPendingTasks({required String userId}) async {
    // 1. 获取未完成任务（按 userId 过滤）
    final pendingTasks = await database.select(
      database.uploadTasks,
      where: (t) => t.userId.equals(userId) & t.status.isIn([
        UploadTaskStatus.pending,
        UploadTaskStatus.uploading,
        UploadTaskStatus.failed, // 可重试的失败任务
      ]),
    ).get();
    
    // 2. 检查任务是否仍然有效
    for (final task in pendingTasks) {
      if (await isTaskValid(task)) {
        // 3. 检查重试次数
        if (task.status == UploadTaskStatus.failed) {
          if (task.retryCount >= task.maxRetries) {
            // 达到最大重试次数，标记为永久失败
            await markTaskAsPermanentlyFailed(task.id, 'Max retries exceeded');
            continue;
          }
        }
        
        // 4. 恢复任务
        await uploadService.addUploadTask(task);
      } else {
        // 5. 标记为永久失败
        await markTaskAsPermanentlyFailed(task.id, 'Task expired or invalid');
      }
    }
  }
  
  /// 检查任务是否有效
  Future<bool> isTaskValid(UploadTask task) async {
    // 检查文件是否存在
    final file = File(task.localPath);
    if (!await file.exists()) {
      return false;
    }
    
    // 检查任务是否过期（例如：超过 7 天）
    final daysSinceCreation = DateTime.now().difference(task.createdAt).inDays;
    if (daysSinceCreation > 7) {
      return false;
    }
    
    return true;
  }
  
  /// 标记任务为永久失败
  Future<void> markTaskAsPermanentlyFailed(String taskId, String reason) async {
    await database.update(
      database.uploadTasks,
    )..where((t) => t.id.equals(taskId))
     ..write(UploadTasksCompanion(
       status: Value(UploadTaskStatus.permanentlyFailed),
       errorMessage: Value(reason),
     ));
  }
}
```

**重试策略说明**：
- **最大重试次数**：默认 3 次，可通过 `maxRetries` 配置
- **重试间隔**：指数退避策略（1秒、2秒、4秒）
- **可重试错误**：网络错误、超时错误、5xx 服务器错误
- **不可重试错误**：认证错误、4xx 客户端错误、本地文件错误、取消错误
- **永久失败**：达到最大重试次数后标记为 `permanentlyFailed`，不再自动重试，但支持用户手动重试
```

### 任务状态转换规则

**状态转换图**：

```
pending
  ├─→ uploading（开始上传）
  └─→ cancelled（用户取消）

uploading
  ├─→ completed（上传成功）
  ├─→ failed（上传失败，可重试）
  ├─→ permanentlyFailed（达到最大重试次数）
  └─→ cancelled（用户取消）

failed
  ├─→ uploading（重试）
  ├─→ permanentlyFailed（达到最大重试次数）
  └─→ cancelled（用户取消）

permanentlyFailed
  └─→ uploading（用户手动重试）

cancelled（终态）
completed（终态）
```

**状态转换验证**：

所有状态更新必须通过 `TaskStatusValidator` 验证，确保转换合法：

```dart

  database: database,
  taskId: taskId,
  from: UploadTaskStatus.pending,
  to: UploadTaskStatus.uploading,

// ❌ 错误使用（会抛出异常）

```

**状态转换规则说明**：
- **pending** → **uploading**：任务开始执行
- **pending** → **cancelled**：用户取消待执行任务
- **uploading** → **completed**：上传成功
- **uploading** → **failed**：上传失败（可重试）
- **uploading** → **permanentlyFailed**：达到最大重试次数
- **uploading** → **cancelled**：用户取消执行中的任务
- **failed** → **uploading**：自动或手动重试
- **failed** → **permanentlyFailed**：达到最大重试次数
- **failed** → **cancelled**：用户取消失败任务
- **permanentlyFailed** → **uploading**：用户手动重试
- **cancelled** 和 **completed** 为终态，不能转换到其他状态

    if (_connections.containsKey(host)) {
      return _connections[host]!;
    }
    
    final client = HttpClient();
    client.idleTimeout = Duration(seconds: 30);
    client.maxConnectionsPerHost = 6;
    
    _connections[host] = client;
    return client;
  }
  
  /// 关闭所有连接
  Future<void> closeAll() async {
    for (final client in _connections.values) {
      client.close(force: true);
    }
    _connections.clear();

class RequestBatcher {
  final Duration batchWindow;
  final int maxBatchSize;
  final List<PendingRequest> _pendingRequests = [];
  
  /// 批量检查已存在资产
  Future<Set<String>> batchCheckAssets(List<String> checksums) async {
    // 将请求添加到批处理队列
    _pendingRequests.addAll(
      checksums.map((c) => PendingRequest(checksum: c)),
    );
    
    // 如果达到批处理大小或超时，执行批处理
    if (_pendingRequests.length >= maxBatchSize) {
      return await _executeBatch();
    }
    
    // 否则等待批处理窗口
    await Future.delayed(batchWindow);
    return await _executeBatch();
  }
  
  Future<Set<String>> _executeBatch() async {
    final checksums = _pendingRequests.map((r) => r.checksum).toList();
    _pendingRequests.clear();
    
    // 调用批量 API
    return await apiService.checkAssetsExist(checksums);
  }
}

class AutoCleanupManager {

  Future<void> autoCleanupCompletedTasks() async {
    final cutoffDate = DateTime.now().subtract(Duration(days: 7));

    await database.delete(

      where: (t) => t.status.equals(UploadTaskStatus.completed) &

    // 清理 30 天前的失败任务
    await database.delete(
      database.uploadTasks,
      where: (t) => t.status.equals(UploadTaskStatus.failed) &
          t.createdAt.isSmallerThanValue(cutoffDate),
    );
  }
  
  /// 清理临时文件
  Future<void> cleanupTemporaryFiles() async {
    final tempDir = await getTemporaryDirectory();
    final files = tempDir.listSync();
    
    for (final file in files) {
      if (file is File) {
        final stat = await file.stat();
        final age = DateTime.now().difference(stat.modified);
        
        // 删除超过 1 天的临时文件
        if (age.inDays > 1) {
          await file.delete();
        }
      }
    }
  }

### 常见问题和解决方案

#### 问题 1：Engine 创建失败

**症状**：后台任务无法启动，Engine 创建失败

**可能原因**：
- Engine Cache 已满
- 内存不足
- 配置错误

**解决方案**：
1. 检查 Engine Cache 大小限制
2. 确保任务完成后正确销毁 Engine
3. 检查内存使用情况
4. 验证 Pigeon 接口配置

#### 问题 2：任务不执行

**症状**：配置了后台任务，但任务不执行

**可能原因**：
- WorkManager/BGTaskScheduler 未正确配置
- 约束条件不满足
- 系统限制

**解决方案**：
1. 检查 WorkManager/BGTaskScheduler 配置
2. 检查约束条件（网络、充电等）
3. 在 Android 上检查电池优化设置
4. 在 iOS 上检查后台刷新权限

#### 问题 3：内存泄漏

**症状**：长时间运行后内存持续增长

**可能原因**：
- Engine 未正确销毁
- 数据库连接未关闭
- 文件句柄未释放

**解决方案**：

### 1. 数据库迁移策略

#### 1.1 backup_status 表结构变更迁移

**迁移场景**：
- 添加新字段
- 修改字段类型
- 删除字段

**迁移示例**：
```dart

@DriftDatabase(tables: [BackupStatus, ...])
class AppDatabase extends _$AppDatabase {
  AppDatabase() : super(_openConnection());
  
  @override
  int get schemaVersion => 2; // 版本号
  
  @override
  MigrationStrategy get migration {
    return MigrationStrategy(
      onUpgrade: (migrator, from, to) async {
        if (from < 2) {
          // 从版本 1 升级到版本 2
          await migrator.addColumn(backupStatus, backupStatus.newColumn);
        }
      },
    );
  }
}
```

#### 1.2 任务格式版本化

**版本字段**：
- 在 `UploadTask` 模型中添加 `version` 字段

- 结构变更时递增版本号

**兼容性处理**：
- **读取旧版本任务**：使用 `TaskVersionMigrator` 转换格式
- **创建新任务**：使用最新版本格式
- **混合版本支持**：支持同时存在多个版本的任务

### 2. 配置迁移策略

#### 2.1 全局配置迁移

**迁移场景**：
- 配置项重命名
- 配置项类型变更
- 新增配置项默认值
- 删除配置项

**迁移策略**：
- **读取时迁移**：加载配置时检查版本，自动迁移
- **写入时迁移**：保存配置时使用新格式
- **向后兼容**：支持读取旧格式配置

**实现方式**：
```dart
class ConfigMigrator {
  Future<Map<String, dynamic>> migrateConfig(
    Map<String, dynamic> oldConfig,
    int fromVersion,
    int toVersion,
  ) async {
    var config = oldConfig;
    
    // 逐步迁移每个版本
    for (int version = fromVersion; version < toVersion; version++) {
      config = await _migrateFromVersion(config, version);
    }
    
    return config;
  }
  
  Future<Map<String, dynamic>> _migrateFromVersion(
    Map<String, dynamic> config,
    int version,
  ) async {
    switch (version) {
      case 1:
        // 版本 1 到 2 的迁移逻辑
        if (config.containsKey('oldKey')) {
          config['newKey'] = config['oldKey'];
          config.remove('oldKey');
        }
        break;
      // 更多版本迁移...
    }
    return config;
  }
}
```

**迁移场景**：
- `backup_status` 表结构变更
- 配置项默认值变更
- 配置项枚举值变更

**迁移策略**：
- 数据库迁移时自动处理结构变更

### 3. 任务队列迁移

#### 3.1 旧版本任务处理

**处理策略**：
- **读取时转换**：读取旧版本任务时，转换为新格式
- **执行前验证**：执行前验证任务格式是否兼容
- **不兼容处理**：不兼容的任务标记为 `permanentlyFailed`，记录原因

**兼容性检查**：
```dart
class TaskCompatibilityChecker {
  bool isCompatible(UploadTask task, int currentVersion) {
    if (task.version == null) {
      return false; // 无版本号的任务视为不兼容
    }
    
    // 定义兼容版本范围
    const int minSupportedVersion = 1;
    const int maxSupportedVersion = 3;
    
    return task.version! >= minSupportedVersion && 
           task.version! <= maxSupportedVersion;
  }
  
  Future<UploadTask?> migrateIfNeeded(UploadTask task) async {
    if (!isCompatible(task, currentVersion)) {
      // 尝试迁移
      return await TaskVersionMigrator().migrate(
        task,
        task.version ?? 1,
        currentVersion,
      );
    }
    return task;
  }
}
```

#### 3.2 任务清理与归档

**清理策略**：
- 不兼容的任务：标记为 `permanentlyFailed`，30 天后清理
- 旧版本已完成任务：正常清理（按时间规则）
- 任务格式变更：不影响已完成任务的清理

### 4. 版本兼容性矩阵

**兼容性规则**：
- **向前兼容**：新版本应用应能读取旧版本数据
- **向后兼容**：旧版本应用不应因新版本数据而崩溃（尽量避免）
- **迁移窗口**：支持跨多个版本的迁移（如从版本 1 直接迁移到版本 3）

**版本兼容性表**：

| 应用版本 | 数据版本 1 | 数据版本 2 | 数据版本 3 |
|---------|-----------|-----------|-----------|
| 1.0.0   | ✅ 兼容   | ❌ 不兼容  | ❌ 不兼容  |
| 2.0.0   | ✅ 兼容   | ✅ 兼容   | ❌ 不兼容  |
| 3.0.0   | ✅ 兼容   | ✅ 兼容   | ✅ 兼容   |

**说明**：
- ✅ 兼容：可以正常读取和使用
- ❌ 不兼容：需要迁移或标记为失败

    if (metrics.errorRate > 0.2) {
      alert('High error rate detected: ${metrics.errorRate}%', 
            level: AlertLevel.warning);
    }
    
    // 检查上传速度
    if (metrics.avgUploadSpeed < 100 * 1024) { // 小于 100KB/s
      alert('Low upload speed detected: ${metrics.avgUploadSpeed} bytes/s',
            level: AlertLevel.warning);
    }
  }
}

### 1. UploadTask 模型完善
- ✅ 增加 `userId` 字段，支持多用户隔离
- ✅ 增加 `taskType` 字段（`manual`/`auto`），区分手动和自动备份
- ✅ 增加 `retryCount` 和 `maxRetries` 字段，支持重试机制
- ✅ 增加 `permanentlyFailed` 状态，区分临时失败和永久失败

### 2. lastBackupTime 更新策略明确
- ✅ 明确更新策略：全部成功或成功比例 ≥ 80% 才更新
- ✅ 三种自动备份模式的 lastBackupTime 使用说明
- ✅ 手动备份不更新 lastBackupTime

### 3. 手动备份去重检查
- ✅ 手动备份支持可选去重检查（默认启用，可通过配置关闭）
- ✅ 避免重复上传，节省网络和存储资源

### 4. 优先级管理完善
- ✅ 优先级排序规则明确：任务类型 > 优先级字段 > 文件类型 > 文件大小 > 创建时间
- ✅ 手动备份始终优先于自动备份

### 5. 多用户支持完善
- ✅ 所有服务接口方法都要求 `userId` 参数
- ✅ 数据库查询始终按 `userId` 过滤
- ✅ 确保多用户场景下的数据隔离

### 6. 去重检查性能优化
- ✅ 分批检查（每批 100 个 checksum）
- ✅ 超时控制（30 秒）
- ✅ 降级策略（批量检查失败时的处理）
- ✅ 本地缓存优先，减少服务器请求

### 7. 错误恢复机制明确
- ✅ 重试策略：最大 3 次，指数退避
- ✅ 可重试和不可重试错误的区分
- ✅ 永久失败的处理机制

### 8. 配置同步机制
- ✅ 配置加载时机明确
- ✅ 配置验证机制
- ✅ 配置迁移支持
