## 二、高优先级问题

### 1. 可取消加载机制缺失 ⚠️

#### 问题描述

设计文档要求实现可取消加载机制，包括：
- `CancellableImageProviderMixin` mixin
- Widget 销毁时自动取消加载
- 支持手动取消加载任务

#### 设计文档要求

```dart
mixin CancellableImageProviderMixin<T extends ImageProvider<T>> on ImageProvider<T> {
  bool _isCancelled = false;
  ImageRequest? _currentRequest;
  
  bool get isCancelled => _isCancelled;
  
  void cancel() {
    _isCancelled = true;
    _currentRequest?.cancel();
    _currentRequest = null;
  }
  
  // ... 其他实现
}
```

```dart
class MediaImageWidget extends StatefulWidget {
  // Widget 销毁时自动取消加载
  @override
  void dispose() {
    if (_imageProvider is CancellableImageProviderMixin) {
      (_imageProvider as CancellableImageProviderMixin).cancel();
    }
    super.dispose();
  }
}
```

#### 实际实现状态

- ❌ 未实现 `CancellableImageProviderMixin`
- ❌ `MediaImageWidget` 是 `StatelessWidget`，无法在 `dispose` 中取消
- ❌ 所有 ImageProvider 都没有取消机制
- ❌ 远程下载任务无法取消

#### 影响分析

1. **资源浪费**：组件销毁后继续加载图片，浪费网络和 CPU 资源
2. **内存泄漏风险**：未取消的加载任务可能持有 Widget 引用
3. **用户体验**：快速滚动时可能加载大量不需要的图片
4. **性能问题**：后台任务占用资源，影响应用性能

#### 相关文件

- `lib/presentation/widgets/media/media_image_widget.dart` - 需要改为 StatefulWidget
- `lib/features/media_loading/providers/*.dart` - 需要添加取消机制
- `lib/features/media_loading/providers/remote_thumb_provider.dart` - 需要取消下载流
- `lib/features/media_loading/providers/remote_full_provider.dart` - 需要取消下载流

#### 修复建议

1. 创建 `CancellableImageProviderMixin` mixin
2. 将 `MediaImageWidget` 改为 `StatefulWidget`
3. 在 `dispose` 中取消加载任务
4. 为远程 Provider 添加 `StreamSubscription` 管理
5. 在加载过程中检查取消状态

### 2. 错误处理机制不完整 ⚠️

#### 问题描述

设计文档要求实现完整的错误处理机制，包括：
- 自定义异常类型（网络错误、文件系统错误、解码错误）
- 自动恢复机制（缓存回退、重试）
- 结构化错误处理

#### 设计文档要求

**异常类型定义**：
```dart
class NetworkImageException implements Exception {
  final String message;
  final int? statusCode;
  final String? url;
}

class FileSystemImageException implements Exception {
  final String message;
  final String? filePath;
}

class ImageDecodeException implements Exception {
  final String message;
  final String? source;
}
```

**错误处理策略**：
1. 网络错误 → 回退到磁盘缓存
2. 文件系统错误 → 回退到远程资源（如果有）
3. 解码错误 → 清理损坏的缓存文件
4. 自动重试机制（指数退避，最多 3 次）

#### 实际实现状态

- ❌ 未定义自定义异常类型
- ❌ 使用通用 `Exception`，错误信息不够明确
- ❌ 无自动重试机制
- ❌ 网络错误时未回退到缓存
- ❌ 解码错误时未清理损坏的缓存文件
- ⚠️ 有基本错误日志，但缺少结构化处理

#### 影响分析

1. **错误诊断困难**：无法区分错误类型，难以定位问题
2. **用户体验差**：网络波动时无法自动恢复
3. **缓存污染**：损坏的缓存文件无法自动清理
4. **稳定性问题**：缺少重试机制，临时网络问题导致加载失败

#### 相关文件

- `lib/features/media_loading/providers/remote_thumb_provider.dart`
- `lib/features/media_loading/providers/remote_full_provider.dart`
- `lib/features/media_loading/providers/local_thumb_provider.dart`
- `lib/features/media_loading/providers/local_full_provider.dart`

#### 修复建议

1. 创建异常类型文件：`lib/features/media_loading/exceptions/`
   - `network_image_exception.dart`
   - `file_system_image_exception.dart`
   - `image_decode_exception.dart`
2. 实现自动重试机制（指数退避）
3. 实现缓存回退逻辑
4. 实现损坏缓存清理机制
5. 完善错误日志记录

### 3. 缓存键格式不一致 ⚠️

#### 问题描述

设计文档要求 LocalThumbProvider 的缓存键格式为：
```
{userId}{localId}{checksum}{width}{height}
```

但实际实现中只包含：
```
local_thumb_{asset.id}_{width}_{height}
```

缺少 `userId` 和 `checksum`。

#### 设计文档要求

```dart
// 缓存键格式：{userId}{localId}{checksum}{width}{height}
final cacheKey = '$userId${assetData.localId}${assetData.checksum}$width$height';
```

#### 实际实现状态

```dart
// lib/features/media_loading/providers/local_thumb_provider.dart
String _generateCacheKey(LocalThumbProvider key) {
  return 'local_thumb_${key.asset.id}_${key.size.width.toInt()}_${key.size.height.toInt()}';
}
```

- ❌ 缺少 `userId`：多用户场景下可能冲突
- ❌ 缺少 `checksum`：文件变更后可能使用旧缓存

#### 影响分析

1. **多用户冲突**：不同用户的相同 localId 会共享缓存
2. **缓存失效问题**：文件内容变更后，checksum 变化但缓存键不变，可能使用旧缓存
3. **缓存命中率降低**：相同文件不同用户需要重复生成缩略图

#### 相关文件

- `lib/features/media_loading/providers/local_thumb_provider.dart` - 第 93-95 行

#### 修复建议

1. 在 `LocalThumbProvider` 中添加 `userId` 参数
2. 从 `BaseAsset` 获取 `checksum`
3. 更新缓存键生成逻辑：
   ```dart
   String _generateCacheKey(LocalThumbProvider key, String? userId, String? checksum) {
     return '${userId ?? 'unknown'}${key.asset.id}${checksum ?? ''}${key.size.width.toInt()}${key.size.height.toInt()}';
   }
   ```

### 5. LocalFullImageProvider 渐进式加载不完整

#### 问题描述

设计文档要求 LocalFullImageProvider 实现多阶段渐进式加载：
1. 先显示缩略图（从缓存或生成）
2. 加载适配设备分辨率的图片
3. 根据设置决定是否加载原图

#### 设计文档要求

```dart
// 加载流程：
// 1. 先显示缩略图（从缓存或生成）
// 2. 加载适配设备分辨率的图片
// 3. 根据设置决定是否加载原图
```

#### 实际实现状态

```dart
// lib/features/media_loading/providers/local_full_provider.dart
Future<ui.Codec> _loadImage(...) async {
  if (key.asset.type == AssetType.image) {
    // 直接读取原文件，无渐进式加载
    final file = await key.asset.originFile;
    final buffer = await ui.ImmutableBuffer.fromFilePath(file.path);
    return await decode(buffer);
  }
  // ...
}
```

- ❌ 直接加载原图，无渐进式加载
- ❌ 未先显示缩略图
- ❌ 未考虑 `loadOriginal` 设置
- ❌ 未加载适配设备分辨率的中间图片

#### 影响分析

1. **加载速度慢**：直接加载原图，大文件加载时间长
2. **用户体验差**：无渐进式显示，等待时间长
3. **内存占用高**：直接加载原图，内存占用大
4. **未尊重用户设置**：未检查 `loadOriginal` 设置

#### 相关文件

- `lib/features/media_loading/providers/local_full_provider.dart`

#### 修复建议

1. 实现多阶段加载流程：
   ```dart
   Stream<ui.Codec> _loadImage(...) async* {
     // 阶段 1：加载缩略图
     final thumbCodec = await _loadThumbnail(...);
     yield thumbCodec;
     
     // 阶段 2：加载适配分辨率图片
     final adaptedCodec = await _loadAdaptedImage(...);
     yield adaptedCodec;
     
     // 阶段 3：根据设置决定是否加载原图
     if (shouldLoadOriginal) {
       final originalCodec = await _loadOriginalImage(...);
       yield originalCodec;
     }
   }
   ```
2. 使用 `MultiImageStreamCompleter` 支持多阶段加载
3. 检查 `AppSetting.get(Setting.loadOriginal)` 设置

**说明**：需要实现自定义异常类型以提升错误处理能力。⚠️ **需要修复**
