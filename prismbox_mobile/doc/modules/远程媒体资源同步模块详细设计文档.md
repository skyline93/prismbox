## 模块概述

### 职责范围

远程媒体资源同步模块是 PrismBox 移动端的核心功能模块，负责：

1. **远程资产同步**：从服务器同步远程媒体资源到本地数据库
2. **增量同步**：基于时间戳和 checkpoint 机制实现高效增量同步
3. **流式同步**：支持流式传输，提升大数据量同步性能
4. **数据一致性**：确保本地和远程数据的一致性
5. **多用户支持**：支持多用户隔离的同步状态管理

### 模块定位

本模块与**本地媒体同步模块**形成完整的同步体系：

- **本地媒体同步模块**：同步系统相册到本地数据库
- **远程媒体资源同步模块**：同步服务器资产到本地数据库
- **数据关联**：通过 `checksum` 关联本地和远程资产

**数据流向**：
```
服务器 → 远程同步模块 → RemoteAssetEntity → 关联 LocalAssetEntity → UI 展示
```

### 多设备场景说明

**核心原则**：每个设备只记录自己拥有的数据，通过合并查询实现统一展示。

**典型场景**：
- **设备A（上传设备）**：本地有照片，上传到服务器
  - `local_asset_entity`：有记录（本地文件存在，`path` 字段指向本地文件）
  - `remote_asset_entity`：有记录（通过 `checksum` 关联）
  - 状态：`AssetState.merged`（本地+远程）

- **设备B（同步设备）**：本地没有照片，从服务器同步
  - `local_asset_entity`：**无记录**（本地文件不存在）
  - `remote_asset_entity`：有记录（从服务器同步）
  - 状态：`AssetState.remote`（仅远程）

**关键设计**：
1. **表独立性**：`local_asset_entity` 和 `remote_asset_entity` 是独立的表，不强制外键关联
2. **本地资产必须有路径**：`local_asset_entity.path` 是必填字段，如果本地没有文件就不写入
3. **远程资产不需要路径**：`remote_asset_entity` 不存储文件路径，通过服务器 API 访问
4. **合并查询**：UI 展示时通过 SQL 视图或应用层合并本地和远程资产，避免重复

### 核心目标

1. **高效同步**：支持全量和增量同步，减少数据传输量
2. **稳定可靠**：完善的错误处理和重试机制
3. **高性能**：流式传输、批量处理、游标分页
4. **用户体验**：后台同步，不阻塞用户操作

### 设计原则

1. **职责分离**：同步接口与展示接口分离
2. **流式优先**：大数据量使用流式传输
3. **Checkpoint 机制**：支持断点续传和增量同步
4. **多用户隔离**：每个用户独立的同步状态
5. **向后兼容**：支持渐进式升级

### 与其他模块的关系

```
远程媒体资源同步模块
    │
    ├─→ API 对接模块：调用同步接口
    ├─→ 数据库模块：存储远程资产信息（RemoteAssetEntity）
    ├─→ 本地媒体同步模块：通过 checksum 关联本地和远程资产
    ├─→ 备份上传下载模块：共享同步逻辑，用于去重判断
    └─→ 媒体资源展示模块：提供远程资产数据源
```

### 1. 流式同步接口（主要接口）

#### 1.1 接口定义

```go
// POST /api/v1/sync/assets/stream
// Content-Type: application/json
// Accept: application/jsonlines+json

// 请求体
type SyncStreamRequest struct {
    Types      []SyncRequestType `json:"types"`       // 同步类型列表
    Reset      bool              `json:"reset"`       // 是否重置同步
    UpdatedAfter *time.Time      `json:"updated_after,omitempty"` // 增量同步时间戳
}

// 响应格式：JSON Lines（每行一个 JSON 对象）
// Content-Type: application/jsonlines+json
```

#### 1.2 同步类型枚举

```go
type SyncRequestType string

const (
    SyncRequestTypeAssetsV1 SyncRequestType = "assets_v1"  // 资产同步
)
```

#### 1.3 响应格式（JSON Lines）

每行一个 JSON 对象，格式如下：

```json
{"type":"asset_v1","ids":["uuid1","uuid2"],"data":{...},"ack":"checkpoint_id"}
{"type":"asset_v1","ids":["uuid3"],"data":{...},"ack":"checkpoint_id"}
{"type":"sync_complete_v1","ids":["now_id"],"data":{}}
```

**字段说明**：
- `type`：实体类型（`asset_v1`、`asset_delete_v1`、`sync_complete_v1`、`sync_reset_v1`）
- `ids`：实体 ID 列表（对于删除事件，为已删除资产的UUID列表）
- `data`：实体数据（资产信息，删除事件为空对象）
- `ack`：checkpoint ID，用于确认同步进度（删除事件不包含此字段）

#### 1.4 资产数据格式

```json
{
  "type": "asset_v1",
  "ids": ["uuid"],
  "data": {
    "uuid": "asset-uuid",
    "user_id": 1,
    "hash": "sha256-hash",
    "item_type": "image",
    "original_filename": "photo.jpg",
    "filename": "photo.jpg",
    "file_size": 1024000,
    "mime_type": "image/jpeg",
    "processing_status": "completed",
    "local_path": "storage/path",
    "backup_status": "completed",
    "created_at": "2024-01-01T00:00:00Z",
    "updated_at": "2024-01-01T00:00:00Z",
    "width": 1920,
    "height": 1080,
    "media_taken_at": "2024-01-01T00:00:00Z"
  },
  "ack": "checkpoint-id"
}
```

#### 1.5 特殊事件类型

**同步完成事件**：
```json
{"type":"sync_complete_v1","ids":["now_id"],"data":{}}
```

**同步重置事件**：
```json
{"type":"sync_reset_v1","ids":["reset"],"data":{}}
```

**删除事件（asset_delete_v1）**：
```json
{"type":"asset_delete_v1","ids":["uuid1","uuid2","uuid3"],"data":{}}
```

删除事件说明：
- **触发时机**：仅在增量同步时（`updatedAfter` 不为空）发送
- **发送时机**：在资产数据发送完成后、同步完成事件之前发送
- **查询机制**：服务器查询 `deleted=true` 且 `updated_at > updatedAfter` 的记录
- **批量发送**：每批最多100个资产ID
- **客户端处理**：收到删除事件后，应调用 `softDeleteAsset` 更新本地数据库的 `deletedAt` 字段
- **永久删除处理**：如果资产在永久删除前未被软删除，服务器会在永久删除前尝试发送删除事件（但由于没有 writer，实际无法发送，会在下次全量同步时发现资产不存在）

#### 1.6 实现要点

**Handler 层**：
```go
// POST /api/v1/sync/assets/stream
func (h *SyncHandler) StreamSyncAssets(c *gin.Context) {
    userID := middleware.MustGetUserID(c)

    }

```

**Service 层**：
```go
func (s *service) StreamAssets(ctx context.Context, writer io.Writer, req *StreamAssetsRequest) error {
    // 1. 检查是否需要重置
    if req.Reset {
        await s.checkpointRepo.ResetSyncProgress(req.UserID)
    }
    
    // 2. 获取 checkpoint
    checkpoint, err := s.checkpointRepo.GetCheckpoint(req.UserID, "assets_v1")
    if err != nil {
        return err
    }
    
    // 3. 检查是否需要全量同步
    if s.needsFullSync(checkpoint) {
        s.sendResetEvent(writer)
        return nil
    }
    
    // 4. 获取当前时间 ID（用于 checkpoint）
    nowID := s.checkpointRepo.GetNowID()
    
    // 5. 流式发送资产数据
    if err := s.streamAssets(ctx, writer, req.UserID, checkpoint, nowID); err != nil {
        return err
    }
    
    // 6. 发送删除事件（仅在增量同步时）
    if req.UpdatedAfter != nil {
        if err := s.sendDeletedAssets(ctx, writer, req); err != nil {
            // 记录警告，但不中断同步流程
            s.log.Warn("failed to send deleted assets", logger.Error(err))
        }
    }
    
    // 7. 发送同步完成事件
    s.sendCompleteEvent(writer, nowID)
    
    return nil
}
```

// Repository 层
func (r *syncRepository) GetAssetsWithCursor(ctx context.Context, userID uint, batchSize int, lastID string) ([]*models.Media, string, error) {
    query := r.db.Where("user_id = ? AND deleted = ?", userID, false)
    
    // 游标分页：使用 ID 排序和比较
    if lastID != "" {
        query = query.Where("id > ?", lastID)
    }
    
    var medias []*models.Media
    if err := query.Order("id ASC").Limit(batchSize + 1).Find(&medias).Error; err != nil {
        return nil, "", err
    }
    
    hasMore := len(medias) > batchSize
    if hasMore {
        medias = medias[:batchSize]
    }
    
    nextLastID := ""
    if len(medias) > 0 {
        nextLastID = medias[len(medias)-1].UUID
    }
    
    return medias, nextLastID, nil
}

#### 1.2 流式同步实现

```dart
Future<RemoteSyncResult> syncRemoteStream({
  bool reset = false,
  DateTime? updatedAfter,
  void Function(int current, int total)? onProgress,
}) async {
  final stopwatch = Stopwatch()..start();
  int addedCount = 0;
  int updatedCount = 0;
  int deletedCount = 0;
  final errors = <String>[];
  
  try {
    final endpoint = _apiService.endpoint ?? '';
    final url = '$endpoint/api/v1/sync/assets/stream';
    final headers = ApiService.getRequestHeaders();
    
    // 构建请求体
    final requestBody = {
      'types': ['assets_v1'],
      'reset': reset,
      if (updatedAfter != null) 'updated_after': updatedAfter.toIso8601String(),
    };
    
    // 发送请求
    final request = http.Request('POST', Uri.parse(url));
    request.headers.addAll(headers);
    request.headers['Content-Type'] = 'application/json';
    request.headers['Accept'] = 'application/jsonlines+json';
    request.body = jsonEncode(requestBody);
    
    final client = http.Client();
    final response = await client.send(request);
    
    if (response.statusCode != 200) {
      throw Exception('Sync failed: ${response.statusCode}');
    }
    
    // 流式读取响应
    await for (final chunk in response.stream.transform(utf8.decoder)) {
      // 解析 JSON Lines
      final lines = chunk.split('\n').where((line) => line.trim().isNotEmpty);
      
      for (final line in lines) {
        final event = _parseSyncEvent(line);
        await _handleSyncEvent(event, addedCount, updatedCount, deletedCount);
      }
    }
    
    client.close();
    
    return RemoteSyncResult(
      addedCount: addedCount,
      updatedCount: updatedCount,
      deletedCount: deletedCount,
      errors: errors,
      duration: stopwatch.elapsed,
    );
  } catch (e, stackTrace) {
    _logger.severe('Remote sync failed', e, stackTrace);
    return RemoteSyncResult(
      addedCount: addedCount,
      updatedCount: updatedCount,
      deletedCount: deletedCount,
      errors: [...errors, e.toString()],
      duration: stopwatch.elapsed,
    );
  }
}
```

#### 1.3 事件解析和处理

```dart
SyncEvent _parseSyncEvent(String line) {
  final json = jsonDecode(line) as Map<String, dynamic>;
  return SyncEvent(
    type: SyncEntityType.fromString(json['type'] as String),
    ids: (json['ids'] as List).cast<String>(),
    data: json['data'] as Map<String, dynamic>,
    ack: json['ack'] as String?,
  );
}

Future<void> _handleSyncEvent(
  SyncEvent event,
  int addedCount,
  int updatedCount,
  int deletedCount,
) async {
  switch (event.type) {
    case SyncEntityType.assetV1:
      // 处理资产数据
      // 注意：这里只处理远程资产，不处理本地资产
      // 本地资产由本地媒体同步模块负责
      for (final assetData in event.data) {
        final remoteAsset = _parseRemoteAsset(assetData);
        final existing = await _database.remoteAssetDao
            .getAssetById(remoteAsset.id);
        
        if (existing == null) {
          // 新增远程资产
          // 注意：不检查本地是否有相同 checksum 的资产
          // 因为设备B可能没有本地文件，但仍需要记录远程资产
          await _database.remoteAssetDao.insertAsset(remoteAsset);
          addedCount++;
        } else {
          // 更新远程资产
          await _database.remoteAssetDao.updateAsset(remoteAsset);
          updatedCount++;
        }
      }
      
      // 更新 checkpoint
      if (event.ack != null) {
        await _checkpointStore.setCheckpoint('assets_v1', event.ack!);
      }
      break;
      
    case SyncEntityType.syncCompleteV1:
      // 同步完成
      break;
      
    case SyncEntityType.syncResetV1:
      // 需要全量同步
      await _checkpointStore.clearCheckpoint('assets_v1');
      break;
  }
}
```

#### 1.4 多设备场景下的数据记录

**关键点**：远程同步只负责写入 `remote_asset_entity` 表，不涉及 `local_asset_entity` 表。

**设备B的同步流程**：
```
1. 从服务器接收远程资产数据
   ↓
2. 解析资产数据，创建 RemoteAssetEntityData
   ├─→ id: 服务器资产 ID
   ├─→ checksum: 文件哈希
   ├─→ ownerId: 用户 ID
   └─→ 其他字段：从服务器同步
   ↓
3. 检查本地是否存在相同 checksum 的资产（可选优化）
   ├─→ 存在：可以记录关联关系（但不强制）
   └─→ 不存在：正常，设备B可能没有本地文件
   ↓
4. 写入 remote_asset_entity 表
   ├─→ 无论本地是否有文件，都写入远程资产记录
   └─→ 这是多设备场景的关键：设备B需要知道服务器上有哪些资产
   ↓
5. 不写入 local_asset_entity 表
   └─→ 因为设备B本地没有文件，所以不写入本地资产表
```

## 多设备场景下的数据记录方案

### 场景分析

**设备A（上传设备）**：
- 本地相册中有照片
- 上传到服务器后，服务器返回远程资产信息
- 数据库记录：
  - `local_asset_entity`：有记录（本地文件存在，`path` 字段指向本地文件）
  - `remote_asset_entity`：有记录（通过 `checksum` 关联）
  - 状态：`AssetState.merged`（本地+远程）

**设备B（同步设备）**：
- 本地相册中没有这个照片
- 从服务器同步远程资产
- 数据库记录：
  - `local_asset_entity`：没有记录（本地文件不存在）
  - `remote_asset_entity`：有记录（从服务器同步）
  - 状态：`AssetState.remote`（仅远程）

### 数据记录方式

#### 1. 数据库表设计

**LocalAssetEntity（本地资产表）**
- 主键：设备资产 ID（photo_manager 的 AssetEntity ID）
- 关键字段：
  - `path`：本地文件路径（必填，因为需要知道文件位置才能读取）
  - `checksum`：文件哈希（可选，用于关联远程资产）

**RemoteAssetEntity（远程资产表）**
- 主键：服务器端资产 ID
- 关键字段：
  - `checksum`：文件哈希（必填，用于关联本地资产）
  - `ownerId`：所有者用户 ID

**关键点**：
- 两个表是独立的，不强制关联
- 通过 `checksum` 进行关联（可选）
- `local_asset_entity` 必须有 `path` 字段（本地文件路径）
- `remote_asset_entity` 不需要 `path` 字段（远程资源通过 URL 访问）

#### 2. 设备B的同步流程

```
1. 设备B从服务器同步远程资产
   ↓
2. 接收远程资产数据（JSON Lines 流式传输）
   ↓
3. 解析资产数据，创建 RemoteAssetEntityData
   ↓
4. 检查本地是否存在相同 checksum 的资产
   ├─→ 存在：关联 localAssetId（可选，用于优化）
   └─→ 不存在：localAssetId = null
   ↓
5. 写入 remote_asset_entity 表
   ├─→ id: 服务器资产 ID
   ├─→ checksum: 文件哈希
   ├─→ ownerId: 用户 ID
   ├─→ localAssetId: null（因为本地没有这个文件）
   └─→ 其他字段：从服务器同步
   ↓
6. 不写入 local_asset_entity 表（因为本地没有文件）
```

**方案B：应用层合并（备选）**

```dart
/// 合并本地和远程资产列表
Future<List<BaseAsset>> mergeLocalAndRemoteAssets(String userId) async {
  final localDao = LocalAssetDao(_database);
  final remoteDao = RemoteAssetDao(_database);
  
  // 1. 获取所有本地资产
  final localAssets = await localDao.getAllAssets();
  
  // 2. 获取所有远程资产
  final remoteAssets = await remoteDao.getUserAssets(userId);
  
  // 3. 构建 checksum 到本地资产的映射
  final localAssetMap = <String, LocalAssetEntityData>{};
  for (final asset in localAssets) {
    if (asset.checksum != null) {
      localAssetMap[asset.checksum!] = asset;
    }
  }
  
  // 4. 合并资产列表
  final mergedAssets = <BaseAsset>[];
  
  // 4.1 处理远程资产（包括有本地关联和没有本地关联的）
  for (final remoteData in remoteAssets) {
    final localData = localAssetMap[remoteData.checksum];
    
    if (localData != null) {
      // 合并资产：本地+远程
      mergedAssets.add(RemoteAsset.fromData(
        id: remoteData.id,
        localId: localData.id,  // 有关联
        // ... 其他字段
      ));
    } else {
      // 仅远程资产：设备B的情况
      mergedAssets.add(RemoteAsset.fromData(
        id: remoteData.id,
        localId: null,  // 没有本地关联
        // ... 其他字段
      ));
    }
  }
  
  // 4.2 处理仅本地的资产（排除已有远程版本的）
  for (final localData in localAssets) {
    if (localData.checksum == null) {
      // 没有 checksum，无法关联，作为仅本地资产
      mergedAssets.add(LocalAsset.fromData(
        id: localData.id,
        remoteId: null,
        // ... 其他字段
      ));
    } else {
      // 检查是否已有远程版本
      final hasRemote = remoteAssets.any(
        (r) => r.checksum == localData.checksum
      );
      
      if (!hasRemote) {
        // 仅本地资产（未上传）
        mergedAssets.add(LocalAsset.fromData(
          id: localData.id,
          remoteId: null,
          // ... 其他字段
        ));
      }
      // 如果已有远程版本，已经在上面处理过了
    }
  }
  
  // 5. 按创建时间排序
  mergedAssets.sort((a, b) => b.createdAt.compareTo(a.createdAt));
  
  return mergedAssets;
}
```

### 总结

多设备场景下的数据记录方式：

1. 设备A（上传设备）：
   - `local_asset_entity`：有记录（本地文件存在）
   - `remote_asset_entity`：有记录（通过 checksum 关联）
   - 状态：`merged`

2. 设备B（同步设备）：
   - `local_asset_entity`：无记录（本地文件不存在）
   - `remote_asset_entity`：有记录（从服务器同步）
   - 状态：`remote`

3. UI 展示：
   - 使用合并查询（SQL 视图或应用层合并）
   - 对于 `AssetState.remote` 的资产，使用远程资源加载器
   - 支持下载到本地（可选功能）

该设计支持多设备场景，每个设备只记录自己拥有的数据，通过合并查询实现统一展示。
