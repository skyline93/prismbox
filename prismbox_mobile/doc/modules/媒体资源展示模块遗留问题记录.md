## 遗留问题列表

### 问题 1：userId 获取机制未实现 ⚠️ **中优先级**

#### 问题描述

`_getUserId` 函数目前返回 `null`，使用 `'unknown'` 作为默认值。这导致在多用户场景下，不同用户的相同 `localId` 会共享缓存，可能造成缓存冲突。

#### 当前实现

**文件位置**: `lib/features/media_loading/image_provider_factory.dart`

```dart
/// 获取用户 ID（从 asset 中获取，如果可用）
/// 目前 BaseAsset 没有 userId 字段，返回 null
/// 后续可以根据需要从上下文或其他地方获取
String? _getUserId(BaseAsset asset) {
  // TODO: 从 asset 或上下文获取 userId
  // 目前返回 null，使用 'unknown' 作为默认值
  return null;
}
```

#### 影响分析

1. **缓存冲突风险**
   - 多用户场景下，不同用户的相同 `localId` 会共享缓存
   - 可能导致用户 A 看到用户 B 的缩略图

2. **缓存键不完整**
   - 当前缓存键格式：`{userId}{localId}{checksum}{width}{height}`
   - 由于 `userId` 始终为 `'unknown'`，无法实现真正的用户隔离

3. **数据安全性**
   - 无法确保用户数据的隔离性
   - 在多用户设备上存在数据泄露风险

#### 相关代码

- **缓存键生成** (`lib/features/media_loading/providers/local_thumb_provider.dart:144`)
  ```dart
  String _generateCacheKey(LocalThumbProvider key) {
    final userId = key.userId ?? 'unknown';  // 始终为 'unknown'
    final localId = key.asset.id;
    final checksum = key.checksum ?? '';
    final width = key.size.width.toInt();
    final height = key.size.height.toInt();
    return '${userId}${localId}${checksum}${width}${height}';
  }
  ```

- **RemoteAsset 已有 ownerId** (`lib/domain/entities/remote_asset.dart:22`)
  ```dart
  /// 所有者用户 ID
  final String ownerId;
  ```

#### 解决方案

**方案 1：从 RemoteAsset 获取 ownerId（推荐）**

```dart
String? _getUserId(BaseAsset asset) {
  // RemoteAsset 已有 ownerId 字段
  if (asset is RemoteAsset) {
    return asset.ownerId;
  }
  
  // LocalAsset 需要从用户服务获取
  return _getCurrentUserId();
}
```

**方案 2：从用户服务获取当前用户 ID**

```dart
String? _getUserId(BaseAsset asset) {
  // 从全局用户服务或 Riverpod Provider 获取
  // 需要创建 UserService 或使用现有的认证服务
  final userService = getIt<UserService>();
  return userService.currentUserId;
}
```

**方案 3：在 BaseAsset 中添加 ownerId 字段**

```dart
abstract class BaseAsset {
  // 添加 ownerId 字段
  String? get ownerId;
  
  // LocalAsset 实现
  @override
  String? get ownerId => _getCurrentUserId();
  
  // RemoteAsset 实现
  @override
  String? get ownerId => this.ownerId;  // 已有字段
}
```

#### 实施步骤

1. **确定用户服务接口**
   - 检查是否已有用户服务或认证服务
   - 确认如何获取当前登录用户的 ID

2. **实现 userId 获取逻辑**
   - 优先使用 RemoteAsset.ownerId
   - 对于 LocalAsset，从用户服务获取

3. **更新缓存键生成**
   - 确保所有 Provider 都使用正确的 userId

4. **测试多用户场景**
   - 验证不同用户的缓存隔离
   - 确保不会出现缓存冲突

#### 工作量估算

- **开发时间**: 1-2 天
- **测试时间**: 0.5-1 天
- **总计**: 1.5-3 天

#### 优先级

**中优先级** - 影响多用户场景的数据隔离，建议在下一个版本中修复。

### 问题 2：ImageRequest 抽象层未完全使用 ⚠️ **低优先级（可选优化）**

#### 问题描述

虽然已经创建了 `ImageRequest` 抽象层和 `LocalImageRequest`、`RemoteImageRequest` 实现，但现有的 Provider 尚未完全重构使用这些类。Provider 仍然直接实现加载逻辑，而不是委托给 ImageRequest。

#### 当前状态

**已创建的文件**:
- ✅ `lib/features/media_loading/requests/image_request.dart` - 抽象基类
- ✅ `lib/features/media_loading/requests/local_image_request.dart` - 本地图片请求实现
- ✅ `lib/features/media_loading/requests/remote_image_request.dart` - 远程图片请求实现

**未使用的 Provider**:
- ❌ `lib/features/media_loading/providers/local_thumb_provider.dart` - 未使用 ImageRequest
- ❌ `lib/features/media_loading/providers/local_full_provider.dart` - 未使用 ImageRequest
- ⚠️ `lib/features/media_loading/providers/remote_thumb_provider.dart` - 已使用 ImageLoader，但未使用 ImageRequest
- ⚠️ `lib/features/media_loading/providers/remote_full_provider.dart` - 已使用 ImageLoader，但未使用 ImageRequest

#### 影响分析

1. **代码耦合度高**
   - 加载逻辑与 Provider 紧密耦合
   - 难以独立测试加载逻辑

2. **代码重复**
   - Provider 和 ImageRequest 都有加载逻辑
   - 维护成本增加

3. **架构不一致**
   - 设计时引入了 ImageRequest 抽象层
   - 但实际实现未使用，造成架构不一致

#### 当前实现示例

**LocalThumbProvider 当前实现**:
```dart
Future<ui.Codec> _loadThumbnail(LocalThumbProvider key, ImageDecoderCallback decode) async {
  // 直接实现加载逻辑
  final cacheKey = _generateCacheKey(key);
  final cacheManager = key.cacheManager ?? ThumbnailImageCacheManager();
  // ... 大量加载逻辑
}
```

**应该使用 ImageRequest**:
```dart
Future<ui.Codec> _loadThumbnail(LocalThumbProvider key, ImageDecoderCallback decode) async {
  final request = LocalImageRequest(
    asset: key.asset,
    targetSize: key.size,
    cacheManager: key.cacheManager,
    userId: key.userId,
    checksum: key.checksum,
    isThumbnail: true,
  );
  setCurrentRequest(request);
  return await request.load(decode);
}
```

#### 解决方案

**重构步骤**:

1. **重构 LocalThumbProvider**
   ```dart
   Future<ui.Codec> _loadThumbnail(...) async {
     final request = LocalImageRequest(
       asset: key.asset,
       targetSize: key.size,
       cacheManager: key.cacheManager,
       userId: key.userId,
       checksum: key.checksum,
       isThumbnail: true,
     );
     setCurrentRequest(request);
     return await request.load(decode);
   }
   ```

2. **重构 LocalFullImageProvider**
   - 使用 LocalImageRequest 处理本地图片加载
   - 保持渐进式加载逻辑

3. **重构 RemoteThumbProvider 和 RemoteFullImageProvider**
   - 虽然已使用 ImageLoader，但可以考虑进一步使用 ImageRequest
   - 或者保持现状（ImageLoader 已经提供了足够的抽象）

4. **保持 API 向后兼容**
   - 确保重构不影响现有调用代码

#### 实施步骤

1. **评估重构收益**
   - 分析使用 ImageRequest 的收益
   - 考虑是否值得重构

2. **逐步重构**
   - 先重构 LocalThumbProvider
   - 再重构 LocalFullImageProvider
   - 最后考虑 Remote Provider

3. **添加单元测试**
   - 为 ImageRequest 添加单元测试
   - 确保重构后功能正常

4. **代码审查**
   - 确保代码质量和一致性

#### 工作量估算

- **开发时间**: 2-3 天
- **测试时间**: 1 天
- **总计**: 3-4 天

#### 优先级

**低优先级（可选优化）** - 不影响核心功能，属于架构优化，可以在后续版本中逐步重构。

### 问题 3：设备分辨率获取使用固定值 ⚠️ **低优先级（可选优化）**

#### 问题描述

`LocalFullImageProvider._getDeviceResolution()` 方法返回固定值 `Size(1080, 1920)`，未根据实际设备分辨率动态获取。这可能导致高分辨率设备加载过大图片（浪费内存），或低分辨率设备加载过小图片（影响清晰度）。

#### 当前实现

**文件位置**: `lib/features/media_loading/providers/local_full_provider.dart:245-251`

```dart
/// 获取设备分辨率
Size _getDeviceResolution() {
  // 默认使用 1080p 分辨率
  // 实际应用中可以通过 MediaQuery 获取，但这里没有 BuildContext
  // 所以使用合理的默认值
  return const Size(1080, 1920);
}
```

#### 影响分析

1. **内存浪费**
   - 高分辨率设备（如 4K 屏幕）可能加载过大的图片
   - 浪费内存和带宽

2. **清晰度问题**
   - 低分辨率设备可能加载过小的图片
   - 影响用户体验

3. **无法根据设备像素比优化**
   - 无法考虑设备的像素密度（devicePixelRatio）
   - 无法实现真正的设备适配

#### 使用场景

该方法在渐进式加载中使用：

```dart
// 阶段 2：加载适配设备分辨率的图片
if (shouldLoadAdapted) {
  final deviceResolution = _getDeviceResolution();  // 使用固定值
  final adaptedCodec = await _loadAdaptedImage(deviceResolution, decode);
  yield adaptedCodec;
}
```

#### 解决方案

**方案 1：通过参数传递设备分辨率（推荐）**

```dart
class LocalFullImageProvider extends ImageProvider<LocalFullImageProvider> {
  final Size? deviceResolution;  // 新增参数
  
  LocalFullImageProvider({
    required this.asset,
    this.targetSize,
    this.deviceResolution,  // 从外部传入
    ...
  });
  
  Size _getDeviceResolution() {
    return deviceResolution ?? const Size(1080, 1920);
  }
}
```

**在工厂方法中获取**:
```dart
ImageProvider getFullImageProvider(
  BaseAsset asset, {
  BuildContext? context,  // 可选参数
  ...
}) {
  Size? deviceResolution;
  if (context != null) {
    final mediaQuery = MediaQuery.of(context);
    deviceResolution = mediaQuery.size * mediaQuery.devicePixelRatio;
  }
  
  return LocalFullImageProvider(
    asset: asset,
    deviceResolution: deviceResolution,
    ...
  );
}
```

**方案 2：使用全局设备信息服务**

```dart
// 创建 DeviceInfoService
class DeviceInfoService {
  static Size? _cachedResolution;
  
  static Size getDeviceResolution() {
    if (_cachedResolution != null) {
      return _cachedResolution!;
    }
    
    // 从全局状态或配置获取
    // 或者使用 window.physicalSize
    final window = WidgetsBinding.instance.window;
    _cachedResolution = window.physicalSize / window.devicePixelRatio;
    return _cachedResolution!;
  }
  
  static void updateResolution(Size resolution) {
    _cachedResolution = resolution;
  }
}

// 在 Provider 中使用
Size _getDeviceResolution() {
  return DeviceInfoService.getDeviceResolution();
}
```

**方案 3：使用 window.physicalSize（最简单）**

```dart
import 'dart:ui' as ui;

Size _getDeviceResolution() {
  // 使用 Flutter 的 window API
  final window = ui.PlatformDispatcher.instance.views.first;
  if (window != null) {
    return window.physicalSize / window.devicePixelRatio;
  }
  return const Size(1080, 1920);  // 回退值
}
```
