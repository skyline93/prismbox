## 概述

本文档详细说明了备份过程中缩略图上传状态标识的优化方案。该功能让用户能够快速识别照片的上传状态：未上传、上传中、已上传、上传失败。

**功能目标**：
- 在照片页面每个缩略图右上角显示上传状态图标
- 支持四种状态：未上传、上传中（动态）、已上传、上传失败
- 实时更新状态，提供清晰的视觉反馈

---

## 一、状态设计

### 1.1 四种状态

1. **未上传（仅本地数据）**：
   - 图标：`Icons.cloud_off_outlined`（白色，透明度 0.8）
   - 条件：`asset.hasRemote == false` 且无上传任务记录

2. **上传中**：
   - 图标：动态进度指示器（`CircularProgressIndicator`）
   - 条件：上传任务状态为 `uploading` 或 `pending`
   - 显示：带进度百分比（如果有）或不确定进度动画

3. **已上传**：
   - 图标：`Icons.cloud_done_outlined`（绿色）
   - 条件：`asset.hasRemote == true` 或任务状态为 `completed`

4. **上传失败**：
   - 图标：`Icons.error_outline`（红色）
   - 条件：上传任务状态为 `failed` 或 `permanentlyFailed`

### 1.2 状态判断逻辑

```
1. 如果 asset.hasRemote == true → 已上传 ✅
2. 如果是 LocalAsset，查询上传任务状态：
   - uploading/pending → 上传中 🔄
   - failed/permanentlyFailed → 上传失败 ❌
   - completed → 已上传（即使 remoteAssetId 为空，可能是数据不一致）
   - paused → 上传中（用户可能继续上传）
   - cancelled → 未上传
3. 否则 → 未上传 ⚪
```

```dart
enum AssetUploadStatus {
  notUploaded,  // 未上传
  uploading,    // 上传中
  uploaded,     // 已上传
  failed,       // 上传失败
```

#### 2.3.2 状态 Provider

**文件**：`lib/services/backup/providers/asset_upload_status_provider.dart`

```dart
@riverpod
Future<AssetUploadStatusInfo> assetUploadStatus(
  AssetUploadStatusRef ref,
  BaseAsset asset, // family 参数通过函数参数传递
) async {
  // 1. 检查是否已上传（通过 remoteAssetId）
  if (asset.hasRemote) {
    return const AssetUploadStatusInfo(
      status: AssetUploadStatus.uploaded,
    );
  }
  
  // 2. 如果是 LocalAsset，查询上传任务状态
  if (asset is LocalAsset) {
    final task = await database.uploadTaskDao
        .getTaskByLocalAssetId(asset.localId);
    
    // 根据任务状态返回相应状态
    // ...
  }
  
  // 3. 默认状态：未上传
  return const AssetUploadStatusInfo(
    status: AssetUploadStatus.notUploaded,
  );
}
```

### 2.4 数据库查询

**文件**：`lib/data/database/daos/upload_task_dao.dart`

添加了 `getTaskByLocalAssetId` 方法：

```dart
/// 根据本地资产ID查询任务（获取最新的任务）
Future<UploadTaskEntityData?> getTaskByLocalAssetId(String localAssetId) {
  return (select(uploadTaskEntity)
        ..where((t) => t.assetId.equals(localAssetId))
        ..orderBy([(t) => OrderingTerm.desc(t.createdAt)])
        ..limit(1))
      .getSingleOrNull();
}
```

## 四、状态更新机制

### 4.1 当前实现

- **查询时机**：组件构建时通过 Provider 查询
- **更新机制**：Provider 自动缓存，依赖变化时自动刷新
- **数据源**：数据库查询（`upload_task_entity` 表）

### 4.2 未来优化（可选）

**实时状态更新**：

在 `UploadService` 或 `UploadOrchestrator` 中添加任务状态变化 Stream：

```dart
/// 任务状态变化流

class TaskStatusUpdate {
  final String taskId;

  final double? progress;

```

然后在 Provider 中监听 Stream：

```dart
@riverpod
Stream<AssetUploadStatusInfo> assetUploadStatusStream(
  AssetUploadStatusStreamRef ref,
  BaseAsset asset,
) async* {
  // 初始查询
  final status = await ref.watch(assetUploadStatusProvider(asset).future);
  yield status;
  
  // 监听任务状态变化
  if (asset is LocalAsset) {
    final stream = ref.watch(uploadTaskStatusStreamProvider(asset.localId));
```

## 五、性能考虑

### 5.1 当前实现

- **查询频率**：每个缩略图构建时查询一次
- **缓存机制**：Riverpod Provider 自动缓存
- **性能影响**：对于大量缩略图，可能产生多次数据库查询

### 5.2 优化建议

1. **批量查询**：
   - 一次查询多个资产的上传状态
   - 减少数据库查询次数

2. **延迟加载**：
   - 只在缩略图可见时查询状态
   - 使用 `VisibilityDetector` 检测可见性

3. **索引优化**：
   - 确保 `upload_task_entity.asset_id` 有索引（已存在：`idx_upload_task_asset_id`）

## 八、注意事项

### 8.1 数据一致性

- **问题**：`completed` 但 `remoteAssetId` 为空时，可能是数据不一致
- **处理**：显示为已上传状态，后续需要修复数据

### 8.2 状态同步

- **问题**：上传完成后需要立即更新状态
- **处理**：通过 `uploadCompleteStream` 通知 UI 刷新（已在 `main_timeline_page.dart` 中实现）

### 8.3 性能优化

- **问题**：大量缩略图时可能产生频繁查询
- **处理**：使用 Provider 缓存，未来可考虑批量查询和延迟加载
