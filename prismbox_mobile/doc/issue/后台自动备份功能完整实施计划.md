### 任务 3：Android 定期触发机制（P1）

#### 3.1 问题描述
Android 平台缺少 `PeriodicWorkRequest`，无法定期触发备份（如每 15-30 分钟）。

#### 3.2 实施步骤

**步骤 3.1：添加定期 Worker**
- **文件**：`android/app/src/main/kotlin/app/prismbox/background/BackgroundWorkerApiImpl.kt`
- **修改内容**：
  ```kotlin
  companion object {
    // ... 现有常量 ...
    private const val PERIODIC_WORKER_NAME = "prismbox/PeriodicBackupV1"
    
    /// 启用定期备份 Worker
    /// 每 15-30 分钟触发一次备份检查
    fun enqueuePeriodicWorker(ctx: Context) {
        val settings = BackgroundWorkerPreferences(ctx).getSettings()
        
        val constraints = Constraints.Builder().apply {
            setRequiresCharging(settings.requiresCharging)
            setRequiresBatteryNotLow(settings.requiresBatteryNotLow)
            
            if (settings.requiresNetworkType) {
                setRequiredNetworkType(androidx.work.NetworkType.UNMETERED) // WiFi
            } else {
                setRequiredNetworkType(androidx.work.NetworkType.CONNECTED)
            }
        }.build()
        
        // 使用 PeriodicWorkRequest，最小间隔 15 分钟
        val periodicWork = PeriodicWorkRequest.Builder(
            BackupWorker::class.java,
            15, // 间隔时间
            TimeUnit.MINUTES
        )
            .setConstraints(constraints)
            .setBackoffCriteria(
                BackoffPolicy.EXPONENTIAL,
                1,
                TimeUnit.MINUTES
            )
            .build()
        
        WorkManager.getInstance(ctx)
            .enqueueUniquePeriodicWork(
                PERIODIC_WORKER_NAME,
                ExistingPeriodicWorkPolicy.UPDATE, // 更新现有任务
                periodicWork
            )
        
        Log.i(TAG, "Enqueued periodic backup worker with interval: 15 minutes")
    }
    
    /// 取消定期备份 Worker
    fun cancelPeriodicWorker(ctx: Context) {
        WorkManager.getInstance(ctx)
            .cancelUniqueWork(PERIODIC_WORKER_NAME)
        Log.i(TAG, "Cancelled periodic backup worker")
    }
  }
  ```

### 任务 4：iOS 定期触发机制优化（P1）

#### 4.1 问题描述
iOS 虽然有 `scheduleRefreshWorker()` 和 `scheduleProcessingWorker()`，但只在 `enable()` 时调度一次，需要确保任务执行后自动重新调度。

#### 4.2 实施步骤

**步骤 4.1：检查 iOS 实现**
- **文件**：`ios/Runner/Background/BackgroundWorkerApiImpl.swift`
- **当前状态**：任务执行后已经重新调度（`handleBackgroundRefresh` 和 `handleBackgroundProcessing` 中都有 `scheduleRefreshWorker()` 和 `scheduleProcessingWorker()`）
- **需要确认**：确保重新调度逻辑正确执行

**步骤 4.2：优化调度策略**
- **文件**：`ios/Runner/Background/BackgroundWorkerApiImpl.swift`
- **修改内容**：
  ```swift
  private static func scheduleRefreshWorker() {
      let backgroundRefresh = BGAppRefreshTaskRequest(identifier: refreshTaskID)
      // 优化：根据上次执行时间动态调整间隔
      // 如果上次执行成功，可以设置更短的间隔（如 5 分钟）
      // 如果上次执行失败，可以设置更长的间隔（如 15 分钟）
      backgroundRefresh.earliestBeginDate = Date(timeIntervalSinceNow: 5 * 60) // 5 分钟后
      
      do {
          try BGTaskScheduler.shared.submit(backgroundRefresh)
          print("BackgroundWorkerApiImpl: Scheduled refresh worker")
      } catch {
          print("BackgroundWorkerApiImpl: Could not schedule the refresh upload task: \(error.localizedDescription)")
      }
  }
  
  private static func scheduleProcessingWorker() {
      let backgroundProcessing = BGProcessingTaskRequest(identifier: processingTaskID)
      backgroundProcessing.requiresNetworkConnectivity = true
      // 优化：处理任务可以设置更长的间隔（如 15-30 分钟）
      backgroundProcessing.earliestBeginDate = Date(timeIntervalSinceNow: 15 * 60) // 15 分钟后
      
      do {
          try BGTaskScheduler.shared.submit(backgroundProcessing)
          print("BackgroundWorkerApiImpl: Scheduled processing worker")
      } catch {
          print("BackgroundWorkerApiImpl: Could not schedule the processing upload task: \(error.localizedDescription)")
      }
  }
  ```

#### 4.3 注意事项
- iOS 的 `BGTaskScheduler` 是系统控制的，不能保证精确的时间间隔
- 系统会根据用户使用模式决定何时执行任务
- 需要确保任务执行后总是重新调度

#### 4.4 验收标准
- ✅ 任务执行后自动重新调度
- ✅ 刷新任务和处理任务都能正常调度
- ✅ 禁用时任务被正确取消

  /// 检查并触发自动备份
  Future<void> _checkAndTriggerAutoBackup(String userId) async {
    try {
      final storeService = ref.read(storeServiceProvider);
      
      // 检查全局自动备份开关
      final globalAutoBackup = storeService.get<bool>(
        StoreKey.autoBackup,
        false,
      );
      
      if (!globalAutoBackup) {
        _log.info('全局自动备份已禁用，跳过检查');
        return;
      }
      
      // 检查用户自动备份配置
      final backupService = await ref.read(backupServiceProvider.future);
      final backupStatus = await backupService.getBackupStatus(userId);
      
      if (backupStatus == null || !backupStatus.enabled) {
        _log.info('用户自动备份已禁用，跳过检查');
        return;
      }
      
      // 检查触发频率（避免频繁触发）
      final lastTriggerTime = storeService.get<DateTime?>(
        StoreKey.lastAutoBackupTriggerTime,
        null,
      );
      
      if (lastTriggerTime != null) {
        final timeSinceLastTrigger = DateTime.now().difference(lastTriggerTime);
        if (timeSinceLastTrigger.inMinutes < 5) {
          _log.info(
            '距离上次触发仅 ${timeSinceLastTrigger.inMinutes} 分钟，跳过触发',
          );
          return;
        }
      }
      
      // 检查网络条件
      final requireWifi = storeService.get<bool>(
        StoreKey.backupRequireWifi,
        true,
      );
      
      if (requireWifi) {
        // TODO: 检查当前网络类型
        // 如果要求 WiFi 但当前不是 WiFi，则跳过
        // 可以使用 connectivity_plus 包检查网络类型
      }
      
      // 触发自动备份
      _log.info('应用恢复时触发自动备份');
      await backupService.startAutoBackup(userId);
      
      // 更新最后触发时间
      await storeService.put(
        StoreKey.lastAutoBackupTriggerTime,
        DateTime.now(),
      );
    } catch (e, stackTrace) {
      _log.warning('应用恢复时自动备份检查失败', e, stackTrace);
    }
  }

### 4.3 性能测试
- [ ] 后台任务不影响应用性能

- [ ] 节流机制有效减少不必要的触发

## 五、风险评估

### 5.1 技术风险
- **Android PeriodicWorkRequest 限制**：最小间隔 15 分钟，可能不够灵活
  - **缓解措施**：使用 OneTimeWorkRequest + 链式调度实现更短间隔
- **iOS BGTaskScheduler 不确定性**：系统控制执行时间，不保证精确
  - **缓解措施**：结合应用恢复触发，确保及时备份

### 5.2 用户体验风险
- **电池消耗**：定期触发可能增加电池消耗
  - **缓解措施**：使用充电条件、WiFi 条件等约束
- **网络流量**：自动备份可能消耗大量流量
  - **缓解措施**：默认要求 WiFi，用户可配置
