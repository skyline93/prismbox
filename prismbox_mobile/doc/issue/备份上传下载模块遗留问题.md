## 概述

本文档详细记录了备份上传下载模块实现与设计文档之间的不一致之处，以及缺失的功能。当前实现已完成核心架构和主要功能（约80%完成度），但存在一些关键问题影响功能的完整性和可靠性。

## 问题分类

### 1. 关键问题 - 数据一致性问题（高优先级）

#### 1.1 上传成功后未立即更新 remote_asset_entity 表 ⚠️

**位置**: 
- `lib/services/backup/upload_task_manager.dart:_updateTaskStatus()` (119-159行)
- `lib/services/backup/upload_orchestrator.dart:_executeUpload()` (590-781行)

**问题描述**:
上传成功后，`UploadTaskManager` 只更新了任务状态为 `completed`，但**没有将上传成功的资产信息写入 `remote_asset_entity` 表**。远程资产信息只有在 `BackgroundSyncManager.syncRemote()` 从服务器同步后才会出现在 `remote_asset_entity` 表中。

**当前代码**:
```dart
// UploadTaskManager._updateTaskStatus()
case TaskStatus.complete:
  newStatus = UploadTaskStatus.completed;
  uploadedAt = DateTime.now();
  // ❌ 只更新任务状态，未写入 remote_asset_entity 表
  break;
```

**根本原因**:
1. `background_downloader` 的 `TaskStatusUpdate` 不包含服务器响应数据
2. 无法从状态回调中直接获取上传成功后的资产 ID 等信息
3. 需要从上传任务的表单字段中提取信息（checksum 可以从表单字段获取，但资产 ID 需要从服务器响应中获取）

**影响**:
1. **去重逻辑时效性问题**：
   - 上传完成后到下次 `syncRemote()` 之前，刚上传的资产不会出现在 `remote_asset_entity` 表中
   - 如果立即再次备份相同资产，会重复上传（去重失败）
   - 只有等待 `syncRemote()` 同步后，去重逻辑才能生效

2. **本地和远程资产关联延迟**：
   - `TimelineProviderService._getRemoteAssetId()` 通过 checksum 查询远程资产
   - 在上传完成后、`syncRemote()` 之前，无法通过 checksum 关联到远程资产
   - `LocalAsset.hasRemote` 判断不准确，影响资源选择策略

3. **备份统计不准确**：
   - `BackupService.getBackupCounts()` 使用 `remote_asset_entity` 统计已备份数量
   - 在上传完成后、`syncRemote()` 之前，统计结果不准确
   - UI 显示的备份进度滞后

**修复建议**:
1. **方案A（推荐）**：在上传任务完成时，解析服务器响应并写入 `remote_asset_entity`
   - 修改 `UploadOrchestrator._executeUpload()`，在上传成功后解析响应
   - 从响应中提取资产信息（id, checksum, 等）
   - 调用 `RemoteAssetDao.insertAsset()` 写入数据库
   - 需要处理 `background_downloader` 不直接提供响应数据的问题（可能需要自定义响应处理逻辑）

2. **方案B**：在上传编排完成时批量更新
   - 在 `UploadOrchestrator.orchestrateUpload()` 完成后
   - 调用 API 批量获取已上传资产信息
   - 批量写入 `remote_asset_entity` 表
   - 缺点：需要额外的 API 调用

3. **方案C**：使用 WebSocket 或推送通知
   - 服务器在上传成功后推送资产信息
   - 客户端接收后立即更新 `remote_asset_entity` 表
   - 需要服务器端支持

**实施步骤**:
1. 研究 `background_downloader` 如何获取上传响应数据
2. 如果无法直接获取，考虑使用自定义 HTTP 客户端或在响应处理中拦截
3. 实现资产信息解析和数据库写入逻辑
4. 添加错误处理和重试机制
5. 编写测试验证数据一致性

**相关代码**:
- `lib/services/backup/upload_task_manager.dart:119-159`
- `lib/services/backup/upload_orchestrator.dart:590-781`
- `lib/services/backup/background_sync_manager.dart:242-375` (syncRemote 实现)

## 已知限制和注意事项

1. **background_downloader 限制**：
   - `TaskStatusUpdate` 不包含服务器响应数据
   - 需要特殊方法获取上传响应（可能需要自定义处理）

2. **数据库迁移**：
   - 如果需要添加字段（如 `UploadTaskEntity.type`），需要数据库迁移
   - 需要处理已有数据

3. **向后兼容**：
   - 修复时需考虑已有用户的兼容性
   - 数据迁移需要平滑过渡

4. **性能影响**：
   - 哈希计算可能耗时较长，需要后台执行
   - 大量资产关联查询需要优化
