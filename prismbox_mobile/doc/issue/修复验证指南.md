## 概述

本文档说明如何验证三个遗留问题的修复是否生效。每个修复都添加了相应的日志输出，可以通过查看应用日志来确认。

## 验证方法

### 1. CustomImageCache 初始化验证

**修复内容**: 通过 `PrismBoxWidgetsBinding` 初始化 `CustomImageCache`

**验证日志**:
应用启动时，应该看到以下日志：
```
[INFO   ] XX:XX:XX [PrismBoxWidgetsBinding] ✅ CustomImageCache 已初始化（三级缓存分离：ThumbHash/小图/大图）
[INFO   ] XX:XX:XX [PrismBoxWidgetsBinding] ✅ CustomImageCache 实例已创建
```

**验证步骤**:
1. 启动应用
2. 查看控制台日志，确认上述日志出现
3. 如果看到这些日志，说明 CustomImageCache 已成功初始化

**额外验证**（可选）:
- 测试滚动性能，确认缩略图加载速度
- 监控内存使用，确认大图不会驱逐小图（需要性能监控工具）

### 2. 应用恢复时的同步检查验证

**修复内容**: 在 `TabShellPage` 中实现应用生命周期监听，应用恢复时自动检查数据新鲜度

**验证日志**:
当应用从后台恢复时，应该看到以下日志：
```
[INFO   ] XX:XX:XX [TabShellPage] ✅ 应用恢复，检查数据新鲜度
[INFO   ] XX:XX:XX [TabShellPage] ✅ 触发应用恢复时的同步检查
[INFO   ] XX:XX:XX [SyncCoordinator] 应用恢复，检查数据新鲜度
```

如果数据过期（超过1小时），还会看到：
```
[INFO   ] XX:XX:XX [LocalSyncService] 开始增量同步
```

**验证步骤**:
1. **方法A：快速验证**
   - 启动应用
   - 将应用切换到后台（按 Home 键或切换到其他应用）
   - 立即恢复应用（切换回应用）
   - 查看日志，应该看到"应用恢复，检查数据新鲜度"的日志
   - 如果数据新鲜（< 1小时），会看到"数据新鲜，跳过同步"
   - 如果数据过期（> 1小时），会触发增量同步

2. **方法B：完整验证**
   - 启动应用，等待同步完成
   - 将应用切换到后台
   - **等待超过1小时**（数据新鲜度阈值）
   - 恢复应用
   - 查看日志，应该看到：
     - "应用恢复，检查数据新鲜度"
     - "开始增量同步"（因为数据过期）

**注意事项**:
- 如果数据新鲜（< 1小时），不会触发同步，这是正常行为
- 日志中会显示"数据新鲜，跳过同步"

### 3. 数据源切换后的刷新验证

**修复内容**: 在 `MainTimelinePage` 中监听 `dataSourceSwitchStream`，同步完成后自动刷新时间线数据

**验证日志**:
首次启动应用并等待同步完成后，应该看到以下日志序列：
```
[INFO   ] XX:XX:XX [MainTimelinePage] ✅ 数据源切换监听已启动
[INFO   ] XX:XX:XX [SyncCoordinator] 同步成功: SyncResult(...)
[INFO   ] XX:XX:XX [SyncCoordinator] 检查数据源切换：数据库资产数量=XXX, 可用=true/false
[INFO   ] XX:XX:XX [SyncCoordinator] ✅ 数据库数据可用（资产数量=XXX），通知切换到数据库数据源
[INFO   ] XX:XX:XX [MainTimelinePage] ✅ 收到数据源切换通知，刷新时间线数据
```

**验证步骤**:
1. **首次启动验证**（数据库为空）:
   - 清空应用数据或首次安装
   - 启动应用
   - 查看日志，应该看到：
     - "数据源切换监听已启动"
     - 等待同步完成（约2秒后开始）
     - 同步完成后，如果数据库资产数量 > 100：
       - "数据库数据可用，通知切换到数据库数据源"
       - "收到数据源切换通知，刷新时间线数据"
     - 时间线数据会自动刷新，使用数据库数据源

2. **已有数据验证**:
   - 如果数据库已有数据（> 100条）
   - 启动应用时应该直接使用数据库数据源
   - 同步完成后，如果数据充足，会看到切换通知

**验证要点**:
- 首次启动时，初始数据来自 `photo_manager`（因为数据库为空）
- 同步完成后，如果数据库数据充足（> 100条），会自动切换到数据库
- 切换后，后续数据获取从数据库读取，性能更好

## 完整验证流程

### 场景1：首次启动完整流程

1. **清空应用数据**（模拟首次安装）
2. **启动应用**，观察日志：
   ```
   [INFO] CustomImageCache 已初始化 ✅
   [INFO] 数据源切换监听已启动 ✅
   [INFO] 启动本地媒体同步服务
   [INFO] 计划延迟自动同步（2秒后）
   ```
3. **等待2秒后**，观察同步日志：
   ```
   [INFO] 开始增量同步（或全量同步）
   [INFO] 同步成功: SyncResult(...)
   ```
4. **同步完成后**，观察数据源切换日志：
   ```
   [INFO] 检查数据源切换：数据库资产数量=XXX, 可用=true
   [INFO] ✅ 数据库数据可用，通知切换到数据库数据源
   [INFO] ✅ 收到数据源切换通知，刷新时间线数据
   ```

### 场景2：应用恢复验证

1. **启动应用**，等待同步完成
2. **切换到后台**（按 Home 键）
3. **等待超过1小时**（数据新鲜度阈值）
4. **恢复应用**，观察日志：
   ```
   [INFO] ✅ 应用恢复，检查数据新鲜度
   [INFO] ✅ 触发应用恢复时的同步检查
   [INFO] 应用恢复，检查数据新鲜度
   [INFO] 开始增量同步（如果数据过期）
   ```

### 场景3：快速验证（无需等待）

1. **启动应用**
2. **立即切换到后台**，然后**立即恢复**
3. **观察日志**：
   ```
   [INFO] ✅ 应用恢复，检查数据新鲜度
   [INFO] 数据新鲜，跳过同步（如果数据新鲜）
   ```

## 常见问题

### Q1: 为什么看不到 CustomImageCache 的日志？

**A**: 检查以下几点：
1. 确认 `PrismBoxWidgetsBinding()` 在 `main()` 中被调用
2. 确认日志级别设置为 `ALL` 或 `INFO`（调试模式默认是 `ALL`）
3. 如果使用 release 模式，日志级别可能被设置为 `INFO` 或更高

### Q2: 为什么应用恢复时没有触发同步？

**A**: 可能的原因：
1. **数据新鲜**：如果数据新鲜（< 1小时），不会触发同步，这是正常行为
   - 查看日志中是否有"数据新鲜，跳过同步"
2. **应用未真正进入后台**：确保应用真正切换到后台（按 Home 键）
3. **快速切换**：如果立即恢复，可能数据仍然新鲜

### Q3: 为什么看不到数据源切换的日志？

**A**: 可能的原因：
1. **数据库数据不足**：如果数据库资产数量 ≤ 100，不会切换
   - 查看日志中是否有"数据库数据不足，保持使用 photo_manager 数据源"
2. **同步未完成**：等待同步完成后再检查
3. **首次启动**：首次启动时数据库为空，需要等待同步完成

### Q4: 如何确认 CustomImageCache 真的在工作？

**A**: 除了日志，还可以：
1. **性能测试**：对比修复前后的滚动性能
2. **内存监控**：使用性能监控工具，确认大图不会驱逐小图
3. **缓存统计**：可以添加缓存统计日志（需要额外实现）
