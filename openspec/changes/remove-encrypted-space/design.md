# Design: Remove Encrypted Space Feature

## Context

加密空间功能是一个完整的子系统，涉及：
- 后端：密码管理、会话令牌、相册加密、资产访问控制
- 前端：加密空间页面、密码设置/验证对话框、文件迁移服务、重试队列
- 数据库：加密相册表、会话令牌表
- API：8 个专用端点

完全移除该功能需要系统性地清理所有相关代码、配置和数据库结构。

## Goals / Non-Goals

### Goals
- 完全移除加密空间功能的所有代码和配置
- 清理数据库中的相关表和字段
- 确保移除后系统可以正常编译和运行
- 保持其他功能（如 PIN 服务）不受影响

### Non-Goals
- 不迁移现有加密空间数据（直接删除）
- 不提供数据导出功能
- 不保留任何加密空间相关的代码作为"遗留代码"

## Decisions

### Decision 1: 数据库迁移策略
**选择**：创建一次性迁移脚本，删除 `album_sessions` 表和 `albums` 表中的加密相关字段。

**理由**：
- 加密空间功能将被完全移除，不需要保留数据
- 一次性迁移可以确保数据库结构干净
- 迁移脚本可以回滚（如果需要）

**替代方案**：
- 保留字段但标记为废弃：会增加数据库复杂度，不符合完全移除的目标

### Decision 2: PIN 服务保留
**选择**：保留 PIN 服务（`lib/services/pin/`），因为它已经解耦，可以用于其他场景。

**理由**：
- PIN 服务已经与加密空间解耦（见 `decouple-pin-service` 变更）
- PIN 服务是通用基础设施，可能用于其他功能
- 删除加密空间不应该影响 PIN 服务

**替代方案**：
- 同时删除 PIN 服务：但 PIN 服务是通用服务，不应该因为加密空间移除而删除

### Decision 3: 删除顺序
**选择**：先删除前端代码，再删除后端代码，最后执行数据库迁移。

**理由**：
- 前端代码删除后可以避免编译错误
- 后端代码删除后可以确保 API 端点不再可用
- 数据库迁移最后执行，确保代码清理完成后再清理数据

**替代方案**：
- 同时删除：但可能导致编译错误和依赖问题

### Decision 4: 测试代码处理
**选择**：删除所有加密空间相关的测试代码。

**理由**：
- 功能已移除，相关测试不再需要
- 保留测试代码会增加维护负担
- 测试代码可能引用已删除的代码，导致编译失败

## Risks / Trade-offs

### Risk 1: 数据丢失
**风险**：删除加密空间会导致用户已存储在加密空间中的照片和视频无法访问。

**缓解措施**：
- 在发布前通知用户（如果有用户使用该功能）
- 提供数据导出功能（如果需要，可以在移除前实现）

### Risk 2: 编译错误
**风险**：删除代码时可能遗漏某些引用，导致编译错误。

**缓解措施**：
- 使用 IDE 的"查找引用"功能全面搜索
- 删除后立即编译验证
- 使用静态分析工具检查未使用的代码

### Risk 3: 数据库迁移失败
**风险**：数据库迁移脚本可能在某些环境下失败。

**缓解措施**：
- 在测试环境充分测试迁移脚本
- 提供回滚脚本
- 迁移前备份数据库

### Risk 4: 遗漏清理
**风险**：可能遗漏某些配置文件、文档或注释中的引用。

**缓解措施**：
- 使用全文搜索（`grep`）查找所有相关引用
- 检查文档目录
- 检查配置文件

## Migration Plan

### Phase 1: 前端代码清理
1. 删除 `lib/services/encrypted_space/` 目录
2. 删除 `lib/presentation/pages/encrypted_space/` 目录
3. 删除 `lib/presentation/widgets/encrypted_space/` 目录
4. 从相关页面移除加密空间入口和功能
5. 删除设置项定义
6. 删除枚举值
7. 删除数据库方法
8. 删除路由定义
9. 编译验证

### Phase 2: 后端代码清理
1. 删除 `backend/internal/service/album_encryption/` 目录
2. 删除 `backend/internal/repository/album_session.go`
3. 删除 `backend/internal/api/middleware/album_session.go`
4. 从 `album.go` 模型删除加密相关字段
5. 删除 `AlbumSession` 模型
6. 从 handler 删除所有加密空间相关方法
7. 从 routes 删除所有加密空间相关路由
8. 从 repository 删除加密空间相关方法
9. 从 app builder 删除服务初始化
10. 从 migrate.go 删除模型迁移
11. 编译验证

### Phase 3: 数据库迁移
1. 创建迁移脚本删除 `album_sessions` 表
2. 创建迁移脚本删除 `albums` 表中的加密相关字段
3. 在测试环境测试迁移
4. 执行迁移
5. 验证数据库结构

### Phase 4: 最终验证
1. 编译前端和后端
2. 运行测试套件
3. 检查日志是否有相关错误
4. 验证 API 端点已删除
5. 验证 UI 中无加密空间入口
