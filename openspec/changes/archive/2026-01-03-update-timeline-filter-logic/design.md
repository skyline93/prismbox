# 照片页面过滤功能重构设计

## Context

当前照片页面的过滤功能基于资产类型（LocalAsset/RemoteAsset）进行简单过滤，无法准确反映本地资产的上传状态。用户需要更精确的过滤选项来区分：
- 已上传的本地资产
- 上传失败的本地资产
- 未上传的本地资产
- 仅存在于云端的远程资产

## Goals

1. 实现基于上传状态的精确过滤逻辑
2. 保持现有 UI 和交互方式不变
3. 优化查询性能，避免 N+1 查询问题

## Non-Goals

- 不改变过滤模式的 UI 展示
- 不修改数据模型或数据库结构
- 不改变其他页面的过滤逻辑

## Decisions

### 决策 1: 异步过滤函数

**选择**: 将 `_filterAssets` 改为异步函数，支持查询数据库获取上传任务状态

**理由**: 
- 需要查询上传任务表来判断上传失败状态
- 需要查询本地资产表的 `isUploaded` 字段来判断已上传状态
- 异步操作可以避免阻塞 UI 线程

**替代方案考虑**:
- 在数据获取阶段就包含上传状态信息：会增加数据获取的复杂度，且不是所有场景都需要过滤
- 使用同步查询：Drift 数据库查询是异步的，无法同步执行

### 决策 2: 上传状态判断逻辑

**选择**: 仅使用本地资产表的 `isUploaded` 字段判断上传状态，不查询上传任务表

**理由**:
- 本地资产表已有 `isUploaded` 字段，标识资产是否已成功上传
- 简化实现，避免复杂的多表查询
- 提升性能，减少数据库查询次数

**实现方式**:
- 在创建 `LocalAsset` 实体时，从数据库实体中读取 `isUploaded` 字段并存储
- 或者，在过滤时直接从数据库实体中读取 `isUploaded` 字段
- 已上传：`isUploaded == true`
- 未上传或上传失败：`isUploaded == false`（不区分是未上传还是上传失败）

**替代方案考虑**:
- 查询上传任务表：可以区分"未上传"和"上传失败"，但增加复杂度，且用户明确表示不需要
- 使用 `remoteAssetId`：但本地和远程资产已解耦，不再关联

## Risks / Trade-offs

### 风险 1: 无法区分"未上传"和"上传失败"

**风险**: 仅使用 `isUploaded` 字段无法区分"从未上传"和"上传失败"两种情况

**缓解措施**:
- 根据用户需求，"未备份"模式包含"未上传或上传失败的本地媒体资源"，不区分这两种情况
- 如果未来需要区分，可以考虑添加额外的字段或查询逻辑

### 风险 2: LocalAsset 实体不包含 isUploaded 字段

**风险**: 当前 `LocalAsset` 实体定义中不包含 `isUploaded` 字段，需要修改实体定义或查询逻辑

**缓解措施**:
- 方案 1：在 `LocalAsset` 实体中添加 `isUploaded` 字段，在创建时从数据库实体中读取
- 方案 2：在过滤时，直接从数据库实体（`LocalAssetEntityData`）中读取 `isUploaded` 字段
- 推荐方案 1，保持实体完整性

### 风险 3: 代码复杂度增加

**风险**: 需要修改 `LocalAsset` 实体定义和创建逻辑

**缓解措施**:
- 将状态判断逻辑提取为独立的辅助函数
- 添加清晰的代码注释
- 保持函数职责单一

## Migration Plan

1. **阶段 1**: 实现新的过滤逻辑，保持向后兼容（如果可能）
2. **阶段 2**: 测试验证各种过滤模式的行为
3. **阶段 3**: 部署并监控性能指标

**回滚方案**: 如果出现问题，可以快速回滚到基于资产类型的简单过滤逻辑
