# 设计文档：收藏属性同步和展示

## Context

PrismBox 移动端使用 `photo_manager` 库访问系统相册，但该库不直接提供资产的收藏（favorite）属性。为了获取此属性，需要直接与原生平台交互。参考 Immich 的实现，我们需要：

1. 在 iOS 平台通过 `PHAsset.isFavorite` 属性获取收藏状态
2. 在 Android 平台通过 `MediaStore.MediaColumns.IS_FAVORITE` 字段获取收藏状态
3. 在本地同步流程中读取并存储此属性到本地数据库
4. 在时间线 UI 中展示收藏状态

**约束**：
- Android 的 `IS_FAVORITE` 字段仅在 Android 11 (API 30) 及以上可用
- 需要保持与现有本地同步流程的一致性
- 需要考虑性能影响（避免单个资产逐个查询）

## Goals / Non-Goals

**Goals**：
- 在本地同步时自动获取系统相册的收藏状态
- 将收藏状态存储到本地数据库的 `isFavorite` 字段
- 在时间线缩略图上清晰展示收藏图标
- 支持增量同步时检测收藏状态变化
- 提供良好的跨平台兼容性

**Non-Goals**：
- 不实现从 PrismBox 修改系统相册的收藏状态（单向同步）
- 不实现收藏夹专用视图（可在后续需求中添加）
- 不对现有已同步资产进行收藏状态回填（仅影响新同步的资产）

## Decisions

### 1. 使用 Pigeon 进行跨平台通信

**决策**：使用 Pigeon 框架定义类型安全的跨平台接口，而不是直接使用 MethodChannel。

**理由**：
- **类型安全**：Pigeon 自动生成类型安全的代码，避免手动序列化/反序列化错误
- **代码生成**：自动生成 Dart、Swift、Kotlin 代码，减少样板代码
- **与项目技术栈一致**：PrismBox 项目已使用 Pigeon（见 `project.md`）
- **参考 Immich**：Immich 也使用 Pigeon 实现类似功能

**替代方案**：
- **MethodChannel**：需要手动处理序列化，容易出错，代码量更大
- **Platform Channels Plugin**：过于重量级，不适合简单的数据查询

### 2. 在 `LocalSyncService._convertToEntity` 中获取收藏状态

**决策**：在本地同步服务的资产转换方法中调用原生 API 获取收藏状态。

**理由**：
- **逻辑集中**：所有从系统相册读取的属性在一个地方处理
- **数据一致性**：首次同步时就能正确记录收藏状态
- **增量同步友好**：可以检测收藏状态的变化并更新数据库
- **与 Immich 设计一致**：Immich 也在同步流程中获取收藏状态

**替代方案**：
- **在上传流程中获取**：本地数据库中的收藏状态会一直是错误的，无法支持收藏夹视图
- **独立的收藏同步服务**：需要额外的扫描过程，性能开销更大

### 3. 提供批量获取 API

**决策**：除了单个资产查询 API，还提供批量获取多个资产元数据的 API。

**理由**：
- **性能优化**：减少跨平台调用次数（每批 100 个资产只需 1 次调用）
- **减少开销**：批量查询可以在原生层优化数据库查询
- **可选实现**：先实现单个查询，后续优化时可切换到批量查询

**实现策略**：
- 第一阶段：实现单个资产查询 API（`getIsFavorite`）
- 第二阶段（优化）：实现批量查询 API（`getAssetMetadata`）

### 4. Android 兼容性处理

**决策**：Android 10 及以下版本无法获取收藏状态时，默认返回 `false`。

**理由**：
- **降级策略**：不影响核心功能，仅收藏状态不准确
- **用户体验**：避免崩溃或错误提示，静默处理
- **版本占比**：Android 11+ 已覆盖大部分用户

**实现**：
```kotlin
if (Build.VERSION.SDK_INT < Build.VERSION_CODES.R) {
    return false  // Android 10- 不支持
}
```

### 5. UI 展示位置

**决策**：在缩略图左下角显示半透明的心形图标。

**理由**：
- **不遮挡主体**：左下角通常是照片的空白区域
- **视觉习惯**：符合大多数相册应用的设计惯例
- **易于识别**：心形图标是收藏的通用符号

**设计细节**：
- 图标大小：16-20px
- 背景：半透明黑色圆形背景（opacity 0.5）
- 颜色：白色或红色心形图标
- 位置：距离左边和底边各 4-8px

## Risks / Trade-offs

### 风险 1：性能影响

**风险**：在同步时逐个调用原生 API 获取收藏状态可能降低同步速度。

**缓解措施**：
- 实现批量查询 API（`getAssetMetadata`），每批 100 个资产只需 1 次跨平台调用
- 在增量同步时只查询新增/修改的资产
- 添加性能监控和日志，量化影响

### 风险 2：Android 兼容性

**风险**：Android 10 及以下用户无法获取收藏状态。

**缓解措施**：
- 默认返回 `false`，不影响核心功能
- 在日志中记录版本信息，便于跟踪
- 可在设置中提示用户升级系统（可选）

### 风险 3：原生代码维护

**风险**：增加原生代码（iOS Swift、Android Kotlin）增加维护成本。

**缓解措施**：
- 使用 Pigeon 自动生成大部分代码，减少手动维护
- 原生实现逻辑简单，主要是数据查询
- 添加完善的错误处理和日志

### Trade-off：单向同步

**Trade-off**：只支持从系统相册读取收藏状态，不支持从 PrismBox 修改系统相册的收藏状态。

**理由**：
- **简化实现**：避免复杂的双向同步逻辑
- **权限问题**：修改系统相册可能需要额外权限
- **与 Immich 一致**：Immich 也是单向同步
- **未来扩展**：如有需求，可在后续迭代中添加

## Migration Plan

### 阶段 1：原生桥接实现（2-3 天）

1. 定义 Pigeon 接口
2. 实现 iOS 原生层（Swift）
3. 实现 Android 原生层（Kotlin）
4. 测试跨平台调用

### 阶段 2：本地同步集成（1-2 天）

1. 修改 `LocalSyncService._convertToEntity` 方法
2. 注入 `AssetNativeApi` 依赖
3. 添加错误处理和日志
4. 测试全量同步和增量同步

### 阶段 3：UI 展示实现（1 天）

1. 创建 `FavoriteIndicator` 组件
2. 集成到时间线缩略图
3. 测试 UI 展示效果

### 阶段 4：性能优化（可选，1-2 天）

1. 实现批量查询 API
2. 更新 `LocalSyncService` 使用批量查询
3. 性能测试和对比

### 回滚计划

如果遇到严重问题：
1. 回滚 `LocalSyncService` 修改，恢复 `isFavorite = false` 的硬编码
2. 隐藏 UI 收藏图标
3. 保留原生代码（不影响其他功能）
