## 规范概述

### 设计目标

本文档规范 PrismBox 移动端应用中媒体资源文件路径的获取和使用，确保：

1. **路径稳定性**：使用永久路径，避免因临时文件清理导致路径失效
2. **数据一致性**：统一使用原始文件路径，保证数据质量
3. **功能可靠性**：所有文件操作基于可靠的路径，避免文件不存在错误
4. **代码一致性**：统一路径获取方式，便于维护和理解

### 适用范围

本规范适用于所有需要获取或使用媒体资源文件路径的场景，包括但不限于：

- 本地媒体同步模块（路径存储到数据库）
- 备份上传下载模块（上传文件路径）
- 媒体资源展示模块（读取文件内容）
- 文件处理和计算（计算 checksum、读取元数据等）

## 路径获取 API 说明

### photo_manager API 差异

photo_manager 提供了两个获取文件路径的 API，**必须明确区分使用场景**：

#### 1. `asset.originFile`（推荐，默认使用）

**定义**: 获取原始文件的永久路径

**特点**:
- ✅ 返回原始文件在设备上的永久路径
- ✅ 路径稳定，不会被系统清理
- ✅ 文件内容未经任何处理
- ✅ 适用于所有需要可靠路径的场景

**使用场景**:
- 存储到数据库
- 上传文件
- 计算文件 checksum
- 读取文件内容
- 获取文件元数据

**代码示例**:
```dart
final file = await asset.originFile;
if (file != null) {
  final path = file.path;  // 原始文件路径
  // 使用路径进行文件操作
}
```

#### 2. `asset.file`（特殊场景使用）

**定义**: 获取可能经过处理的文件（如应用 EXIF 旋转）

**特点**:
- ⚠️ 可能返回处理后的临时文件
- ⚠️ 路径可能包含特殊后缀（如 `_exif.jpg`）
- ⚠️ 临时文件可能被系统清理
- ⚠️ 路径不稳定，不适合长期存储

**使用场景**:
- **仅在确实需要处理后的文件时使用**（目前项目中无此需求）
- 例如：需要显示已应用 EXIF 旋转的图片（但通常由图片解码库处理）

**代码示例**:
```dart
// ⚠️ 注意：只有在确实需要处理后的文件时才使用
final file = await asset.file;  // 可能返回临时文件
// 使用后应立即释放，不要存储路径
```

## 路径使用规范

### 基本原则

1. **默认使用 `originFile`**：除非有特殊需求，否则统一使用 `asset.originFile`
2. **不要存储 `file` 的路径**：`asset.file` 返回的路径不应存储到数据库
3. **路径验证**：使用路径前应验证文件是否存在
4. **错误处理**：路径失效时应使用 `originFile` 重新获取

### 路径存储规范

#### 数据库存储

**规范**: 所有存储到数据库的文件路径必须使用 `originFile` 获取

**原因**:
- 数据库中的路径需要长期有效
- 临时文件路径会被系统清理，导致路径失效
- 原始文件路径稳定可靠

**示例代码**:
```dart
// ✅ 正确：使用 originFile 获取原始路径
final file = await asset.originFile;
final path = file?.path ?? '';
if (path.isNotEmpty) {
  // 存储到数据库
  entity.path = path;
}

// ❌ 错误：使用 file 获取临时路径
final file = await asset.file;  // 可能返回临时文件路径
entity.path = file?.path ?? '';  // 路径可能很快失效
```

#### 内存变量存储

**规范**: 临时使用的路径可以使用 `originFile` 或 `file`，但需要注意生命周期

**建议**:
- 优先使用 `originFile`，除非确实需要处理后的文件
- 不要将 `file` 返回的路径传递给其他方法或存储

### 场景 3: 计算文件 checksum

**场景**: 计算文件的 SHA256 哈希值用于去重

**规范**: 必须使用 `asset.originFile`

**代码示例**:
```dart
Future<String> calculateChecksum(String assetId) async {
  final assetEntity = await pm.AssetEntity.fromId(assetId);
  final file = await assetEntity?.originFile;  // 使用原始文件
  if (file == null) {
    throw FileSystemException('File not found', assetId);
  }
  
  final bytes = await file.readAsBytes();
  final hash = sha256.convert(bytes);
  return hash.toString();
}
```

**原因**: 需要计算原始文件的哈希值，确保一致性

### 场景 5: 路径失效修复

**场景**: 数据库中的路径失效，需要重新获取

**规范**: 使用 `asset.originFile` 重新获取，并更新数据库

**代码示例**:
```dart
// 检查文件是否存在
File file = File(task.localPath);
if (!await file.exists()) {
  // 路径失效，使用 originFile 重新获取
  final assetEntity = await pm.AssetEntity.fromId(task.assetId);
  final fileFromAsset = await assetEntity?.originFile;  // ✅ 使用 originFile
  
  if (fileFromAsset != null && await fileFromAsset.exists()) {
    final newPath = fileFromAsset.path;
    
    // 更新数据库中的路径
    await dao.updateTaskLocalPath(task.id, newPath);
    
    // 使用新路径
    file = fileFromAsset;
  }
}
```

**位置**: `lib/services/backup/backup_service.dart`, `lib/services/backup/upload_orchestrator.dart`

## 代码实现规范

### 统一路径获取方法

建议创建一个统一的路径获取辅助方法：

```dart
/// 获取资产的原始文件路径
/// 
/// [asset] photo_manager 的 AssetEntity
/// 
/// 返回原始文件的路径，如果获取失败返回 null
Future<String?> getAssetOriginPath(pm.AssetEntity asset) async {
  try {
    final file = await asset.originFile;
    if (file != null && await file.exists()) {
      return file.path;
    }
  } catch (e) {
    // 记录错误但不抛出异常
    Logger('AssetPathHelper').warning('Failed to get origin path: $e');
  }
  return null;
}

/// 通过资产 ID 获取原始文件路径
/// 
/// [assetId] 资产 ID
/// 
/// 返回原始文件的路径，如果获取失败返回 null
Future<String?> getAssetOriginPathById(String assetId) async {
  try {
    final asset = await pm.AssetEntity.fromId(assetId);
    if (asset != null) {
      return await getAssetOriginPath(asset);
    }
  } catch (e) {
    Logger('AssetPathHelper').warning('Failed to get asset by ID: $assetId', e);
  }
  return null;
}
```

### 代码注释规范

在使用路径获取 API 时，应添加清晰的注释：

```dart
// ✅ 好的注释
// 使用 originFile 获取原始文件路径
// 注意：originFile 返回原始文件的永久路径，不会被系统清理
// file 可能返回处理后的临时文件（如应用 EXIF 旋转），路径可能包含 _exif.jpg 后缀
final file = await asset.originFile;

// ❌ 不好的注释（缺少说明）
final file = await asset.originFile;  // 获取文件

// ⚠️ 特殊场景注释
// 注意：这里使用 file 而不是 originFile，因为需要获取已应用 EXIF 旋转的图片
// 这是一个特殊场景，通常应该使用 originFile
final file = await asset.file;
```

## 错误处理规范

### 路径获取失败处理

**规范**: 路径获取失败时，应记录错误但不中断流程（如果可能）

**代码示例**:
```dart
Future<String?> getAssetPath(pm.AssetEntity asset) async {
  try {
    final file = await asset.originFile;
    if (file != null && await file.exists()) {
      return file.path;
    }
  } catch (e, stackTrace) {
    _logger.warning(
      'Failed to get origin file path for asset: ${asset.id}',
      e,
      stackTrace,
    );
  }
  return null;
}
```

### 路径验证

**规范**: 使用路径前应验证文件是否存在

**代码示例**:
```dart
final path = asset.path;  // 从数据库获取的路径
final file = File(path);

if (!await file.exists()) {
  // 路径失效，尝试重新获取
  final assetEntity = await pm.AssetEntity.fromId(asset.id);
  final originFile = await assetEntity?.originFile;
  
  if (originFile != null && await originFile.exists()) {
    // 使用新路径并更新数据库
    final newPath = originFile.path;
    await updateAssetPath(asset.id, newPath);
    return originFile;
  } else {
    throw FileSystemException('File not found', asset.id);
  }
}

return file;
```

## 最佳实践

### 1. 路径获取优先级

1. **优先使用数据库路径**：如果数据库中有路径，先尝试使用
2. **路径失效时使用 originFile**：如果路径失效，使用 `originFile` 重新获取
3. **更新数据库路径**：获取到新路径后，更新数据库

### 2. 路径缓存策略

- **不缓存临时文件路径**：不要缓存 `asset.file` 返回的路径
- **可以缓存原始路径**：原始路径稳定，可以安全缓存
- **及时更新失效路径**：发现路径失效时，及时更新数据库

### 3. 错误恢复机制

- **自动修复**：路径失效时自动使用 `originFile` 重新获取
- **更新数据库**：修复后更新数据库中的路径
- **记录日志**：记录路径失效和修复的日志，便于问题追踪

## 常见问题

### Q1: 什么时候使用 `asset.file`？

**A**: 仅在确实需要处理后的文件时使用（如需要显示已应用 EXIF 旋转的图片）。目前项目中**没有这样的需求**，应统一使用 `asset.originFile`。

### Q2: `asset.file` 和 `asset.originFile` 的性能差异？

**A**: 
- `originFile` 直接返回原始文件路径，性能更好
- `file` 可能需要处理文件（如应用旋转），性能可能较差
- 推荐使用 `originFile` 以获得更好的性能

### Q3: 如何处理已存在的错误路径？

**A**: 
1. **自动修复**（推荐）：在路径失效时自动使用 `originFile` 重新获取并更新
2. **批量修复**：编写脚本批量修复数据库中的错误路径（可选）

### Q4: 路径格式有什么要求？

**A**:
- 路径应该是绝对路径
- 不应包含 `_exif`、`_processed` 等临时文件标识
- 路径应该指向实际存在的文件

### Q5: iOS 和 Android 平台是否有差异？

**A**:
- `originFile` 在 iOS 和 Android 上都返回原始文件路径，行为一致
- `file` 在不同平台上的行为可能略有差异，但都不推荐用于存储路径
- 建议统一使用 `originFile` 以确保跨平台一致性

### Q6: 路径失效后如何自动修复？

**A**:
- 在文件操作前检查文件是否存在
- 如果不存在，使用 `AssetEntity.fromId()` 获取 AssetEntity，然后使用 `originFile` 重新获取路径
- 获取到新路径后，更新数据库中的路径记录
- 详细实现见"路径失效修复"场景示例

## 数据迁移指南

### 现有错误路径修复策略

如果数据库中已存在错误路径（包含 `_exif.jpg` 后缀或其他临时文件标识），可以采用以下策略：

#### 方案 A：自动修复（推荐）

**策略**：在文件操作时自动检测和修复错误路径

**实现位置**：
- `lib/services/backup/backup_service.dart` - 创建上传任务时
- `lib/services/backup/upload_orchestrator.dart` - 执行上传时

**优点**：
- 无需额外操作，自动修复
- 修复是渐进式的，不影响现有功能
- 只修复实际使用的路径，效率高

**缺点**：
- 修复需要时间，不是立即完成
- 可能仍有部分未使用的路径保持错误状态

#### 方案 B：批量修复脚本（可选）

**策略**：编写脚本批量扫描和修复所有错误路径

**实现示例**：
```dart
/// 批量修复数据库中的错误路径
Future<void> fixInvalidPaths() async {
  final dao = LocalAssetDao(_database);
  final assets = await dao.getAllAssets();
  
  int fixed = 0;
  for (final asset in assets) {
    // 检测错误路径（包含 _exif 等临时文件标识）
    if (asset.path.contains('_exif') || 
        asset.path.contains('/app_flutter/')) {
      try {
        final assetEntity = await pm.AssetEntity.fromId(asset.id);
        if (assetEntity != null) {
          final file = await assetEntity.originFile;
          if (file != null && await file.exists()) {
            final updatedAsset = asset.copyWith(path: Value(file.path));
            await dao.updateAsset(updatedAsset);
            fixed++;
          }
        }
      } catch (e) {
        _logger.warning('Failed to fix path for ${asset.id}: $e');
      }
    }
  }
  
  _logger.info('Fixed $fixed invalid paths');
}
```

**优点**：
- 一次性修复所有错误路径
- 立即完成数据修复

**缺点**：
- 需要额外的开发工作
- 可能需要长时间运行（大量数据时）
- 修复过程中可能影响数据库性能

#### 推荐方案

**推荐使用方案 A（自动修复）**，因为：
1. 修复逻辑已经在上传流程中实现
2. 不会影响现有功能
3. 只修复实际使用的路径，效率更高
4. 修复是渐进式的，不会造成性能冲击

2. **可靠性**：使用永久路径，避免路径失效
3. **可维护性**：统一规范，便于理解和维护
4. **性能优化**：优先使用 `originFile`，性能更好

## 总结

媒体资源路径规范的核心原则是：**统一使用 `asset.originFile` 获取原始文件的永久路径**。

### 关键要点

1. ✅ **默认使用 `originFile`**：除非有特殊需求，否则统一使用 `asset.originFile`
2. ✅ **不要存储临时路径**：`asset.file` 返回的路径不应存储到数据库
3. ✅ **路径验证和修复**：使用路径前验证文件存在，失效时自动修复
4. ✅ **代码注释**：添加清晰的注释说明路径获取方式
5. ✅ **错误处理**：完善的错误处理和日志记录
