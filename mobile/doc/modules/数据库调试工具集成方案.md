## 方案概述

### 背景与目标

在移动端应用开发过程中，调试本地数据库是一个常见需求。PrismBox 使用 Drift (SQLite) 作为数据持久化层，需要提供便捷的数据库查看和调试工具，以提升开发效率。

**核心目标**：

1. **可视化查看**：在开发环境中可视化查看数据库表结构和数据
2. **实时调试**：运行时查看数据变化，无需导出数据库文件
3. **零侵入**：仅在调试模式下启用，不影响生产代码和性能
4. **易于使用**：集成简单，使用方便，无需额外配置

### 方案特点

- ✅ **仅调试模式启用**：通过 `kDebugMode` 控制，发布版本不包含相关代码
- ✅ **IDE 集成**：支持 Android Studio / IntelliJ IDEA 插件直接查看
- ✅ **类型安全**：配合 Drift 的类型系统，提供类型安全的调试体验
- ✅ **实时同步**：运行时查看数据变化，无需重启应用

## 技术选型

### 核心工具

#### 1. Storage Inspector

**简介**：Storage Inspector 是一个允许开发者在运行时检查应用程序本地存储的库，支持查看和修改应用的本地文件、数据库等。

**特点**：
- 支持多种存储后端（Drift、SharedPreferences、Hive 等）
- 提供 HTTP 服务器接口，供 IDE 插件连接
- 自动端口选择，避免端口冲突
- 轻量级，性能影响小

**官方文档**：https://pub.dev/packages/storage_inspector

#### 2. Drift Local Storage Inspector

**简介**：Storage Inspector 的 Drift 数据库插件，专门用于调试 Drift 数据库。

**特点**：
- 与 Drift 深度集成
- 支持查看所有表和数据
- 支持执行 SQL 查询
- 实时数据更新

**官方文档**：https://pub.dev/packages/drift_local_storage_inspector

### 核心组件

#### 1. StorageInspectorService

**职责**：
- 管理 Storage Inspector 的生命周期
- 仅在调试模式下启用
- 处理初始化错误，不影响应用运行

**关键方法**：
- `initialize(AppDatabase database)`: 初始化服务
- `shutdown()`: 关闭服务
- `isInitialized`: 检查初始化状态

#### 2. StorageServerDriver

**职责**：
- 创建 HTTP 服务器
- 管理端口分配
- 处理 IDE 连接请求

#### 3. DriftServer

**职责**：
- 将 Drift 数据库暴露给 Storage Inspector
- 提供表结构和数据查询接口
- 处理 SQL 查询请求

## 实施步骤

### 步骤 1: 添加依赖

在 `pubspec.yaml` 的 `dependencies` 部分添加以下依赖：

```yaml
dependencies:
  # ... 现有依赖 ...
  
  # 数据库调试工具（仅在调试模式下使用）
  storage_inspector: ^1.0.0
  drift_local_storage_inspector: ^1.0.0
```

**注意**：这些依赖仅在调试模式下使用，不会影响生产版本的包大小和性能。

### 步骤 2: 创建 Storage Inspector 服务

创建文件 `lib/services/debug/storage_inspector_service.dart`：

```dart
// lib/services/debug/storage_inspector_service.dart

import 'package:flutter/foundation.dart';
import 'package:storage_inspector/storage_inspector.dart';
import 'package:drift_local_storage_inspector/drift_local_storage_inspector.dart';
import 'package:prismbox/data/database/app_database.dart';

/// Storage Inspector 服务
/// 仅在调试模式下启用，用于可视化查看和调试本地数据库
class StorageInspectorService {
  static StorageServerDriver? _driver;
  static bool _isInitialized = false;

  /// 初始化 Storage Inspector
  /// 仅在调试模式下启用
  static Future<void> initialize(AppDatabase database) async {
    if (!kDebugMode) {
      // 非调试模式下不启用
      return;
    }

    if (_isInitialized) {
      // 已经初始化，避免重复初始化
      return;
    }

    try {
      // 创建 Storage Server Driver
      _driver = StorageServerDriver(
        bundleId: 'com.u163.glf9832.prismbox', // 应用 ID
        port: 0, // 0 表示自动选择空闲端口
      );

      // 添加 Drift 数据库服务器
      final driftServer = DriftServer(
        database,
        'PrismBox Database', // 显示名称
      );
      _driver!.addDatabaseServer(driftServer);

      // 启动服务器
      await _driver!.start();

      _isInitialized = true;

      if (kDebugMode) {
        debugPrint('✅ Storage Inspector 已启动');
        debugPrint('📊 数据库调试工具已就绪，可在 IDE 中查看数据库');
      }
    } catch (e, stackTrace) {
      if (kDebugMode) {
        debugPrint('❌ Storage Inspector 启动失败: $e');
        debugPrint('堆栈跟踪: $stackTrace');
      }
      // 启动失败不影响应用运行
    }
  }

  /// 关闭 Storage Inspector
  static Future<void> shutdown() async {
    if (!kDebugMode || _driver == null) {
      return;
    }

    try {
      await _driver!.stop();
      _driver = null;
      _isInitialized = false;

      if (kDebugMode) {
        debugPrint('Storage Inspector 已关闭');
      }
    } catch (e) {
      if (kDebugMode) {
        debugPrint('关闭 Storage Inspector 时出错: $e');
      }
    }
  }

  /// 检查是否已初始化
  static bool get isInitialized => _isInitialized;
}
```

### 步骤 3: 在 main.dart 中集成

修改 `lib/main.dart`，在数据库初始化后启动 Storage Inspector：

```dart
// lib/main.dart

import 'dart:async';
import 'package:flutter/material.dart';
import 'package:flutter/foundation.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'package:logging/logging.dart';
import 'package:prismbox/infrastructure/api/ssl/http_ssl_options.dart';
import 'package:prismbox/presentation/routing/app_router.dart';
import 'package:prismbox/data/database/connection.dart';
import 'package:prismbox/services/debug/storage_inspector_service.dart';

void main() async {
  // 确保 Flutter 绑定已初始化
  WidgetsFlutterBinding.ensureInitialized();
  
  // 应用 SSL 配置（必须在应用启动时调用）
  unawaited(HttpSSLOptions.apply());
  
  // 配置日志系统
  _setupLogging();

  // 初始化数据库
  await DatabaseConnection.initializeDatabaseIsolate();
  
  // 在调试模式下启动 Storage Inspector
  if (kDebugMode) {
    final database = await DatabaseConnection.getInstance();
    unawaited(StorageInspectorService.initialize(database));
  }

  runApp(
    const ProviderScope(
      child: MyApp(),
    ),
  );
}

// ... 其余代码保持不变 ...
```

### 步骤 4: 安装 IDE 插件

#### Android Studio / IntelliJ IDEA

1. 打开 IDE，进入 `Settings` (Windows/Linux) 或 `Preferences` (macOS)
2. 选择 `Plugins`
3. 搜索 "Local Storage Inspector"
4. 点击 `Install` 安装插件
5. 重启 IDE

#### VS Code

VS Code 目前不直接支持 Storage Inspector，但可以通过以下方式查看数据库：

1. 使用 Android Studio / IntelliJ IDEA 的插件
2. 通过命令行工具查看数据库文件（见下方说明）

### 步骤 5: 运行应用并连接

1. 在调试模式下运行应用
2. 在 IDE 中打开 `View` → `Tool Windows` → `Local Storage Inspector`
3. 选择运行中的应用实例
4. 查看数据库表和数据

## 使用指南

### 基本使用

#### 1. 启动调试模式

确保应用在调试模式下运行：

```bash
flutter run
# 或
flutter run --debug
```

#### 2. 打开 Storage Inspector

在 Android Studio / IntelliJ IDEA 中：

1. 运行应用后，在 IDE 底部工具栏找到 `Local Storage Inspector` 标签
2. 如果没有显示，通过 `View` → `Tool Windows` → `Local Storage Inspector` 打开
3. 在设备列表中选择运行中的应用实例

#### 3. 查看数据库

- **查看所有表**：在左侧面板中展开数据库，查看所有表
- **查看表数据**：点击表名，在右侧面板查看数据
- **执行 SQL 查询**：在查询面板中输入 SQL 语句并执行
- **刷新数据**：点击刷新按钮更新数据

### 高级功能

#### 1. 实时数据监控

Storage Inspector 支持实时查看数据变化：

- 当应用中的数据发生变化时，可以在 IDE 中看到更新
- 支持手动刷新以获取最新数据

#### 2. SQL 查询

在查询面板中可以执行自定义 SQL 查询：

```sql
-- 查看所有本地资产
SELECT * FROM local_asset_entity LIMIT 10;

-- 查看远程资产统计
SELECT COUNT(*) as total, 
       COUNT(DISTINCT owner_id) as owners
FROM remote_asset_entity;

-- 查看相册关联
SELECT a.name, COUNT(aa.asset_id) as asset_count
FROM remote_album_entity a
LEFT JOIN album_asset_entity aa ON a.id = aa.album_id
GROUP BY a.id, a.name;
```

#### 3. 数据导出

部分 IDE 插件支持导出数据为 CSV 或 JSON 格式，方便进一步分析。

### 替代方案：命令行查看

如果 IDE 插件不可用，可以通过命令行查看数据库文件：

#### Android 设备

```bash
# 1. 连接设备
adb devices

# 2. 进入应用数据目录
adb shell run-as com.u163.glf9832.prismbox
cd /data/data/com.u163.glf9832.prismbox/app_flutter

# 3. 查看数据库文件
ls -la *.db

# 4. 导出数据库文件到本地
adb pull /data/data/com.u163.glf9832.prismbox/app_flutter/prismbox.db ./

# 5. 使用 SQLite 工具查看
sqlite3 prismbox.db
```

#### iOS 设备

```bash
# 1. 通过 Xcode 下载应用数据
# Xcode → Window → Devices and Simulators
# 选择设备 → 选择应用 → Download Container

# 2. 解压下载的 .xcappdata 文件
# 3. 在 AppData/Documents/ 目录下找到 prismbox.db
# 4. 使用 SQLite 工具查看
sqlite3 prismbox.db
```

#### 使用 SQLite 命令行工具

```bash
# 查看所有表
.tables

# 查看表结构
.schema local_asset_entity

# 查询数据
SELECT * FROM local_asset_entity LIMIT 10;

# 退出
.quit
```

## 注意事项

### 1. 仅调试模式启用

Storage Inspector 仅在 `kDebugMode` 为 `true` 时启用，确保：

- ✅ 发布版本不包含调试代码
- ✅ 不影响生产环境性能
- ✅ 不暴露敏感数据

### 2. 性能影响

虽然 Storage Inspector 设计为轻量级，但在某些情况下可能影响性能：

- **网络请求**：IDE 插件通过 HTTP 连接，可能产生网络开销
- **数据查询**：频繁查询大量数据可能影响应用性能
- **建议**：仅在需要调试时启用，调试完成后可以关闭

### 3. 端口冲突

使用 `port: 0` 自动选择空闲端口，通常不会出现端口冲突。如果遇到问题：

- 检查是否有其他应用占用端口
- 重启 IDE 和应用
- 手动指定端口（不推荐）

### 4. 数据库路径

不同平台的数据库路径不同：

- **Android**: `/data/data/com.u163.glf9832.prismbox/app_flutter/prismbox.db`
- **iOS**: `Documents/prismbox.db`（通过 Xcode 访问）

### 5. 数据安全

⚠️ **重要**：Storage Inspector 会暴露数据库中的所有数据，包括：

- 用户信息
- 资产元数据
- 相册信息
- 其他敏感数据

**建议**：
- 仅在开发环境使用
- 不要在生产环境启用
- 不要在包含真实用户数据的设备上使用（除非必要）

### 6. 跨 Isolate 支持

PrismBox 使用 Drift Isolate 在独立线程中运行数据库。Storage Inspector 通过 `DriftServer` 可以正确访问跨 Isolate 的数据库，无需额外配置。

## 故障排查

### 问题 1: Storage Inspector 无法启动

**症状**：应用启动后，控制台没有显示 "Storage Inspector 已启动" 消息。

**可能原因**：
1. 应用不在调试模式下运行
2. 依赖未正确安装
3. 端口被占用

**解决方案**：

```dart
// 1. 检查是否在调试模式
if (kDebugMode) {
  debugPrint('当前为调试模式');
}

// 2. 检查依赖
flutter pub get

// 3. 检查端口
// 查看控制台是否有端口冲突错误
```

### 问题 2: IDE 插件无法连接

**症状**：IDE 中显示 "无法连接到应用" 或设备列表为空。

**可能原因**：
1. 应用未在调试模式下运行
2. IDE 插件未正确安装
3. 防火墙阻止连接

**解决方案**：

1. **确认应用在调试模式**：
   ```bash
   flutter run --debug
   ```

2. **重新安装插件**：
   - 卸载插件
   - 重启 IDE
   - 重新安装插件

3. **检查防火墙设置**：
   - 允许 IDE 和应用的网络连接
   - 检查本地防火墙规则

### 问题 3: 数据库表不显示

**症状**：连接成功，但看不到数据库表。

**可能原因**：
1. 数据库未正确初始化
2. 表为空
3. 插件版本不兼容

**解决方案**：

1. **检查数据库初始化**：
   ```dart
   final db = await DatabaseConnection.getInstance();
   final tables = await db.allTables;
   debugPrint('数据库表数量: ${tables.length}');
   ```

2. **检查表数据**：
   ```dart
   final localAssets = await db.localAssetDao.getAll();
   debugPrint('本地资产数量: ${localAssets.length}');
   ```

3. **更新插件版本**：
   - 检查插件是否有更新
   - 更新到最新版本

### 问题 4: 数据不更新

**症状**：应用中的数据已更新，但 IDE 中显示的数据未更新。

**可能原因**：
1. 缓存问题
2. 连接断开
3. 数据未提交

**解决方案**：

1. **手动刷新**：点击 IDE 中的刷新按钮
2. **重新连接**：断开并重新连接
3. **检查事务**：确保数据已提交到数据库

### 问题 5: 性能问题

**症状**：启用 Storage Inspector 后，应用变慢。

**可能原因**：
1. 频繁查询大量数据
2. 网络延迟
3. IDE 插件占用资源

**解决方案**：

1. **减少查询频率**：不要频繁刷新数据
2. **限制查询数据量**：使用 LIMIT 限制返回的数据量
3. **关闭不需要的功能**：仅启用必要的调试功能

## 总结

通过集成 Storage Inspector 和 Drift Local Storage Inspector，我们可以在开发过程中方便地查看和调试本地数据库。这个方案具有以下优势：

- ✅ **零侵入**：仅在调试模式启用，不影响生产代码
- ✅ **易于使用**：IDE 插件集成，无需额外配置
- ✅ **功能强大**：支持查看表结构、数据、执行 SQL 查询
- ✅ **实时同步**：运行时查看数据变化

**适用场景**：
- 开发阶段调试数据库操作
- 验证数据迁移是否正确
- 检查数据一致性
- 性能分析和优化

**不适用场景**：
- 生产环境（已通过 `kDebugMode` 控制）
- 包含真实用户数据的设备（除非必要）
- 性能敏感的场景（可能影响性能）

通过这个方案，开发团队可以更高效地开发和调试 PrismBox 移动端应用。
