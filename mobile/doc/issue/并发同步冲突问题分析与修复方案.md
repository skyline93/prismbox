# 并发同步冲突问题分析与修复方案

**状态**: 待实施  
**优先级**: 高  
**创建时间**: 2025-12-11  
**模块**: 本地媒体同步模块  
**相关文档**: 
- `doc/modules/本地媒体同步模块详细设计文档.md`
- `doc/issue/本地媒体同步模块遗留问题.md`

## 问题概述

### 问题描述

在应用启动或恢复时，多个同步任务并发执行，导致数据库唯一约束冲突（UNIQUE constraint failed），同步失败。

### 问题表现

**错误日志**：
```
[WARNING] 15:08:12.986 [LocalSyncService] 批量插入失败，尝试逐个插入
ERROR: SqliteException(1555): while executing statement, UNIQUE constraint failed: local_asset_entity.id, constraint failed (code 1555)
Causing statement: INSERT INTO "local_asset_entity" (...) VALUES (...), parameters: ..., 816C929B-7867-4392-9A5F-3622E377E8DC/L0/001, ...
```

**时序分析**：
```
15:08:03.368 [LocalSyncService] 开始全量同步  ← 任务1
15:08:04.993 [LocalSyncService] 开始全量同步  ← 任务2（1.6秒后）
```

两个同步任务几乎同时启动，尝试插入相同的资产记录，导致唯一约束冲突。

### 问题根源

1. **并发同步冲突**：应用启动和应用恢复两个触发路径几乎同时执行
2. **竞态条件**：`SyncCoordinator._sync()` 方法的检查-设置操作不是原子操作
3. **架构设计缺陷**：SyncCoordinator 不是严格单例，状态不共享
4. **数据库操作缺陷**：批量插入失败后，逐个插入时没有正确处理 UNIQUE constraint 错误

## 根本原因分析

### 一、问题时序分析

#### 触发路径1：应用启动

```
TabShellPage.initState()
  → WidgetsBinding.instance.addPostFrameCallback()
    → _startAutoSync() (延迟500ms)
      → startAutoSyncOnLaunch() (延迟2秒)
        → _checkAndSync()
          → _sync() → _doSync() → syncLocal()
```

#### 触发路径2：应用恢复

```
TabShellPage.didChangeAppLifecycleState(resumed)
  → _checkAndSyncOnResume()
    → checkAndSyncOnResume()
      → _checkAndSync()
        → _sync() → _doSync() → syncLocal()
```

**问题**：应用启动时可能立即触发 `AppLifecycleState.resumed`，导致两个路径几乎同时执行。

### 二、架构设计问题

#### 问题1：SyncCoordinator 不是真正的单例

**当前实现**：
```dart
// lib/features/local_sync/providers/local_sync_providers.dart
@riverpod  // 默认是 AutoDisposeFutureProvider
Future<SyncCoordinator> syncCoordinator(SyncCoordinatorRef ref) async {
  return SyncCoordinator(...);
}
```

**问题**：
- 使用 `@riverpod`（默认 `AutoDisposeFutureProvider`），可能创建多个实例
- 不同调用可能拿到不同实例，`_currentSyncTask` 状态不共享
- 应该使用 `@Riverpod(keepAlive: true)` 确保单例

**影响**：
- 多个 SyncCoordinator 实例各自维护 `_currentSyncTask` 状态
- 无法有效防止并发同步

#### 问题2：并发控制存在竞态条件

**当前实现**：
```dart
// lib/features/local_sync/services/sync_coordinator.dart:100-109
Future<SyncResult> _sync({bool full = false}) async {
  if (_currentSyncTask != null) {  // ← 检查点1
    _logger.warning('同步任务正在进行中');
    return await _currentSyncTask!;
  }

  _currentSyncTask = _doSync(full: full);  // ← 设置点（非原子操作）
  final result = await _currentSyncTask!;
  _currentSyncTask = null;
  return result;
}
```

**竞态条件时序**：
```
时间线：
T1: 任务A 检查 _currentSyncTask == null ✅
T2: 任务B 检查 _currentSyncTask == null ✅ (任务A还没设置)
T3: 任务A 设置 _currentSyncTask = _doSync()
T4: 任务B 设置 _currentSyncTask = _doSync() (覆盖任务A)
T5: 任务A 和 任务B 都开始执行同步 → 并发冲突！
```

**问题**：
- 检查与设置不是原子操作
- 缺少锁机制
- 两个任务可能同时通过检查

**影响**：
- 多个同步任务同时执行
- 尝试插入相同的数据库记录
- 触发 UNIQUE constraint 错误

#### 问题3：应用启动和应用恢复触发重叠

**当前实现**：
```dart
// TabShellPage
void initState() {
  WidgetsBinding.instance.addPostFrameCallback((_) {
    _startAutoSync();  // 延迟500ms后，再延迟2秒
  });
}

void didChangeAppLifecycleState(AppLifecycleState state) {
  if (state == AppLifecycleState.resumed) {
    _checkAndSyncOnResume();  // 立即执行
  }
}
```

**问题**：
- 应用启动时可能立即触发 `resumed`
- 两个路径没有去重机制
- `_checkAndSync()` 中的新鲜度检查可能同时通过

**影响**：
- 两个同步任务几乎同时启动
- 导致并发冲突

#### 问题4：数据新鲜度检查的时序问题

**当前实现**：
```dart
// sync_coordinator.dart:81-96
Future<void> _checkAndSync() async {
  // 检查数据新鲜度
  final isFresh = _lastSyncedAt != null &&
      DateTime.now().difference(_lastSyncedAt!) < _freshnessThreshold;

  if (isFresh) {
    _logger.info('数据新鲜，跳过同步');
    return;
  }

  // 执行增量同步
  await _sync(full: false);
}
```

**问题**：
- `_lastSyncedAt` 在任务开始后才更新（`_doSync` 完成后）
- 两个任务可能同时通过新鲜度检查
- 没有在检查前设置"正在同步"标志

**影响**：
- 多个任务同时通过新鲜度检查
- 同时触发同步

#### 问题5：数据库操作缺少 Upsert 支持

**当前实现**：
```dart
// local_sync_service.dart:154-167
for (final entity in entities) {
  try {
    final existing = await dao.getAssetById(entity.id);  // 检查
    if (existing != null) {
      await dao.updateAsset(entity);
    } else {
      await dao.insertAsset(entity);  // 可能此时另一个任务已插入
    }
  } catch (e2) {
    _logger.warning('插入资产失败: ${entity.id}', e2);  // 只记录警告
  }
}
```

**问题**：
- 检查-插入操作存在竞态条件
- 遇到 UNIQUE constraint 错误时，只记录警告，没有正确处理
- 缺少 upsert（INSERT OR REPLACE）机制

**影响**：
- 批量插入失败后，逐个插入时仍然可能冲突
- 错误处理不完善，导致同步失败

## 架构设计缺陷总结

### 1. 单例模式不严格

**问题**：
- SyncCoordinator 使用 `AutoDisposeFutureProvider`，可能创建多个实例
- 状态（`_currentSyncTask`、`_lastSyncedAt`）不共享

**应该**：
- 使用 `@Riverpod(keepAlive: true)` 确保全局单例
- 所有调用共享同一个实例和状态

### 2. 并发控制不足

**问题**：
- 缺少锁机制（如 `synchronized` 或 `Mutex`）
- 检查-设置操作不是原子的
- 没有"正在同步"标志防止重复触发

**应该**：
- 使用同步锁或标志位
- 确保检查-设置操作的原子性
- 在同步开始前设置标志，完成后清除

### 3. 触发时机去重缺失

**问题**：
- 应用启动和应用恢复没有去重
- 应该统一入口，避免重复触发

**应该**：
- 统一触发入口
- 添加去重机制（如防抖）
- 记录最后触发时间，避免短时间内重复触发

### 4. 数据库操作缺少 Upsert

**问题**：
- 批量插入失败后，逐个插入时没有正确处理 UNIQUE constraint
- 应该使用 `INSERT OR REPLACE` 或先检查再决定插入/更新

**应该**：
- 在 DAO 中添加 upsert 方法
- 批量插入失败时，使用 upsert 逐个处理
- 正确处理 UNIQUE constraint 错误

## 解决方案

### 方案1：修复 SyncCoordinator 为严格单例（必须）

**文件**: `lib/features/local_sync/providers/local_sync_providers.dart`

**修改**：
```dart
/// SyncCoordinator Provider
/// 
/// 使用 keepAlive: true 确保全局单例
@Riverpod(keepAlive: true)
Future<SyncCoordinator> syncCoordinator(SyncCoordinatorRef ref) async {
  final syncService = await ref.watch(localSyncServiceProvider.future);
  final database = await ref.watch(infra.databaseProvider.future);
  return SyncCoordinator(
    syncService: syncService,
    database: database,
  );
}
```

**效果**：
- 确保全局只有一个 SyncCoordinator 实例
- 所有调用共享同一个 `_currentSyncTask` 状态

### 方案2：添加同步锁机制（必须）

**文件**: `lib/features/local_sync/services/sync_coordinator.dart`

**修改**：
```dart
import 'dart:async';

class SyncCoordinator {
  // ... 现有代码 ...
  
  /// 同步锁
  Completer<void>? _syncLock;
  bool _isSyncing = false;
  
  /// 执行同步（带锁保护）
  Future<SyncResult> _sync({bool full = false}) async {
    // 如果正在同步，等待完成
    if (_isSyncing) {
      _logger.warning('同步任务正在进行中，等待完成');
      await _syncLock?.future;
      return _currentSyncTask!;
    }
    
    // 设置同步标志和锁
    _isSyncing = true;
    final lock = Completer<void>();
    _syncLock = lock;
    
    try {
      _currentSyncTask = _doSync(full: full);
      final result = await _currentSyncTask!;
      return result;
    } finally {
      _isSyncing = false;
      _currentSyncTask = null;
      lock.complete();
      _syncLock = null;
    }
  }
}
```

**效果**：
- 使用 `_isSyncing` 标志防止并发
- 使用 `Completer` 实现等待机制
- 确保同一时间只有一个同步任务执行

### 方案3：统一触发入口，添加去重机制（推荐）

**文件**: `lib/features/local_sync/services/sync_coordinator.dart`

**修改**：
```dart
class SyncCoordinator {
  // ... 现有代码 ...
  
  /// 最后触发时间（用于去重）
  DateTime? _lastTriggerTime;
  static const Duration _triggerDebounce = Duration(seconds: 3);
  
  /// 统一的同步触发入口（带去重）
  Future<void> _checkAndSync({bool force = false}) async {
    // 去重：如果最近3秒内已触发，跳过
    if (!force && _lastTriggerTime != null) {
      final timeSinceLastTrigger = DateTime.now().difference(_lastTriggerTime!);
      if (timeSinceLastTrigger < _triggerDebounce) {
        _logger.info('最近已触发同步，跳过（去重）');
        return;
      }
    }
    
    _lastTriggerTime = DateTime.now();
    
    try {
      // 检查数据新鲜度
      final isFresh = _lastSyncedAt != null &&
          DateTime.now().difference(_lastSyncedAt!) < _freshnessThreshold;

      if (isFresh) {
        _logger.info('数据新鲜，跳过同步');
        return;
      }

      // 执行增量同步
      await _sync(full: false);
    } catch (e) {
      _logger.warning('自动同步失败', e);
    }
  }
  
  /// 应用启动时自动同步（延迟执行）
  void startAutoSyncOnLaunch() {
    _logger.info('计划延迟自动同步（${_startDelay.inSeconds}秒后）');
    Future.delayed(_startDelay, () {
      _checkAndSync();
    });
  }

  /// 应用恢复时检查并同步
  void checkAndSyncOnResume() {
    _logger.info('应用恢复，检查数据新鲜度');
    _checkAndSync();  // 使用统一入口
  }
}
```

**效果**：
- 统一触发入口，避免重复逻辑
- 添加防抖机制，避免短时间内重复触发
- 简化代码，提高可维护性

### 方案4：添加数据库 Upsert 支持（必须）

**文件1**: `lib/data/database/daos/local_asset_dao.dart`

**修改**：
```dart
/// 插入或更新资产（Upsert）
/// 如果记录已存在则更新，不存在则插入
Future<void> insertOrUpdateAsset(LocalAssetEntityData asset) {
  return into(localAssetEntity).insertOnConflictUpdate(asset);
}

/// 批量插入或更新资产（Upsert）
Future<void> insertOrUpdateAssets(List<LocalAssetEntityData> assets) {
  return batch((batch) {
    for (final asset in assets) {
      batch.insertOnConflictUpdate(localAssetEntity, asset);
    }
  });
}
```

**文件2**: `lib/features/local_sync/services/local_sync_service.dart`

**修改**（全量同步）：
```dart
// 批量写入数据库
if (entities.isNotEmpty) {
  try {
    await dao.insertAssets(entities);
    added += entities.length;
  } catch (e) {
    // 如果批量插入失败，使用 upsert 逐个处理
    _logger.warning('批量插入失败，使用 upsert 逐个处理', e);

        await dao.insertOrUpdateAsset(entity);

        final existing = await dao.getAssetById(entity.id);
        if (existing != null && existing.updatedAt == entity.updatedAt) {
          added++;
        } else {
          updated++;
        }
      } catch (e2) {
        _logger.warning('插入/更新资产失败: ${entity.id}', e2);
      }
    }
  }
}
```

**修改**（增量同步）：
```dart

if (toInsert.isNotEmpty) {
  try {
    await dao.insertAssets(toInsert);
    added += toInsert.length;
  } catch (e) {
    _logger.warning('批量插入失败，使用 upsert 逐个处理', e);

      try {
        await dao.insertOrUpdateAsset(entity);

        _logger.warning('插入/更新资产失败: ${entity.id}', e2);
      }
    }
  }
}
```

**效果**：
- 使用 `INSERT OR REPLACE` 避免 UNIQUE constraint 错误
- 正确处理并发插入场景
- 提高同步的可靠性

### 方案5：改进错误处理（推荐）

**文件**: `lib/features/local_sync/services/local_sync_service.dart`

**修改**：
```dart
// 批量插入失败后，逐个处理
for (final entity in entities) {
  try {
    await dao.insertAsset(entity);
    added++;
  } catch (e2) {
    // 检查是否是 UNIQUE constraint 错误
    if (e2.toString().contains('UNIQUE constraint') || 
        e2.toString().contains('1555')) {
      // 如果是唯一约束错误，说明记录已存在，尝试更新
      try {
        await dao.updateAsset(entity);
        updated++;
      } catch (e3) {
        _logger.warning('更新资产失败: ${entity.id}', e3);
      }
    } else {
      _logger.warning('插入资产失败: ${entity.id}', e2);
    }
  }
}
```

**效果**：
- 正确处理 UNIQUE constraint 错误
- 自动转换为更新操作
- 提高错误恢复能力

## 总结

### 根本原因

1. **架构层面**：
   - SyncCoordinator 不是严格单例，状态不共享
   - 缺少全局锁或同步机制
   - 触发路径重叠，没有统一去重

2. **实现层面**：
   - 并发控制存在竞态条件
   - 数据库操作缺少 upsert 机制
   - 错误处理不完善

3. **设计层面**：
   - 应用启动和应用恢复的触发逻辑重叠
   - 没有考虑并发场景下的数据一致性

### 修复优先级

1. **必须修复**（高优先级）：
   - 修复 SyncCoordinator 为严格单例
   - 添加同步锁机制
   - 添加数据库 Upsert 支持

2. **推荐修复**（中优先级）：
   - 统一触发入口，添加去重机制
   - 改进错误处理

### 预期效果

修复后，应该能够：
- 防止并发同步冲突
- 正确处理数据库唯一约束错误
- 提高同步的可靠性和稳定性
- 改善用户体验（减少错误和重试）
