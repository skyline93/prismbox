# 本地媒体同步模块遗留问题

**状态**: 待修复  
**优先级**: 中高  
**创建时间**: 2025  
**模块**: 本地媒体同步模块  
**相关文档**: `doc/modules/本地媒体同步模块详细设计文档.md`

## 概述

本文档详细记录了本地媒体同步模块实现与设计文档之间的不一致之处，以及缺失的功能。当前实现已完成基础功能（阶段1），但缺少部分优化功能和高级功能（阶段2和阶段3）。

## 问题分类

### 1. 代码错误/不一致（高优先级）

#### 1.1 增量同步中的 `getAssetPathList` 调用不一致

**位置**: `lib/features/local_sync/services/local_sync_service.dart:206-209`

**问题描述**:
- 增量同步中使用了 `type: pm.RequestType.all` 参数
- 全量同步中（第93-95行）没有使用该参数
- 导致代码不一致，可能引起混淆

**当前代码**:
```dart
// 增量同步（第206-209行）
final albums = await pm.PhotoManager.getAssetPathList(
  type: pm.RequestType.all,  // 这个参数在全量同步中没有
  hasAll: true,
);

// 全量同步（第93-95行）
final albums = await pm.PhotoManager.getAssetPathList(
  hasAll: true,  // 没有 type 参数
);
```

**修复建议**:
- 统一调用方式，移除 `type` 参数（因为 `hasAll: true` 已足够）
- 或者在全量同步中也添加该参数以保持一致性

**影响**: 代码一致性，维护性

### 2. 功能缺失 - 核心功能（高优先级）

#### 2.1 增量同步优化策略未实现

**位置**: `lib/features/local_sync/services/local_sync_service.dart:_incrementalSync()`

**文档要求** (`doc/modules/本地媒体同步模块详细设计文档.md:478-484`):
- 通过修改时间快速判断
- 快速路径：比较资产数量、最后修改时间等元数据
- 如果元数据未变化，跳过全量对比
- 只对比有变化的资产

**当前实现**:
- 获取所有资产后全量对比
- 未使用元数据优化策略
- 性能较差，特别是资产数量多时

**需要实现**:
1. 在增量同步开始时，获取系统相册的元数据（资产数量、最后修改时间）
2. 与数据库中的元数据比较
3. 如果元数据未变化，跳过同步
4. 如果元数据变化，只处理有变化的资产（通过修改时间过滤）

**影响**: 性能问题，大量资产时同步速度慢

**实施步骤**:
1. 在数据库中添加最后同步时间字段（或使用现有字段）
2. 实现元数据比较逻辑
3. 实现基于修改时间的资产过滤
4. 优化增量同步流程

#### 2.2 从数据库读取时缺少 AssetEntity

**位置**: `lib/features/local_sync/services/timeline_provider_service.dart:_convertToLocalAsset()`

**文档要求** (`doc/modules/本地媒体同步模块详细设计文档.md:252-255`):
- 需要通过 ID 获取 AssetEntity（延迟获取或批量获取）
- 提供两种策略：
  - 方案A：延迟获取（按需获取，首次加载图片时）
  - 方案B：批量获取（读取数据时一次性获取所有 AssetEntity）

**当前实现**:
- `assetEntity: null` - 未实现获取逻辑
- 从数据库读取的数据无法直接加载图片

**需要实现**:
1. 实现延迟获取策略（推荐）：
   - 在需要加载图片时，通过 `photo_manager` 的 `AssetEntity.fromId()` 获取
   - 缓存获取的 AssetEntity
2. 或实现批量获取策略：
   - 在 `_getFromDatabase()` 中批量获取所有 AssetEntity
   - 注意性能影响

**影响**: 从数据库读取的数据无法直接加载图片，需要额外处理

**实施步骤**:
1. 实现 `_getAssetEntityById(String id)` 方法
2. 在 `_convertToLocalAsset()` 中延迟获取或批量获取
3. 添加 AssetEntity 缓存机制

#### 3.2 duration 类型处理不一致

**位置**: 
- `lib/features/local_sync/services/local_sync_service.dart:349`
- `lib/features/local_sync/services/timeline_provider_service.dart:189`

**问题描述**:
- `local_sync_service.dart` 中使用了 `asset.duration.toInt()`
- `timeline_provider_service.dart` 中直接使用 `asset.duration`（类型为 `int?`）
- 处理方式不一致

**当前代码**:
```dart
// local_sync_service.dart:349
durationInSeconds: asset.duration.toInt(),

// timeline_provider_service.dart:189
durationInSeconds: asset.duration,  // asset.duration 是 int?
```

**修复建议**:
- 统一处理方式
- 如果 `asset.duration` 是 `int?`，使用 `asset.duration`
- 如果是 `double?`，使用 `asset.duration?.toInt()`

**影响**: 代码一致性，可能的数据类型错误
