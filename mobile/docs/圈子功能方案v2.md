### **方案：基于现有架构扩展的“圈子相册 (Group Album)”功能**

---

### **第一部分：现有 API 架构分析与核心洞察**

通过分析你提供的 Swagger 文档，我们可以得出以下关键结论：

1.  **强大的个人媒体管理核心**：你的后端已经拥有一个非常成熟的个人媒体管理系统。`User`, `Media`, `Album` 模型定义清晰，上传流程（哈希预检、秒传）、下载（原图/预览/缩略图）、增量同步 (`/media/changes`) 等功能非常完善。**这是我们能够构建新功能所依赖的坚实基础**。

2.  **`Album` 模型的局限性**：当前的 `Album` 模型通过 `user_id` 与单个用户强绑定 (`models.Album` -> `user_id`)。这意味着它在设计上就是一个**纯粹的个人实体**。我们**不能**简单地往这个模型里添加多个用户来实现共享，这会破坏其核心设计，并引发后续无数的权限问题。

3.  **`Share` 模型的局限性**：当前的 `Share` 模型是为**单个媒体项**设计的**临时性、点对点**的分享 (`handlers.CreateShareInput` -> `media_uuid`, `duration_minute`)。它不适用于创建一个**持久的、多用户、多照片**的共享空间。

**核心架构决策：**

> **我们必须引入新的数据模型来承载“圈子”这一概念，而不是改造现有的 `Album` 或 `Share` 模型。** 这种方式可以确保新旧功能逻辑分离，权责清晰，并且不会对现有 App 的稳定性造成破坏。我们将把圈子设计成一个**媒体引用容器**，圈子本身不“拥有”照片，而是“引用”了成员上传的个人照片。

---

### **第二部分：新功能的数据模型设计**

我们需要在后端新增以下核心数据模型：

1.  **`Group` (圈子/群组)**
    *   `id` (主键)
    *   `uuid` (对外暴露的唯一标识符)
    *   `name` (圈子名称)
    *   `description` (圈子简介)
    *   `cover_media_uuid` (封面照片的 UUID，可为空)
    *   `owner_id` (外键 -> `users.id`，圈主)
    *   `created_at`, `updated_at`

2.  **`GroupMember` (圈子成员)** - (多对多关系表)
    *   `id` (主键)
    *   `group_id` (外键 -> `groups.id`)
    *   `user_id` (外键 -> `users.id`)
    *   `role` (ENUM: 'owner', 'admin', 'member')
    *   `joined_at`

3.  **`GroupMedia` (圈子媒体)** - (核心的媒体引用表)
    *   `id` (主键)
    *   `group_id` (外键 -> `groups.id`)
    *   `media_uuid` (外键 -> `media.uuid`) **<- 引用全局的媒体项**
    *   `uploader_id` (外键 -> `users.id`)
    *   `caption` (照片描述/标题)
    *   `created_at`

4.  **`Comment` (评论)**
    *   `id` (主键)
    *   `group_media_id` (外键 -> `group_media.id`)
    *   `user_id` (外键 -> `users.id`)
    *   `content` (文本内容)
    *   `created_at`

### **第三部分：新增后端 API 接口设计 (对 Swagger 的扩展)**

我们将新增一个 `tag: Groups`，并定义以下接口。

**Tag: `Groups`**

*   **`POST /groups` (创建圈子)**
    *   **描述**: 为当前登录的用户创建一个新的圈子。
    *   **请求体**: `{ "name": "我的家庭", "description": "记录美好瞬间" }`
    *   **响应**: `201 Created`，返回新创建的 `Group` 对象。
*   **`GET /groups` (获取我的圈子列表)**
    *   **描述**: 获取当前用户已加入的所有圈子列表。
    *   **响应**: `200 OK`，返回 `Group` 对象数组（可包含成员数、照片总数等聚合信息）。
*   **`GET /groups/{uuid}` (获取圈子详情)**
    *   **描述**: 获取特定圈子的详细信息。
    *   **响应**: `200 OK`，返回 `Group` 对象。
*   **`PUT /groups/{uuid}` (更新圈子信息)**
    *   **描述**: 更新圈子信息（仅圈主/管理员）。
    *   **请求体**: `{ "name": "新名称", "description": "新简介" }`
    *   **响应**: `200 OK`。
*   **`DELETE /groups/{uuid}` (解散圈子)**
    *   **描述**: 解散圈子（仅圈主）。
    *   **响应**: `204 No Content`。

**Tag: `Group Members`**

*   **`POST /groups/{uuid}/members/invite` (创建邀请)**
    *   **描述**: 创建一个加入圈子的邀请链接或邀请码（圈主/管理员）。
    *   **请求体**: `{ "duration_hour": 24 }`
    *   **响应**: `201 Created`，返回 `{ "invite_code": "XYZ789", "expires_at": "..." }`。
*   **`POST /groups/join` (加入圈子)**
    *   **描述**: 用户使用邀请码加入一个圈子。
    *   **请求体**: `{ "invite_code": "XYZ789" }`
    *   **响应**: `200 OK`，返回成功加入的 `Group` 对象。
*   **`GET /groups/{uuid}/members` (获取成员列表)**
    *   **描述**: 获取圈子内的所有成员列表。
    *   **响应**: `200 OK`，返回 `User` 对象数组（不含敏感信息），并附带其 `role`。
*   **`DELETE /groups/{uuid}/members/{userId}` (移除成员)**
    *   **描述**: 将指定用户移出圈子（圈主/管理员）。
    *   **响应**: `204 No Content`。

**Tag: `Group Media`**

*   **`POST /groups/{uuid}/media` (分享照片到圈子)**
    *   **描述**: 将一个或多个**已存在于用户个人空间**的媒体项分享到圈子。
    *   **请求体**: `{ "media_uuids": ["uuid1", "uuid2"], "caption": "这次旅行太棒了" }`
    *   **工作流程**:
        1.  **客户端**: 走现有的 `/media/upload` 流程，确保照片已上传至用户个人空间。
        2.  **客户端**: 获得 `media_uuid` 后，调用此接口。
        3.  **后端**: 校验用户是否为圈子成员，校验媒体是否属于该用户，然后在 `GroupMedia` 表中创建引用记录。
    *   **响应**: `201 Created`。
*   **`GET /groups/{uuid}/media` (获取圈子 Feed)**
    *   **描述**: 分页获取圈子内的所有媒体项。
    *   **查询参数**: `?page=1&limit=30`
    *   **响应**: `200 OK`，返回一个对象数组，每个对象包含 `GroupMedia` 信息（如 caption, uploader）以及完整的 `Media` 对象（通过 `media_uuid` 关联查询得到）。
*   **`DELETE /group-media/{groupMediaId}` (从圈子移除照片)**
    *   **描述**: 从圈子中移除照片引用（上传者或圈主/管理员）。注意：这只删除 `GroupMedia` 记录，不删除原始的 `Media` 文件。
    *   **响应**: `204 No Content`。

### **第四部分：详细实施路线图（分阶段进行）**

#### **Phase 0: 后端架构与基础 API 建设 (1-2 周)**

**目标**: 搭建新功能的核心数据结构和基础 API，为前端开发铺平道路。

*   **后端任务**:
    1.  **数据库设计**: 创建 `Groups`, `GroupMembers`, `GroupMedia`, `Comments` 四张表，并建立正确的索引和外键关联。
    2.  **实现 `Groups` CRUD API**: `POST /groups`, `GET /groups`, `GET /groups/{uuid}`。
    3.  **实现成员管理核心 API**: `POST /groups/join` (可先用一个永久有效的邀请码)，`GET /groups/{uuid}/members`。
    4.  **实现媒体引用核心 API**: `POST /groups/{uuid}/media` 和 `GET /groups/{uuid}/media` (带分页)。

*   **前端任务**:
    1.  **技术预研**: 与后端同步对齐 API 设计。
    2.  **搭建基础 UI 框架**: 创建“圈子”主 Tab，设计圈子列表页和圈子详情页的静态 UI 布局。

#### **Phase 1: MVP - 核心循环验证 (2-3 周)**

**目标**: 实现最核心的用户流程：创建/加入圈子 -> 上传照片 -> 浏览 Feed。让功能在内测中跑起来。

*   **后端任务**:
    1.  完善邀请机制 `POST /groups/{uuid}/members/invite`。
    2.  对 Feed 接口进行性能测试和优化。

*   **前端任务**:
    1.  **圈子列表页**: 调用 `GET /groups` 接口，展示用户加入的所有圈子。
    2.  **创建圈子**: 实现创建圈子表单，调用 `POST /groups`。
    3.  **加入圈子**: 实现通过邀请码加入圈子的功能，调用 `POST /groups/join`。
    4.  **圈子 Feed 页**:
        *   调用 `GET /groups/{uuid}/media`，使用 `GridView` 或 `ListView` 展示照片缩略图。
        *   集成下拉刷新和上滑加载更多功能。
    5.  **照片上传流程**:
        *   在圈子 Feed 页放置上传按钮。
        *   点击后，引导用户选择照片。
        *   **复用现有上传逻辑**: 调用 `POST /media/check_hashes` 和 `POST /media/upload`。
        *   上传成功后，获取 `media_uuid`，再调用新的 `POST /groups/{uuid}/media` 接口。
        *   上传成功后，本地即时更新 Feed UI。
    6.  **大图浏览**: 点击缩略图，进入大图页，加载预览图或原图。

#### **Phase 2: 社交体验增强 (2 周)**

**目标**: 增加互动功能，提升社区氛围和用户粘性。

*   **后端任务**:
    1.  **实现 `Comments` 相关 API**: `POST /media/{mediaId}/comments`, `GET /media/{mediaId}/comments` 等。
    2.  **实现 `Likes` 相关 API** (如果决定要做)。
    3.  **实现基础通知系统**: 在数据库中创建 `Notifications` 表，当有新照片、新评论时，插入通知记录。

*   **前端任务**:
    1.  **评论功能**: 在大图浏览页，实现评论输入框和评论列表的 UI 和业务逻辑。
    2.  **点赞功能**: 添加点赞按钮和状态更新。
    3.  **通知中心**: 创建一个简单的通知页面，轮询或在进入页面时拉取用户的通知列表。

#### **Phase 3: 管理与完善 (1-2 周)**

**目标**: 提供更完善的管理功能和用户体验优化。

*   **后端任务**:
    1.  **实现完整的成员管理 API**: `DELETE /groups/{uuid}/members/{userId}`，设置管理员等。
    2.  **实现删除 API**: `DELETE /groups/{uuid}` (解散) 和 `DELETE /group-media/{groupMediaId}` (移除照片)。
    3.  **集成推送通知**: 对接 APNS 和 FCM，将数据库中的通知实时推送给客户端。

*   **前端任务**:
    1.  **实现成员管理界面**: 圈主/管理员可以进行移除成员等操作。
    2.  **实现删除功能**: 在照片和圈子菜单中增加“删除”或“退出”选项。
    3.  **集成 Push Notification SDK**: 接收并展示推送通知。
    4.  **UI/UX 打磨**: 根据内测反馈，优化动画、加载状态、错误提示等。
